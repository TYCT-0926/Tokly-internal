## 偏差与裁决点

1. **`--no-tests pass`（文档与 ci.yml 的空格形式）vs 任务文本 `--no-tests=pass`**：以 nextest 0.9.140 实证（样本 crate 含真实测试）——两种形式行为完全一致，值被正确消费、不会被误解析为测试过滤器。故 ci.yml 与文档该行**均未改动**（二者本就一致）；xtask 与本地验证采用 `=` 形式。两形式混用无风险，如需统一书写形式请维护者裁决。
2. **cargo-deny 对 workspace 成员也做许可证检查**：xtask 初版无 `license` 字段 → `error[unlicensed]`，licenses FAILED。处置：xtask `Cargo.toml` 增 `license = "MIT"`（与仓库 LICENSE 一致）。此要求任务未预见，属 cargo-deny 0.20.x 默认行为，非白名单问题。
3. **本机工具安装（非仓库改动，记录留痕）**：rustup 安装 1.97.1 toolchain；cargo-deny 0.20.2 预编译二进制（GitHub release，sha256 校验通过）装入 `~/.cargo/bin`——本地跑 `cargo deny check` 所必需。均为开发工具追加，未改任何既有工具配置。
4. **xtask fmt 语义取舍**：`fmt` 子命令 = `cargo fmt --all -- --check`（检查而非写入），使 `xtask ci` 复刻门禁语义。被弃备选：fmt 做格式化写入——弃因 ci 子命令必须复刻门禁语义，且"检查/写入双模式"属未被要求的变体。注意 xtask 镜像的是完成定义的**本地**命令列表：nextest 不带 `--profile ci`（该 profile 仅供 ci.yml 的 CI 步骤消费，fail-fast=false 是给 CI 一次跑全失败面的；本地默认 fail-fast 反而合意）。这是有意差异，非漂移。
5. **开发流程文档 CI 节措辞**：「Rust stable 三平台矩阵」→「版本由 rust-toolchain.toml 固定」，与 pin 后现实对齐（文档随批）。

## 复审修复（2026-08-03，第二轮，针对 阶段一-复审.md 两项必须修复）

1. **quotePath 绕过**：`git ls-files` → `git -c core.quotepath=false ls-files`。默认 `core.quotePath=true` 会把含非 ASCII 字符的路径整行加引号并转义（`"internal/\346..."`），行首引号使 `^(internal|docs)/` 锚定失配——本仓内部文档几乎全部中文命名，等于防线整体失效。关闭 quotePath 后路径以原始字节输出，锚定恢复。
2. **push main 空转 + 大小写变体**：署名检查区间按事件选取——PR 用 `origin/main..HEAD`，push 用 `github.event.before..HEAD`；`event.before` 为全零 SHA（分支新建）改查全史，不可解析（如被 force-push 甩掉）直接红。正则改为全大小写不敏感的 `co-authored-by|\bgenerated with`；`\b` 词边界是验收样例之外自加的回归防线，防 "regenerated with insta" 类正常行文误杀。表达式经 `env:` 传入脚本，不做内联展开。
3. **fixture 验证 21/21**（用 YAML 解析器从 ci.yml 原样提取 run 块、`bash -e` 执行，对齐 GitHub 默认 shell）：中文路径两例拒绝且旧命令绕过被复现；删除类提交与真实公开树通过；六个大小写署名变体（含 `cO-aUtHoReD-bY`、`CO-AUTHORED-BY`、`GENERATED WITH`）全部拒绝；push 直推 main 的署名提交拒绝、干净提交通过；全零 SHA 查全史并命中深处署名；`deadbeef` 基线与 origin/main 缺失均 fail-closed；空范围跳过。
4. **有意收严的残留误杀面（记录在案）**：大小写不敏感的 `generated with` 词组会命中正常英文行文（如 "Diagrams generated with mermaid"）——按复审验收标准明确要求收严；命中是响亮失败，重写提交措辞即可，不构成静默风险。
