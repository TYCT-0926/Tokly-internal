## 事故档案 · internal/ 误删（2026-08-04）

维护者在 `git worktree remove` 报 "Directory not empty" 后直接 `rm -rf` 阶段六 worktree，MSYS2 的 rm 跟随其中指向 `internal/` 的 NTFS junction 递归删除，`internal/` 连同其 `.git` 全灭。恢复：私有远端 `79c37f7`（34 份）+ 公开仓旧提交 `ecc0225` 对象库（六份 spec + 四份治理文档）→ 45 份基线；`79c37f7` 之后的裁决与契约条款由维护会话据上下文重写（即本汇编与各 ADR 增补），执行者报告由各执行者重出。
**教训入约**：① 破坏性命令报错即停下调查，报错本身就是信号（全局 CLAUDE.md §5 已有，此次是执行失败非规则缺失）；② **worktree 内可能存在指向 internal 的 junction，删除 worktree 一律用 `git worktree remove`，失败则先查明原因，绝不 `rm -rf` 兜底**；③ **internal 仓恢复"每批提交后必推远端"纪律**——单仓改版把它降为"可选备份"，正是这个降级把损失从 0 放大到一整天。
