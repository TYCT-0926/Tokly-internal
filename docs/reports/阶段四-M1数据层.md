## 一、先说三条必须裁决的事

这三条是本轮**发现的契约缺口 / 规格与实现不可两全处**。按纪律没有静默取舍，全部在此上报，请维护者裁决。

### 缺口 1：定案 6 补文第 3 条的 `skipped` 第三因，其「充要」刻画并不互斥（已按窄化实现，需追认）

补文原文把第三因的谓词写成双条件：

> 「该事件在冻结事务中成为基线成员且当时 `computed_cost_status='pending'`」⟺ 「终态 `skipped` 且金额与 `pricing_version` 均 NULL 且所属会话 `has_partial_cost=1`」

右侧**不是**第三因的专有特征。一个第一因事件（`pricing_eligibility='disabled'`，由 worker 落章 `skipped`、金额与版本均 NULL）只要恰好落在一个因别的原因被标 `has_partial_cost=1` 的会话里，就**逐字满足右侧而不满足左侧**——而这种会话在实测中很常见（`rebuild_session` 只要该会话计价覆盖不齐就置 1）。所以该双条件按字面为**假**。

实现取舍（已落地，明确上报而非静默）：判定加入 `frozen_baseline_at IS NOT NULL`，即以「冻结事务写下的成员标记」作为第三因的判据。这是**窄化**，理由是左侧本身无歧义（基线成员 + 当时 pending），右侧只是它的一个不充分刻画。测试文件里已写明这是有意窄化。

请裁决：把补文右侧改为含 `frozen_baseline_at` 的刻画，还是另立区分方式。位置：`crates/tokly-pricing/tests/skipped_causes.rs`。

### 缺口 2：`skipped` 三因之二「配置关闭计价」在 M1 无任何写入者

ADR-0015 列 `skipped` 三因：`pricing_eligibility` 判定 / **配置关闭** / 生命周期封存。全仓审计结果：`tokly-config` 只有 `pricing.remote_refresh` 与 `pricing.override_path` 两个键，**没有任何「关闭计价」的配置面**，因此第二因没有产生者，其谓词恒假。

这不构成契约违反（空析取项不会让枚举出错），但使「三因枚举」实际只有两因。P6 的 `skipped` 枚举里已把第二因显式写成空集并注明。请裁决：补配置键，还是把 ADR-0015 的三因改为两因。

### 缺口 3：ADR-0019 的 `scope = health` 标注没有产生者（DTO 有，发布者无）

定案 3 要求诊断可见写「事件 scope 标 `health`」。实测：`tokly-service` 的 `ChangeScope`（含 `Health`）与 `ChangeEvent` 两个 DTO **已定义**，但全仓**没有任何代码构造 ChangeEvent**——其文档注释自己写着「Publishers arrive with the ingest path and the SSE upgrade」，即发布者属后续阶段。

本轮落地的是**数据层部分**（谓词域扩为 fold ∪ health，单一计数器递增），未新增 scope 标注机制（无产生者可标，且新增广播层不属 M1 数据层范围，必要性检验不过）。请确认这一分界，或指定由哪个阶段补发布者。

### 加宽的 oracle 抓到的两个真实缺陷

**A-1 全量重建抹掉基线封存（严重）。** `rebuild_projection_from_observations` 以 `observations_pruned_at IS NULL` 为界删除并重折叠投影，基线事件正在此列内。后果两层：一是**重写了已入永久汇总的内容**（违反「此后零触碰绝对」）；二是**丢掉 `frozen_baseline_at` 标记本身**——而尾账正是靠该标记为空来识别尾侧事件，所以重建后的基线事件会被下一次 compact **吸收进尾账，与已包含它的汇总重复计数**。修法：重建的四条语句统一以 `COALESCE(observations_pruned_at, frozen_baseline_at) IS NOT NULL` 为不可变界，与 `fold_key` 既有判据一致。

复现（修前红）：
```
cargo test -p tokly-core --test fold_rules a_full_rebuild_leaves_a_sealed_baseline_alone
```
修前实际：`("...0020","h03",None,103)`，期望 `("...0010","h00",Some(1722000000001),100)`。

**A-2 冻结把不可计价事件永久留在 `pending`（违反 ADR-0015 红线）。** 冻结落章语句带 `AND pricing_eligibility <> 'disabled'`，而 reprice 的分页扫描又排除基线成员——两者相加，一个 `disabled` 事件若在 worker 首扫前随会话冻结，就**永远停在 `pending`**，正是 ADR-0015「不参与计价的事件永停 pending 即谎报队列，禁止」所禁。补文第 3 条左侧只说「基线成员且当时 pending」，**未按资格收窄**，故实现的 `<> 'disabled'` 是无授权的窄化。修法：去掉该条件，终态同为 `skipped` + 金额/版本 NULL。

## 三、批 B —— F1 第四腿与 F2 部分成本（`ccc9c05`）

### F1 第四腿

`store_totals` 由三腿改为**五段四腿**：净汇总 + 脏会话事件 + 无会话事件 + **（存活尾侧事件 + `session_tail_ledger`）**。

四腿的识别谓词：会话 `frozen_at IS NOT NULL` 且事件 `frozen_baseline_at IS NULL`。同时给脏腿补 `AND s.frozen_at IS NULL`，使四腿**可证不相交**（冻结会话由「定格汇总 + 尾账」核算，不再有与脏腿重叠的可能）。

尾账读回时用 `native_cost_events` / `computed_cost_events` 两个计数列把 `NOT NULL DEFAULT 0` 的金额还原成 `Option`——否则「无成本记录」会显示成 `$0.00`，这正是 schema 注释里那两列存在的理由。

复审给的最小反例已恢复为永久回归，且**修前实测与复审报告逐字段一致**：

```
cargo test -p tokly-cli report::tests::a_reactivated_frozen_session_does_not_hide_the_new_event
```
修前：`events 4 / input 737 / computed 1,000,000`；真值：`5 / 778 / 1,000,017`。

另加 `an_absorbed_tail_event_survives_in_the_ledger`：先断言活尾事件确实进了总账（锚定 sealed 基线，避免两端同时丢失而假绿），再模拟 compact「同事务累加后删除」，断言总账不变。

### F2 部分成本

`Totals` 增 `partial_cost`。三种来源：汇总层用 `has_partial_cost` 与「跨会话有/无成本混合」；事件腿与尾账用覆盖计数比较。`merge` 另行检测**跨腿缺口**（一腿全有价、另一腿全无价，各自内部都不混合，合起来仍是部分覆盖）。

展示：部分金额单元格带 `*` 标记（直接贴在数字上，二者不可分读），表下给出解释行。既有测试 `the_table_separates_the_two_costs_and_marks_the_missing_one` 的期望随之更新为 `["-", "$1.25*", "$6.25*"]` / `["$0.60", "$1.00*", "$1.00*"]`——今日列单事件、两列各自覆盖完整，故不带标记，这一点也一并断言。

## 五、批 D —— 可审计突变清单（`730d683`）

**结果：25/25 击杀，3 个作为等价突变剔除，退出码 0。**

过程值得记录：**首轮 28 个 mutant 只杀死 17**。存活的 11 个里，8 个是我给的 killer 测试根本不可能抓到（例如用一个根本没有冻结会话的 fixture 去验尾账规则）。这些暴露的**真实覆盖缺口已全部补齐**，新增回归：两条保留期是独立时钟、尾账只收封存后到达且放过过期的基线、封存只发生一次不重复盖章、冻结不动已计算出的成本、excluded 事件不入基线、pruned 键重观测是可见变更、部分成本必须标在数字本身（原测试只断言页面里出现 "partial"，footer 存在即通过，抓不到单元格标记被移除）、尾账无成本记录不得显示为 0。

3 个等价突变**剔除而非计入击杀**，各自附不可能改变终态的论证：

1. `fold/baseline-key-is-folded`——`ingest_one` 的基线短路被去掉后，`fold_key` 仍用同一 `COALESCE(...)` 判据返回零变更，终态/证据/结局三者全同。真正承载该行为的是另一处守卫，由 `rebuild/baseline-is-rederived` 击杀。
2. `compact/baseline-remarked-on-every-pass` 与 3. `compact/sessions-refrozen`——两者都被 `compact_expiring_sessions` 的 `s.frozen_at IS NULL` 挡住：已冻结会话永不再进计划表，所以语句里的 `frozen_at IS NULL` / `frozen_baseline_at IS NULL` 是纵深防御而非承载条件。

第 2、3 条同时说明了一件对复审有用的事：**计划表的谓词才是冻结的承载点**，把纵深防御当作被杀死的 mutant 计分，正是突变分数虚高的典型来路。

## M1 · 回收后重读的防护（定案 7）

### 机制选定：按 source_instance 的回收时间水位

新表 `source_reclaim_watermarks(source_instance_id PK, reclaimed_through_ms, updated_at)`，迁移 v5
`reclaim-water-line`（append-only）。

- **写侧（compact）**：删除过期投影**之前**、同一事务内，把「本轮即将搁浅、且已被永久层计入」的事件中
  最大源时间戳并入水位（只升不降）。判据 = `status='counted' AND session_key IS NOT NULL` 且其会话行存在
  ——恰好覆盖两类：本轮冻结会话在步骤 2 已刷入汇总的成员，以及已冻结会话上刚被尾账吸收的尾侧事件。
  deferred 会话排除在外（其事件不删）。
- **读侧（fold_key）**：投影行不存在 **且** 候选胜者 `timestamp <= 水位` ⇒ 零触碰（不建投影行、不写子表、
  不打 dirty）。判据放在 `fold_key` 而非 `ingest_one`，因此**四入口统一**（摄取／规范化替换／dirty 重算／全量重建）。
- **判据是观测集合的纯函数**（读派生胜者而非到达观测），故交换/乱序/重放/重建四场景同判、收敛契约不破。
  有专门回归钉住（a_rebuild_does_not_resurrect_a_reclaimed_projection）——正是上一轮只堵重建入口那个洞的对偶。
- **冲突证据不在守卫内**：它描述观测集合，而观测层此边界零改动；若一并 withhold，证据闭包会依赖到达顺序，
  重建与增量将分叉。

### 论证：为什么是这个形态

不变量要求「已永久计入且被回收的事件，再次到达零触碰」。可用判别信息只有到达观测本身——身份载体
（投影行）恰恰是被回收掉的那个。因此任何**逐事件保留标识**的形态（墓碑表、布隆过滤器）要么违反存储有界
（ADR-0011 永久层年增 < 50 MB），要么违反可判定（概率结构）。剩下的可判别量只有**时间**：回收总是按
`timestamp < cutoff` 的时间前缀进行，故「已回收前缀的上界」是**完备**判别式——任何被回收事件的时间戳必
<= 水位。O(1)、确定、与事件量无关。

代价：水位之下到达的**迟到真新事件**同样被拒。这不是妥协而是定案 7 明写的裁断（不可区分时取不二次计入），
且已按其要求留证。窄墓碑表 + 时间界能缩小误拒，但把「有界」换成「有界但更大」，并引入清理时机这一新的
正确性面；在缺口可见的前提下不值得。

### 存储量级估算

每行 = TEXT id（SHA-256 十六进制 64 B）+ 2 × INTEGER（<= 8 B）+ 行开销，约 **90 B**。行数 = 源实例数
（源 × 账号 × 机器 × data_root）：六源单机单账号 = 6 行约 **0.6 KB**；10 台机器 × 6 源 = 60 行约 5 KB。
**与事件量无关，年增趋近 0**，相对 ADR-0011 永久层年增 < 50 MB 预算可忽略。

### 「真新事件被判为重读」的可见性

新证据码 `reclaimed-key-reobserved` 写入 ingest_errors，字段严格按补文表：stream_key = 到达观测
originStream；source_position = 其 canonical position；detail_key = eventKey；payload_hash = 到达归一化
canonical JSON 的 hash（同集合取字典序最小）；payload_len = 同一 canonical JSON 的 UTF-8 字节数（取最小）；
occurrence_count = **不同 observation 的集合基数**（同一 observation 重放不计数、不移动时间——实现上以
「观测行确为新插入」为门）。每一次少计都逐键可数、可定位到具体流与位置。

## MF-1 换判别器：时间水位 → 事件身份

### 形态

迁移 v5 **就地替换**（v5 从未合入 main，不另立 v6 去删一张只在未合分支上存在过的表）。
新表 `reclaimed_event_identities`，新模块 `crates/tokly-core/src/reclaimed.rs`。

判别器 = **每源实例 64 个分片，每分片一条可伸缩 Bloom 链**（scalable Bloom filter，Almeida 等）。

- **身份摘要**：`SHA-256("tokly/reclaimed-event-identity/v1" ‖ 0x1f ‖ instance ‖ 0x1f ‖ event_key)`。
  首 4 字节 mod 64 定分片；随后两个 64 位字作双散列的基与步长（步长强制为奇数）。
- **链**：第 i 片容量 `64 << i`、散列数 `16 + i`，故该片假阳性率 `2^-(16+i)`；
  整链上界 `Σ 2^-(16+i) = 2^-15 ≈ 3.1e-5`，**与链长无关**——这正是选可伸缩形态而不是定宽
  Bloom 的原因：定宽的会随写入饱和到"对一切答有"，那是把少计放大成全拒。
- **位宽**：`m = n·k/ln2`，整数运算（`1/ln2` 以 1_442_695/1e6 定点表示，向上取整到整字节）。
  用浮点会让一个永久结构的几何依赖第一次写它那台机器的舍入。
- **写入**：先查链，已答「有」则什么都不写（幂等，第二轮 compact 扫同一批行时字节不变）；
  否则写最后一片，满则新开一片。
- **查询**：读该分片全部片，任一片答「有」即「有」。

每行自带 `hash_count` 与位宽（`length(bits)*8`），所以上面的参数是"新片按什么建"，
而不是"代码对既有片的假设"——将来调参不会让既有片失效。
**分片数与摘要函数是红线**（模块首注释与 schema 注释都写明）：改它们等于旧身份查不到，
即亲手制造假阴性，而假阴性正是这个结构存在的唯一理由。

### 正确性论证：为什么它在观测剪枝下不动

三轮复审的根因一般化是「任何以可随观测集合剪枝而移动的派生量为判据的形态都不成立」。
水位读 fold 派生胜者的 `timestamp`；`usage_observations` 按各行自己的 `event_timestamp` 剪枝，
集合被裁剪后胜者换人、时间戳上移，水位不动。

事件身份 `(source_instance_id, event_key)` 是剪枝不变量，三条：

1. 它是观测层键的前两列，剪枝按行删除，不改变任何存活行的 `event_key`；
2. 它不由 fold 派生——fold 在同一 `event_key` 的观测集合里选胜者，胜者是谁不影响这个键是谁；
3. 因此「该身份是否已被回收」的真值，只由 compact 是否删过它的 counted 投影决定，
   与观测集合此刻是什么、胜者是谁、时间戳在哪里全部无关。

由此两条性质是**构造性成立**，不是靠测试碰出来的：

- **增量腿 = 重建腿**：判据不读任何两腿会不同的东西。旧形态在 `projection_absent` 上分叉
  （增量腿投影还在 → 不判；重建腿投影全无 → 判），一次携带更旧时间戳的到达就能把两腿分开。
- **四场景收敛**：交换/乱序/重放/重建改变的是到达顺序，判据不读到达顺序，也不读集合。

**无假阴性**（绝不双计）：位只置不清、片只增不删；`record` 只在链答「无」时才写，
而链答「无」蕴含该身份的位在每一片里都不全为 1；一旦写入，该身份在其所在片里的位全为 1，
`present()` 对该片恒真，后续写入只会置更多位。故写入过的身份永远查得到。

**并发**：读-改-写一整片位图看似有丢更新风险，但 WAL 下写事务是串行的，
且 compact 在本步之前已写过 rollup（已持写锁），第二个 compact 只会拿到 BUSY/BUSY_SNAPSHOT
而不会覆盖。已复核，不需要额外机制。

### 覆盖范围（MF-2）

推进侧不再有 `session_key IS NOT NULL`。记录集合 = **删除会剪掉的全部 counted 投影行**，
与删除共用同一段 SQL（`compact.rs` 的 `STRANDED_ROWS` 常量），只多一个 `status = 'counted'`：

- `counted` 是"永久层是否计入过它"的完整谓词——日聚合、会话汇总、尾账三者都只读它；
- **无会话事件同样记录**：它不进会话汇总，但它的日聚合键由**同一轮**第 5 步定格，属永久计入。
  今天报表五条腿都不读 `daily_usage_rollups` 所以观察不到；M2 趋势/下钻落地即零防护复现；
- `excluded` 行照常被删除但**不记录**——永久层从未计入过它，记录它只会制造纯少计。

推进与删除现在是同一个函数 `reclaim_stranded_projections` 的两句，共用一段 WHERE，

  单链在同样规模下每次要读约 4 MB。

**这是一笔真花销，不是白拿**：判别器吃掉年增预算的三到四成。可调旋钮是首片散列数

### 推进侧进性质模型的方式

这是 MF-1 里"两轮没抓到"的根因：P5 与 P6 都用**手写 SQL** 模拟回收
（把水位设成那一个键自己的时间戳），真正的推进查询从未在性质之下跑过。
一个自己重写被测步骤的模型，只是在和自己达成一致。

1. `compact.rs` 新增 `reclaim_expired_projections(store, cutoff, now)`，内部就是 `compact`
   在第 2 步与第 5 步之间跑的那一段（`plan_expiring_keys` + `reclaim_stranded_projections`）。
2. P5（`convergence.rs`）与 P6（`evidence.rs`）的 `Reclaim` op 都改为调用它。
3. **op 语义随之从"回收这一个键"改为"回收这个 cutoff 之下的一切"**——那才是这个操作真实的形状。
   模型侧 `ContractModel::reclaim_through(cutoff)` 独立从条文算出"删除会剪掉哪些行"，
   harness 断言两者行数相等。MF-2 那条 `session_key IS NOT NULL` 若被写回去，两个性质立刻红。

- `prune()` 现在同时清 `shadow` 与 `seen_coords`：被搁置的坐标也在观测日志里，而剪枝删的正是日志。
  `seen_coords` 决定 `appended`，而 `appended` 的定义是"日志增长一行"、P5 拿它对真表断言；
  记着一个已被删除的坐标，会让模型声称日志没长而它长了，随后对一次真实发生的拒绝**扣下证据**。
- 被剪枝的键的到达现在进 `shadow`（原先直接丢弃）：零触碰的域是投影层与永久层、不含观测层
  （定案 7 ②追认），到达照常入日志；而 `observations_pruned_at` 标记长在投影行上，
  投影一旦被回收，fold 就会重新读到它们。
- 旧模型里"被剪枝的键永不可能被回收"由旧 `reclaim()` 的守卫强行保证；扫描式回收按 cutoff 取行，
  不问这个，于是该状态第一次可达。

## MF-3 证据两列同源

`store.rs` 写 `obs.payload_hash`（源 payload 的 SHA-256）与 `normalized.len()`（canonical JSON
字节数）。两者各自都站得住，**放在一起就没用**：消费者拿着这一对无法互验，
而同时带两列的唯一理由就是互验。

存储层根本没有源 payload 的长度，所以这是一处**契约缺口而不只是写错**：
`NewObservation` 新增 `payload_len: Option<i64>`，紧挨它一直带着的 hash。

- adapter：`Some(payload.len() as i64)`（就是它 hash 的那串字节）；
- API 周期 reconcile 的合成观测：`Some(excluded.len() as i64)`——它 hash 的正是这段 canonical
  excluded JSON，即补文表里唯一的例外，两列仍同源；
- **从 `pending_messages` 恢复出来的观测：`None`**。见下「偏差与提请裁决」。

`row.payload_hash == obs.payload_hash`，而夹具里 `obs.payload_hash` 是捏造的 `"h00"`——
**它对实现求值，永远分辨不出这类偏差**。现在改为：喂进一行真实源 payload，
两列的期望值都从那行字节**独立算出**，并额外断言 `payload_len != canonical_len`

新增变异体 `evidence/refusal-columns-describe-different-objects`——把 len 改回 canonical JSON

## S-1 `has_partial_cost` 捕获点前移

`compact_sealing_sessions` 建在第 5 步，而第 3 步的删除已经把过期事件全剪掉了。

## S-4 定案 5 (b) 零触碰域精确化（含一条偏差）

原 `snapshot_content_domain` 把**整个证据面**排除，理由只写在测试注释里——

理由：(b) 类到达做的任何事都不构成生命周期码的依据——被剪枝/被回收的键在到达定案 5 之前
就已分类完毕。

- 实测反例（P5 立刻判红）：一次 (b) 类到达（更小坐标、同内容）在 `s0` 上落位 `...0000`，
  与 `s1` 上既有坐标构成一对**新的** `cross-stream-diff-payload`；

- 契约依据在定案 7 的②追认里：**冲突是观测集合的历史性质，与投影是否接纳无关**。

## 另需裁断：S-5（本轮不修）

### 事实

`SourceInstance::stable_id()` = SHA-256 over (source, account|none, machine, data_root)
（`crates/tokly-core/src/domain.rs:63`）。adapter 后来学到 account ⇒ 新 id。

### 判断一：新机制**不缓解**它

判别器按 `source_instance_id` 键控，新 id 下判别器为空——与水位形态完全一样，没有任何改善。

### 判断二：它比定案 7 宽得多，不该塞进定案 7

实例 id 变更打断的不是判别器一个结构，而是**每一个以它为键的结构**：

- `watermarks` 的 PK 含 `source_instance_id` ⇒ 新 id 没有游标 ⇒ 每条流从 position 0 全量重读；
- `usage_events` 的 PK 是 `(source_instance_id, event_key)` ⇒ 同一事件在新 id 下是**另一行投影**；
- `sessions`、`daily_usage_rollups`、`daily_tool_rollups`、`session_tail_ledger` 同理。

也就是说：**即使一次 compact 都没跑过、一个事件都没被回收**，实例 id 一变整段历史就双计。
实测 report total = 3 / truth = 2 只是这个更大缺陷的一个切片；判别器是受害者，不是成因。

在定案 7 内打补丁（例如让判别器改按 (source, machine, data_root) 键控）是**有害的半修**：
它会让判别器拒绝那些投影层正在新 id 下欢快重建的事件，制造两层互相矛盾的状态，比现在更难诊断。

### 建议

路由到**阶段八 adapter 成熟期**，作为「实例身份稳定性」独立条款。两条候选：

- **(a) 身份不含后学属性**：id = (source, machine, data_root)，`account` 降为可变属性列。
  代价是 `source_instances` 的 UNIQUE 要改 + 一次迁移；收益是这类断裂从此不可能发生。
  **我倾向这条**——就已知六个源而言，data_root 本身就是按账号分的，
  「同机同 data_root 两个账号」不是真实配置。
- **(b) 显式 rekey 迁移**：adapter 升级身份解析能力时跑一次，单事务内把旧 id 改写为新 id，
  覆盖所有以它为键的表。代价是每次身份规则演进都要配一次迁移，且中途崩溃的语义要另想。

两条都超出 M1 与定案 7 的范围。本轮不动。

## 偏差与提请裁决（汇总）

1. **S-4 冲突面**与裁决文字不符，见上文，已按契约实现并上报。
2. **`reclaim_expired_projections` 是一处刻意的可测性接缝**：`compact.rs` 里唯一没有产品调用者的
   公开函数，公开的唯一理由是让 P5/P6 驱动真正的推进查询（MF-1 的要求）。
   备选是 `#[doc(hidden)]` 或 feature 门控。**请裁定是否接受这个公开面。**
3. **`pending` 路径的 `payload_len` 是 NULL**：`pending_messages` 存了 payload 的 hash 但从未存长度，
   所以从它恢复出来的观测无法陈述源 payload 的长度。两列因此是「同源但其一缺失」，
   不是「描述两个对象」，方向仍是缺口可见。补齐需要一次 v6 迁移加一列
   （`last_payload_len`）——为一条罕见路径上的诊断长度加一次迁移，我判断不值，**但这是取舍不是遗漏，请裁定**。
4. **`pruned-key-reobserved` 的 `payload_len` 写 NULL**（既有行为，本轮未动）。
   两列同源原则说「凡存在真实到达观测的证据码，两列一律描述该观测的源 payload」，
   而这一条有真实到达观测。补文表只列了 `api-reconcile-absent` 与 `reclaimed-key-reobserved` 两行，
   所以我按 MF-3 的字面范围只改了后者，**没有顺手改它**——改它要动 P6 模型的期望，
   属于超出必修范围的改动。**请裁定该原则是否要求补齐它。**
5. **v5 迁移就地替换**而非新增 v6：v5 从未合入 main，新增 v6 去删一张只在未合分支上存在过的表
   是给正本留一条无意义的历史。若维护者已在某处应用过旧 v5，请告知，我改成 v6。
