## 关键设计裁决（含被弃备选）

1. **锁 / daemon.json / secure_file 归属 `tokly-service`**。daemon 所有权是进程模型属性，三端共享。备选"放 tokly-server"弃：桌面是 daemon 候选（ADR-0004）却不依赖 server。
2. **文件锁用 std `File::try_lock`**（Windows `LockFileEx` / POSIX `flock`），崩溃即内核释放。备选 `fs4`/`fd-lock` 弃：std 已覆盖，零依赖。
3. **读池自建**（tokio `Semaphore`→后改 `mpsc` 通道 + `Mutex<Receiver>`）：所有 rusqlite 调用经 `spawn_blocking`，handler 不碰连接。备选 r2d2 弃。读连接以 **READ_WRITE flag 打开 + `PRAGMA query_only=ON`**：read-only flag 在"首个读者需创建 WAL shm"的边角会失败。
4. **service 是 async API**，TUI 用运行时 block_on——同进程零 IPC 不变，"spawn_blocking 全覆盖"只需实现一次。
5. **schema 握手双向拒开**：`Service::open` 读侧永不建库/迁移；缺失→NotInitialized、版本不等→SchemaMismatch。只读降级路径与 daemon 路径共用同一函数。
6. **Origin 缺失语义**：Host 全路由强制精确匹配；Origin 出现即校验、伪造即 403；**缺失放行至 token 层**（同源 GET fetch 按规范不带 Origin）。→ 维护者裁决采纳并写入 ADR-0012。
7. **Windows DACL 经 `icacls` 子进程**（先建空文件→硬化→写入→rename）。备选弃：`windows-sys` 直调需 unsafe（workspace forbid）、`windows-acl` 停更、PowerShell `Set-Acl` 本机实测模块加载失败。
8. **按日序列直接从 `usage_events` 按 UTC 日聚合**：rollup 表在 `tokly compact` 落地前恒空；时区随行聚合是 compact 的职责。
9. **desktop src-tauri 独立 cargo workspace**：Tauri 依赖树不进根门禁；lint 政策本地重申。代价（无 CI 覆盖）后由二轮裁决补齐。
10. **ts-rs i64 按字段覆写为 `number`**：JSON 线格式是 number，默认 `bigint` 描述的是线上不存在的形状。
11. **种子数据锚定"两天前 UTC 午夜"**：固定日期会让默认 30 天窗口一个月后失效。
12. **依赖裁决**：新增 tokio / axum / tokio-stream / ts-rs / ratatui / crossterm / getrandom，全 MIT/Apache 双授权族，根 deny 白名单零扩充。ratatui 定 **0.30**：0.29 携带停更的 `paste`（RUSTSEC-2024-0436），0.30 已移除。

## 裁决落地（一轮裁决）

### 锁完整性可见性兜底

| 条款要素 | 实现 |
|---|---|
| 周期核验持锁路径身份 | `daemon::lock_intact()`：重新打开路径并尝试加锁——**内核拒绝对已持有的同一文件二次加锁（同进程亦然）**，故"加锁成功"即证明路径已指向另一个文件；`Err` 表示本轮无法判断，下轮再试 |
| 周期 | 默认 30s，`--lock-check-ms` 可调 |
| 停止摄取 | 看门狗**持有写连接**，判失即 `drop(store)`——进程内不再存在任何写路径。不是标志位模拟，是机制本身 |
| 不退出、不重新抢锁 | 探测锁随 `probe` 析构释放；服务继续应答读请求 |
| 状态可见 | `OwnershipStatus` DTO + `/api/status` + 演示页 |

**为什么不用字面 `file_id`/inode 比对**：Windows 上 `MetadataExt::file_index` 需 unstable feature（`windows_by_handle`），而 Windows 是一等平台；二次加锁在两平台都是稳定 API，语义更强。

回归三条 + 突变自证（把"文件不存在"判定翻转为"完好"后端到端测试 10.7s 超时变红）。

### `Origin` 与 DACL 与增补条款逐条对读，一致

`auth.rs` 的 Origin 处理与 Host 全路由校验、`secure.rs` 的 reset→授予→读回校验→fail-closed，均与 ADR-0012 増補逐字对应，无偏差。

### 受阻上报：`ingest_errors` 与 schema 冲突

`ingest_errors.source_instance_id` 是 `NOT NULL REFERENCES source_instances(id)`（源作用域，UNIQUE 键含 stream_key/position），而锁完整性是进程级事件；未扫描过任何源的 daemon 该表为空，无合法 FK 值。四条路径均涉契约取舍，按红线停下上报。→ **维护者二轮裁决：撤回该条款，不持久化，现有实现即最终形态。**

## 二轮裁决落地

### 桌面树 CI 覆盖

新增 `desktop (apps/desktop)` job（ubuntu）：装 WebKitGTK 与 Tauri 系统依赖后跑 `fmt --check → clippy -D warnings → nextest → build → cargo deny`；**不做 bundle**。`apps/desktop` 保持不入 workspace members。

许可证单列 `apps/desktop/src-tauri/deny.toml`（作用域仅桌面树）：

| 新增 | 命中 crate | 依赖链 | 理由 |
|---|---|---|---|
| `Apache-2.0 WITH LLVM-exception` | target-lexicon | 构建期目标三元组解析 | Apache-2.0 加链接例外，**严格弱于已允许的 Apache-2.0** |
| `MPL-2.0` | cssparser / cssparser-macros / dtoa-short / selectors / option-ext | 前四者 tauri-utils →（build）dom_query → Servo CSS 栈；option-ext 经 dirs | OSI 批准、**文件级 copyleft**，约束的是对这些文件的修改（我们不修改）。拒绝它等于拒绝 Tauri，而 ADR-0004 已定案 |

### POSIX ACL 对等

`chmod` 不清除扩展 ACL，目录上的**默认 ACL 更糟——它落到之后创建的每个文件上，包括 `tokly.db`**（SQLite 建的，不经 `write_private`）。

| 环节 | 实现 |
|---|---|
| 检测 | `ls -ld` mode 串尾部 `+`（access 与 default 皆标记）——只依赖必然存在的工具 |
| 清除 | Linux `setfacl -b`（目录加 `-k`）；macOS `chmod -N`；其他 unix fail-closed |
| 读回校验 | 清除后重新检测，仍有即 `Err` → 三端拒绝启动 |
| 工具缺失 | 仅在"确实有 ACL 要清"时触发报错——不把"无法验证"当"验证通过" |

**验收在 CI Linux runner**：两条测试用 `setfacl` 造污染（含 default ACL）再断言清除，实测**在 ubuntu 上执行并通过**（79/91、80/91），非 cfg 跳过。本机 Windows 无法运行，故另用独立 scratch crate 对 **linux 与 macOS 两个目标各跑 clippy -D warnings**，均干净（尤其确认 macOS 不因 linux-only 测试的辅助函数触发 dead_code）。

## 三轮裁决落地

### advisories 最终形态：警告而非 ignore、而非跳过

桌面 job 改为 **`cargo deny check --warn unmaintained`**（单命令覆盖四项）。`-W` 只降指定 lint，**`vulnerability` 与 `yanked` 保持 deny**；`deny.toml` 零 ignore 条目。

### 期间一次 CI 红：runner 第三方源，非本仓代码

`rust (ubuntu-latest)` 在 `install acl tooling` 步骤红一次：runner 镜像自带的 `packages.microsoft.com/repos/azure-cli` 返回 **403**，令整个 `apt-get update` 退出码 100——而 Ubuntu 主源全程可达。同步骤上一跑为绿，本笔改动只触及 desktop job，故与本仓代码无关。
