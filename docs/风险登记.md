# Tokly 风险登记

每条按「风险 / 证据 / 对冲 / 状态」登记。来源：[审查-2026-08-02](research/审查-2026-08-02.md)、[审查-2026-08-02-二轮](research/审查-2026-08-02-二轮.md)（外部独立复审）；R6/R7 来自三轮终审；**R8–R12 来自 [审查-2026-08-03](research/审查-2026-08-03.md) 四轮修订**。状态随里程碑推进更新；新增风险追加在文末。

## R1 · Bun 单点风险——已关闭

- **状态（2026-08-02 三轮终审）**：**已关闭，随栈切换消除**（[ADR-0001](adr/0001-技术栈与运行时.md)：内核 Bun/TS → Rust，TUI OpenTUI → Ratatui + Crossterm，桌面 sidecar → Tauri 直嵌）。四类同源风险（OpenTUI Windows 质量、node:sqlite 缺失、94MB 编译体积地板、sidecar 孤儿进程）随被移除的技术层一并消失；原对冲同步作废。
- **历史证据（保留备查）**：bun.com/reference/node/sqlite 长期标 "Not implemented"；本机 Bun 1.3.14 实测 "No such built-in module"；本机复现编译体积 93.90MB；opentui#152 已关闭但留闪烁/低帧未完成项。

## R2 · 价格的时间维度

- **风险**：用今天的价目表回算历史成本是 bug 温床——模型调价后历史月份被错误改写，`tokly reprice` 的设计初衷反而变成污染源。
- **证据**：LiteLLM 价目持续滚动更新，无生效日期维度（2026-08-02 审查 §四 盲区 3）。
- **对冲**：`pricing_history` 带 `[effectiveFrom, effectiveTo)` 区间 + 区间重叠触发器，reprice 用 `event.timestamp` 匹配事件时点价；远程表无历史时自建覆盖层。**2026-08-03 补两条**：舍入与求和顺序定死使 reprice 可复现（[ADR-0015](adr/0015-计价精度.md)）；**首次安装前的历史无价目可匹配**，按最早快照计价并标 `priced-at-snapshot`，UI 显示为"计算值（价目回溯不可得）"——这个结构性缺口此前未被承认。
- **状态**：方案已定（DDL 已含触发器），pricing 层实现时落地（M1）。

## R3 · 多通道同源双计

- **风险**：同一源的多个采集通道并存（Copilot 的 OTEL / session-state / 个人 API / 企业报告是最完整实例），直接并库必然重复计数。
- **证据**：ccusage #1174（双源共存去重是开放问题）；2026-08-02 审查 §四 盲区 4。
- **对冲**：**用户配置唯一权威通道**，非权威通道照常入库但 `status='excluded'` + `channel` 区分。**2026-08-03 补齐落地面**：此前"用户配置"没有配置子系统也没有 UI，对冲实际悬空——现由 [ADR-0010](adr/0010-配置子系统.md) 的 `sources.<name>.authoritative_channel` 与[组件规格](design/组件规格.md) §8 设置界面承载。
- **状态**：已对冲（契约 + 配置 + UI 三层齐备），待实现（M2）。

## R4 · 静默丢数据三点位

- **风险**：① Cursor 库 VACUUM 后 rowid 重编使水位线失效；② OpenCode `finish` 永空的中断轮次悬置不结算；③ `(time_updated, id)` 复合游标页边界同毫秒并发漏行。
- **证据**：2026-08-02 审查 §三 P1-7；二轮审查 §2 更正旧"已修"状态为错误。
- **对冲**：① backup API 副本 + DB generation；② `pending_messages` 状态机；③ 轮内严格分页与跨轮 checkpoint 回退分离 + 尾部 safety horizon + 周期 reconciliation。**2026-08-03 补一条边界**：`pending_messages` 只适用于可按 id 随机重读的源；JSONL 类顺序水位线不使用该机制——"水位线不越过任何 pending id"在按偏移推进的流上会阻塞其后所有完整行（[数据库-schema](数据库-schema.md) 该表注释）。
- **状态**：方案已定，待实现；三个点位各至少一个回归用例并纳入收敛性 property tests。

## R5 · codeburn 竞争窗口期

- **风险**：codeburn 的形态覆盖已接近 Tokly 目标形态，它差我们**只差持久化仓库层**，补上即正面重叠。
- **证据**：github.com/getagentseal/codeburn，GitHub API 2026-08-02 当日数据（9,095 stars / 4 个月 / 36 源；Anthropic 开源计划 recipient，非"资助"，二轮审查 §3 更正）。
- **对冲**：核心数据层压到 M1、配额窗口提到 M2 并进第一带，以「永久仓库 + 跨工具配额聚合」抢先固化差异化。
- **张力（2026-08-03 补记）**：M0.5 冻结门在工程上正确，但它按周计的阻塞与按月计的窗口期直接竞争。**当前判断是不缩短冻结门**——已入库的错数据不可逆，而窗口期丢了还能靠质量赢回来；这条取舍写在这里是为了它被显式承担，而不是事后当成疏忽。若窗口期证据变化（竞品发布仓库层），重新评估的触发条件是：竞品出现事件级持久化 + 跨工具配额聚合两者同时具备。
- **状态**：监控中（每月复核竞品仓库层动向）。

## R6 · Linux WebKitGTK 桌面体验

- **风险**：Tauri 2 在 Linux 依赖系统 WebKitGTK，发行版间版本碎片化，旧引擎与开发基线有能力差距；透明窗口在部分 NVIDIA 驱动下渲染异常。Linux 桌面是三端体验最弱的一环（此判断待 M5 实测证实或证伪）。
- **证据**：WebKitGTK 版本随发行版锁定，应用侧不可控；ADR-0004 边角坑登记。
- **对冲（2026-08-03 按 [ADR-0009](adr/0009-运行期基线.md) 重写）**：① 下限改为**引擎 ≥ 2.44**——原文的 `webkit2gtk-4.1` 是 API/ABI 版本号，不表达渲染能力，用它当能力下限是错的；② 低于下限时桌面壳**拒绝启动**并引导 Web + TUI，不做劣化中间态；③ 透明窗口默认不透明，仅作显式开启项；④ Linux CI 截图冒烟。
- **状态**：开放；M5 首次实测。

## R7 · WebKit CSS 能力滞后

- **风险**：桌面窗口经系统 WebView 渲染，CSS 特性落地滞后于 Chromium；栈内特性在旧 WebKit 上缺支持会造成桌面与浏览器视觉分叉。
- **证据**：Tauri 使用系统 WebView 而非捆绑 Chromium（这正是体积优势的来源）；WebKit 特性节奏由 OS 版本决定。
- **对冲（2026-08-03 按 [ADR-0009](adr/0009-运行期基线.md) 重写）**：① **基线不再是空话**——browserslist 明确为 `Chrome/Edge >= 120, Firefox >= 129, Safari >= 17.4`，Lightning CSS targets 由此生成且是唯一降级配置源；② macOS 下限提到 **14**（对齐 Apple 自身支持线），这同时解锁 `linear()` 弹簧与 `@starting-style`，使动效可以退回平台原生；③ View Transitions 只作渐进增强，必须有 WAAPI 等价路径；④ OKLCH 派生全部在构建期或安装期完成，运行期只消费 sRGB 字面量——从根上消除运行期色彩支持依赖。
- **遗留动作**：基线版本号系按特性门槛推定，**冻结前须按 caniuse 逐项复核并回填复核日期**（M0.5 冻结物之一）。
- **状态**：开放；M5 首次三平台截图比对时验证。

## R8 · 解析器腐坏（2026-08-03 新增）

- **风险**：六个上游工具持续演进格式，而**最危险的形态是"结构合法、语义变了"**——JSON 解析成功、字段名相同、含义不同，产出看起来正常的错数据且无任何痕迹。这大概率是本产品真实世界里的第一号故障源，此前竟无风险条目。
- **证据**：公开仓 `docs/开发流程.md` 自述"解析器是本项目最易腐坏的部分"；二轮审查记录的生态版本快照（Codex 0.146.0 / Claude Code 2.1.220 / OpenCode 1.18.11 / Gemini CLI 0.53.1 / Copilot CLI 1.0.77）在数月内即会全部过时；Codex 已出现 `ordinal` 行级字段与 `.jsonl.zst` 冷存储等演进。
- **对冲**（[ADR-0014](adr/0014-诊断与格式演进.md)）：每个 adapter 声明**已验证格式版本集合**（即 golden fixtures 实际覆盖的集合）；集合外版本 → `status='excluded'` + `exclude_reason='unverified-schema'` + `ingest_errors` + UI 状态点转"有问题" + `tokly doctor` 输出。**少算是可见的，错算是不可见的**——本对冲选择让用户看见缺口。
- **状态**：方案已定，M1 随首个 adapter 落地；每次支持新版本须同步更新集合与 fixtures。

## R9 · 定价数据源依赖（2026-08-03 新增）

- **风险**：成本是产品主输出，而定价完全依赖第三方的 LiteLLM 定价 JSON。R2 只覆盖了它的**时间维度**，没覆盖**可用性、许可与格式变更**三个同样致命的维度：上游停更、改许可、改结构，都会让成本能力直接失效。
- **证据**：全行业事实标准就是这一个文件（竞品调研"被验证的实践"第 1 条），没有第二来源；ADR-0006 对"依赖侧全部 MIT 兼容"只有断言没有机制。
- **对冲**：① **bundled 快照随版本发布**是保底层，远程不可达时产品不失能（保鲜链已有此设计，此处确认它同时是可用性对冲）；② 远程解析加**结构校验与版本标识**，结构不符时保留旧缓存并标 `stale`，不静默接受；③ 用户覆盖 `pricing.json` 是最终逃生口，格式在公开仓文档化，使用户在上游失效时可自救；④ **许可合规进 CI**（`cargo-deny licenses`），依赖树许可证从断言变成门禁。
- **状态**：①③ 已在契约内，②④ 待实现（M1 / CI）。

## R10 · 范围与产能比（2026-08-03 新增）

- **风险**：六源 × 三端 × 三平台 × "每个点打磨到极致"，与实际维护产能直接竞争。表现形式不是做不完，而是**广度先于质量推进**：新 adapter 上线而旧 adapter 的 fixtures 与口径测试没跟上，错数据静默入库且不可逆。这是项目最大的结构性风险，此前无条目。
- **证据**：路线图 M3 加两源、M6 再加一批；而每个 adapter 都需要持续跟踪上游格式（R8）。ADR-0001 已登记"adapter 迭代速度下降"的代价，但封顶手段（贡献套件）排在 M6。
- **对冲**：① **优先级判据写进路线图**——任何新 adapter 不得先于已有 adapter 的 golden fixtures、口径一致性测试与已验证格式版本集合完成；② 广度可推迟，已入库的错数据不可逆，两者不对等，判据不接受个案豁免；③ 贡献套件（M6）把单 adapter 成本压到"写映射 + 喂 fixture"，是产能侧的唯一结构性解。
- **状态**：判据已写入路线图，随每个 adapter PR 执行。

## R11 · Windows 首发不签名的信任摩擦（2026-08-03 新增）

- **风险**：[ADR-0013](adr/0013-分发信任链.md) 决定 Windows 首发不购证书，用户会遇到 SmartScreen 警告。部分用户会直接放弃安装，且对一个"读取我全部用量数据"的工具，未签名会放大不信任。
- **证据**：SmartScreen 对无信誉签名的可执行文件默认拦截；这是分发链路上可预期的转化损失，非假设。
- **对冲**：① 下载页明示警告成因与绕过步骤，并提供 SHA-256 校验和；② 提供 winget 清单（winget 通道的信任模型不同）；③ **1.0 前引入 Azure Trusted Signing**（订阅制，无需 EV 硬件令牌，与无人值守 CI 兼容）；④ macOS 侧首发即签名并公证，不在两个平台同时留缺口。
- **状态**：开放；M5 首次分发时观察实际影响，1.0 前关闭。

## R12 · 嵌套双仓的误删与泄漏（2026-08-03 新增）

- **风险**：私有仓 `internal/` 位于公开仓工作树内部并被 `.gitignore` 排除，产生两条真实路径：① **`git clean -xdff` 会删除 ignored 目录**，即整个私有仓工作树——而这正是清理 Rust `target/` 时最常敲的命令；② 一次 `git add -f`、一次误改 `.gitignore`、或 IDE 的"全部加入版本控制"，都能把内部文档送进公开仓的 commit。
- **证据**：2026-08-03 的工作区重组过程中，公开仓工作树连同其未提交的 core 实现一并从磁盘消失（约 3,774 行，staged 未 commit、未 push，不在任何 git 历史中）——嵌套布局的操作风险已经以另一种形式兑现过一次。
- **对冲**：① 外层 `.gitignore` 写 `/internal/`，**并**在 `.git/info/exclude` 重复一份（后者不随仓库分发，误改 `.gitignore` 时仍生效）；② **pre-commit hook 硬拒**任何路径含 `internal/` 的暂存文件；③ CI 加同规则检查，防 hook 被绕过；④ 约定**禁用 `git clean -xdff`**，清理走 `cargo clean` 或 `git clean -xdf -e internal`；⑤ 私有仓保持独立远端并**及时推送**——它是唯一不依赖本地磁盘的副本。
- **备选布局（记录备查）**：并列布局（`Tokly/public` + `Tokly/internal`，父目录不是仓库）可从结构上消除全部四条路径，代价只是公开仓根目录不等于工作根目录。当前采用嵌套 + 五重对冲；若任一对冲失效一次，即改并列。
- **状态**：开放；对冲 ①②③ 在公开仓工作树恢复时第一批落地。
