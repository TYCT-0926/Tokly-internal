## 后续实施顺序（供任务拆分用）

1. **`crates/tokly-tokens`**（M1.5）：按 令牌系统.md + 主题.md 实现——DTCG 解析、OKLCH 派生、gamut 映射、对比度救济、质量门、ANSI 降级链、`linear()` 弹簧生成；构建期由 `cargo xtask tokens` 调用，安装期由 `tokly theme install` 调用同一份代码
2. `packages/design-tokens`（M1.5）：DTCG 令牌源 + preview 验证页（**不含算法**）——五主题可切换，另用一张本地图片验证 bgImage 的 scrim 与运行时采样
3. 10 个官方变体（5 主题 × dark/light）的 golden JSON 与 CSS 入库，作为派生引擎的唯一验收面
4. 验收通过后进入 M2 Web Dashboard 施工

## 本轮修订（2026-08-03）

依据 [审查-2026-08-03](../research/审查-2026-08-03.md)：

- 组件规格补四个缺失组件——**配额油表**（差异化第一位却无规格）、**设置界面**（R3 权威通道的落地面）、**首次运行**、**数据健康**
- 热力图修**标定窗口**（改为等于显示窗口）与**分档函数**（非零日分位数切分）——原规则在真实右偏数据上会毁掉签名对象
- 动效补**感知层三条**（同时性、打断、方向对称），移除 Motion 依赖，验收改为可执行门禁
- 「签名时刻」由三个收敛为一个，与设计原则的"个性预算只允许一个"对齐
- Tier 3 登记表一次补全，结束"禁止字面量"与实际用值之间的自相矛盾
