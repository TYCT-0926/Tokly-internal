# 三层令牌系统规格

> 2026-08-02 二轮审查（docs/research/审查-2026-08-02-二轮.md §2 "M1.5 design-tokens" 共 11 条阻塞项）修订版。每处修订在行内注明依据（"二轮审查 §2 M1.5-n"）。

## Tier 1 · 主题家族种子（唯一可自定义层）

一个主题 = 一个 **ThemeFamily**，含 dark/light 两个变体种子（依据：二轮审查 §2 M1.5-1，ThemeSeed → ThemeFamily）：

```ts
interface ThemeFamily {
  id: string;                    // kebab-case，如 "amber"
  defaultMode: "dark" | "light"; // 家族默认变体（paper 为 "light"，其余官方主题为 "dark"）
  dark: VariantSeed;
  light: VariantSeed;
}

interface VariantSeed {
  accent: string;                // 强调色，hex 或 oklch()
  bgBase: string;                // 基础底色（决定色温），hex 或 oklch()
  grayTint: number | null;       // 灰阶色相（OKLCH H，0-360）；null = 纯中性
  overrides?: {
    accentSecondary?: string;    // 图表第二系列；缺省 = 中性灰
    bgImage?: { url: string };   // 仅 Web/桌面；仅本地文件路径或 data URL（见 bgImage 节）
    radiusScale?: number;        // 0–1，圆角缩放系数，缺省 1
  };
}
```

用户主题 = 一份 ThemeFamily JSON，放在 `~/.config/tokly/themes/<id>.json`，运行时校验（非法即拒绝并报告字段）。

**种子校验不设任何中间值域检查**（依据：二轮审查 §2 M1.5-3——原"accent OKLCH L ∈ [0.45, 0.85]"硬边界已删除，mono 官方种子实测 L=0.870/0.285 自身即越界）。校验仅含：JSON 结构、字段类型、色彩串可解析为 hex/oklch()、`grayTint ∈ [0,360] 或 null`、`radiusScale ∈ [0,1]`、bgImage URL 协议白名单。**色彩质量的唯一权威是派生完成后的对比度/gamut 质量门**（见"质量门"与"对比度救济算法"），救济无解才拒绝种子。除此之外没有任何可调项：字号、间距、动效、布局全部锁定。

## 派生总规则（所有 Tier 2 令牌适用）

1. **种子 hex 是输入基准，派生公式作用于 OKLCH 参数**（依据：二轮审查 §2 M1.5-4）：种子色先解析为 OKLCH `(L0, C0, H0)`；派生公式按需替换 L、缩放 C、保留 H，而非直接搬运 hex。
2. 派生全程在 OKLCH 空间运算；每个候选色先经 **gamut 映射**（见下），再转 sRGB 并量化为 8-bit hex 输出。对比度等一切门禁均对**量化后的 8-bit 值**计算（WCAG 相对亮度公式）。
3. 本文示例中给出的输出 hex（如 amber-dark 的 `bg.canvas` ≈ `#120F0C`）是**参考输出而非保证值**（依据：二轮审查 §2 M1.5-4）。最终输出以实现提交时冻结的 golden 快照为唯一权威。
4. **Golden 快照验收**（依据：二轮审查 §2 M1.5-4）：实现 `packages/design-tokens` 时必须提交 10 个变体（5 套官方主题 × dark/light）的 golden JSON（全部 Tier 2 令牌的计算值）与 golden CSS，入库作为验收快照；派生引擎的任何变更必须同步更新快照并在变更说明中列出差异。

### gamut 映射（统一规则，全部派生色适用）

依据：二轮审查 §2 M1.5-5——从仅 heat ramp 泛化到所有派生色。

```
输入：OKLCH (L, C, H)；容差 ε = 1e-6
判定：色值经 OKLCH→OKLab→linear-sRGB 变换后，r/g/b 三通道均在 [-ε, 1+ε] 内即合法
1. 若 (L, C, H) 合法，返回 C' = C
2. 否则保持 L、H 不变，在区间 [0, C] 上二分搜索最大的合法 C'：
   迭代至区间宽度 < ε（上限 64 次），返回下界
输出：OKLCH (L, C', H)；转 sRGB 时将各通道 clamp 到 [0,1] 后再做 8-bit 量化
异常：C = 0（纯中性）时直接合法，无需迭代
```

heat ramp 在此之上另加"整 ramp 统一缩放"规则（见"图表与热力图"），其余派生色逐色应用本映射即可。

## Tier 2 · 语义令牌（派生规则，dark 变体为例）

### 背景阶梯

| 令牌 | 规则 |
|---|---|
| `bg.canvas` | 取 bgBase 的 `(C0, H0)`，L = 0.17（dark）/ 0.97（light），gamut 映射后输出 |
| `bg.raised` | canvas 同 C/H，L +0.03（dark）；light 下 L = 1.00 |
| `bg.overlay` | canvas 同 C/H，L +0.07（dark，浮层专用，配 `shadow.overlay`）；light 下 L = 1.00 |
| `bg.scrim` | canvas 色 + alpha（bgImage 遮罩，透明度规则见 bgImage 节） |

> 消歧示例（依据：二轮审查 §2 M1.5-4）：amber 的 dark 种子 `bgBase = #171310` 实测 OKLCH L≈0.190；`bg.canvas` 公式强制 L=0.17，参考输出为 `#120F0C`——种子 hex 不等于输出 hex，二者差是公式行为而非实现错误。

### 前景阶梯（H=grayTint，C=0.008；grayTint=null 时 C=0）

| 令牌 | L（dark） | L（light） |
|---|---|---|
| `fg.primary` | 0.93 | 0.22 |
| `fg.secondary` | 0.75 | 0.38 |
| `fg.muted` | 0.62 | 0.48 |
| `fg.faint` | 0.42 | 0.68 |

### 强调色系列

| 令牌 | 规则 |
|---|---|
| `accent.solid` | 种子 accent 原值（L/C/H 不变，仅过 gamut 映射），派生后进入对比度救济（见下节） |
| `accent.hover` | solid L +0.06（救济后 L 之上） |
| `accent.muted` | solid C×0.45，L 用救济算法调至对 bg.canvas 对比 ≥ 3:1（用于大面积淡底） |
| `accent.onAccent` | `#000000` / `#FFFFFF` 二选一：对 accent.solid 对比度更高者；参与 onAccent 门禁 |

### 对比度救济算法（统一定义）

依据：二轮审查 §2 M1.5-7——非文本 accent/focus 统一 3:1、onAccent 4.5:1，消解原"light 下压至 4.5:1"与质量门 3:1 的冲突；救济从"自动微调"升级为完整可编码算法。

```
输入：候选色 OKLCH (L0, C, H)；达标谓词 P(L)
输出：救济后 L*，或"拒绝种子"错误
P(L) 定义：令 c = sRGB8(gamut_map(L, C, H))
  - accent.solid / focus.ring：contrast(c, bg.canvas) ≥ 3.0 且
    max(contrast(c, #000000), contrast(c, #FFFFFF)) ≥ 4.5
  - accent.muted：contrast(c, bg.canvas) ≥ 3.0
  （contrast 为 WCAG 相对亮度比，对 8-bit 量化值计算）
步骤：
1. P(L0) 成立 → 返回 L0（ΔL = 0）
2. 粗扫：L 从 0 到 1、步长 0.005 求值 P，取距 L0 最近的成立点 Lc；
   全部不成立 → 拒绝种子，错误报告字段路径（如 "dark.accent"）与实测最优对比度
3. 精化：在 Lc 与其最近的不成立邻点之间二分，至 |ΔL| 容差 1e-4，返回解
边界：L 限制在 [0,1]；gamut 映射在每步求值内生效（降 C 不视为救济手段，救济只动 L）
报告：|ΔL| > 0.05 触发构建警告，主题作者需人工复核；所有救济写入构建日志
```

### 图表与热力图

- `chart.series[1]` = accent.solid；`[2]` = accentSecondary 或中性灰（L=0.60）；`[3]` = accent L+0.15、C×0.7；`[4]` = 中性灰 L=0.45；`[5]` = accent L−0.15
- `chart.grid`（网格线/轴）= fg.faint alpha 0.08
- `heat[0]` = bg.raised（空格，中性色）
- `heat[1..4]`：accent 同 H，明度与彩度分档（依据：二轮审查 §2 M1.5-6，补全 light 算法）：

| 档 | L（dark） | L（light，反向强度） | C（两模式相同） |
|---|---|---|---|
| heat[1] | 0.35 | 0.86 | accent.C × 1/2 |
| heat[2] | 0.493 | 0.72 | accent.C × 2/3 |
| heat[3] | 0.637 | 0.58 | accent.C × 5/6 |
| heat[4] | 0.78 | 0.44 | accent.C × 1 |

  light 用反向强度：light 背景亮，越深代表量越大，故强档 L 更低。
- **heat ramp 彩度统一缩放（gamut-aware，两模式共用）**：对每档 i 计算 gamut 映射下的最大合法彩度 `Cmax_i`（保持该档 L/H，按 gamut 映射规则二分），取 `s = min(1, min_i Cmax_i / C_i)`（仅对 C_i > 0 的档），整条 ramp 的 C 统一乘 s——不逐点 clamp（逐点 clamp 会削平高档位、破坏 ramp 单调性与均匀感）。mono 等 C=0 的种子跳过缩放，ramp 为纯灰明度档。
- **8-bit roundtrip 可区分性检查**（依据：二轮审查 §2 M1.5-6 新增）：每档经 gamut 映射 → sRGB 8-bit hex → 再解析回 OKLCH；要求相邻档 hex 互不相同，且 roundtrip 后相邻档的 OKLab 欧氏距离 ≥ 0.02。任一不满足即构建失败并报出档位。（官方 10 变体实测最小距离 ≈ 0.139，裕量充足。）

### 状态色（全主题统一色相，保证语义稳定）

success H=145 · warning H=85 · error H=25；dark 下 L=0.70，light 下 L=0.55；C=0.13。只作小面积指示（圆点、图标、细条），正文一律用 fg 系列。

### light 变体配对规则

canvas/raised/overlay 见背景阶梯表；前景见前景阶梯表；accent 与 heat 走各自既定规则与救济算法（不再单独"L 下压至 4.5:1"——依据：二轮审查 §2 M1.5-7，accent 为非文本元素，统一 3:1 + onAccent 4.5:1）。种子在 ThemeFamily 中可为 light 变体单独给值（主题.md 中标注）。

### bgImage 可读性处理（硬规则，不可覆盖）

依据：二轮审查 §2 M1.5-8——承认"单一合成底色无法证明任意图片逐像素达标"，原"系统校验合成底色对比并自动提高 scrim 至达标"的构建期承诺不成立，改为以下三层：

1. **来源限制**：`overrides.bgImage.url` 仅允许本地文件路径（绝对路径或 `file://`）或 `data:` URL；`http(s)://` 一律拒绝并报告字段（离线可用、内容不可外部变更，采样校验才有意义）。
2. **固定最低 scrim**：dark alpha ≥ 0.82 / light alpha ≥ 0.88（构建期固定下限，不再"自动调至达标"）；图片本身透明度上限 0.35、`background-size: cover`。
3. **运行时动态采样校验**：渲染端加载图片后对合成背景降采样取位图，计算 `fg.primary` 对采样点集的最差对比度；< 4.5:1 时运行时以 0.02 步长上调 scrim alpha（上限 1.0）直至达标；到 1.0 仍不达标则 scrim=1.0（等同无图）并记录警告。采样逻辑属运行时职责，不进构建门禁。

## 质量门（派生后自动校验，对 8-bit 量化值计算）

| 对比对 / 检查项 | 要求 |
|---|---|
| fg.primary on bg.canvas | ≥ 7:1（正文 AAA） |
| fg.secondary on bg.canvas | ≥ 4.5:1 |
| fg.muted on bg.raised | ≥ 4.5:1 |
| accent.solid on bg.canvas（图表/焦点环等非文本） | ≥ 3:1，不达标走救济算法（不静默放行） |
| accent.onAccent on accent.solid | ≥ 4.5:1，不达标走救济算法 |
| accent.muted on bg.canvas | ≥ 3:1 |
| heat ramp C 单调性 | 统一缩放后各档 C 单调不减（逐点 clamp 削平即失败） |
| heat[i] 相邻档可区分性 | 8-bit roundtrip 后相邻 hex 不同且 OKLab 距离 ≥ 0.02 |
| gamut 合法性 | 全部派生色过 gamut 映射，linear-sRGB 通道 ∈ [0,1]（容差 1e-6） |

救济算法无法达标（L 搜遍 [0,1] 无解）→ 拒绝种子，错误指到具体字段；|ΔL| > 0.05 → 构建警告，需人工复核。

### ANSI 降级规则

依据：二轮审查 §2 M1.5-9——距离改 OKLab 欧氏距离、同距取最低 index、ANSI16 固定语义映射。

- **距离定义**：候选色（xterm 调色板 sRGB）与令牌色都转 OKLab，取欧氏距离最小者；**同距取最低 index**（消除实现自由度）。
- **ANSI256**：在 xterm 256 调色板（index 0–255，固定定义）内按上述距离选择。
- **ANSI16**：先按固定语义映射表定性，再对无定性的令牌在 16 色内按距离选择。16 色语义表（参考 sRGB 为选择算法的固定输入，终端实际渲染值不在控制内）：

| index | 名称 | 参考 sRGB | 固定语义 |
|---|---|---|---|
| 0 | black | `#000000` | bg.canvas / bg.raised / heat[0] |
| 1 | red | `#800000` | status.error（固定，不参与最近匹配） |
| 2 | green | `#008000` | status.success（固定） |
| 3 | yellow | `#808000` | status.warning（固定） |
| 4 | blue | `#000080` | — |
| 5 | magenta | `#800080` | — |
| 6 | cyan | `#008080` | — |
| 7 | white | `#C0C0C0` | fg.secondary |
| 8 | brightBlack | `#808080` | fg.muted / fg.faint / border.hairline |
| 9 | brightRed | `#FF0000` | — |
| 10 | brightGreen | `#00FF00` | — |
| 11 | brightYellow | `#FFFF00` | — |
| 12 | brightBlue | `#0000FF` | — |
| 13 | brightMagenta | `#FF00FF` | — |
| 14 | brightCyan | `#00FFFF` | — |
| 15 | brightWhite | `#FFFFFF` | fg.primary |

  accent.solid、chart.series、heat[1..4] 无语义定色，在 16 色参考值内按 OKLab 距离最近选择（同距取最低 index）。

  > 已知损失：16 色域内高明度低彩度的 accent（如 amber `#E0985A`）最近匹配会落到 gray/white，色相信息丢失——这是 16 色域的固有限制，语义色（status.*）因固定映射不受影响。
