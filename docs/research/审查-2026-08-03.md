**方法**：通读内部仓全部 22 份文档 + 公开仓治理文档（AGENTS / README / 开发流程 / git-规范 / 代码风格 / 设计原则）第一手核对；逐份比对内部↔内部、内部↔公开、文档↔实现的一致性；对 DDL 做可执行性推演（`foreign_keys=ON` 下的 compact 与重建路径）；对技术栈逐项做必要性与备选检验。

## 一、总判决

**技术栈的大方向没有错**，Rust 内核那条决策链的论证质量高于多数商业项目，本轮未推翻任何内核方向决策。问题集中在三类：

1. **换栈时的清扫不彻底**——uPlot、Motion、culori、changesets、`fsnotify` 五处旧栈残骸仍在文档里，其中 uPlot 写在公开仓的施工依据文档中，贡献者照它施工会直接用错库；
2. **几处契约在时间轴上互相冲突**——「observation 永久保留」与「raw 90 天清理」在 DDL 层就跑不通，实现者只能靠猜；
3. **有整块子系统从未被发现不存在**——配置面、配额油表的视觉规格、用户主题的运行期派生、代码签名与分发信任链。

共记 82 项，全部处置见 §二。

## 三、被必要性检验筛掉的过度设计

记录下来，是因为"没做什么"和"做了什么"同样是决策：

| 曾计划 | 弃选理由 |
|---|---|
| daemon 租约表 + 心跳 + CAS 抢占 | OS 咨询文件锁在进程崩溃时由内核自动释放，无需超时判据、时钟处理与心跳写入。正确性更高、代码更少 |
| token 一次性交换码 + `/auth/exchange` 端点 | 在「本机同用户进程 + 恶意网页」威胁模型下，它防不住任何 URL fragment 防不住的东西（能读地址栏的扩展同样能读 sessionStorage），代价却是新端点、服务端状态与过期逻辑 |
| 价格列改 `unit_price_nano_usd` | micro 域配 `per_unit=1e6` 已能精确表达现实价目下限；**问题在计算过程不在存储精度** |
| Rust 侧引 ICU4X 与 `Intl` 同源 | 为两个 locale、五项格式引入带数据包的依赖，直接顶到"CLI 启动 < 100ms"与轻量分发上。共享测试向量能以极小代价保证一致性；社区新增语言时再评估 |
| 日志轮转、更新器实现等细节写进 ADR | ADR 记录不可逆决策，实现细节留给里程碑 |

## 五、本轮无法核对的部分

公开仓工作树不在磁盘上，以下未能第一手复核，列为公开仓恢复后的第一批动作：

- 六份数据源 spec 与核心契约的**编译级冲突**是否已修（二轮审查列出：`codex` vs `codex-cli`、`project` vs `projectKey/projectLabel`、`tokens.cacheWrite` vs 双 cache-write、`costUSD` vs 双成本列、`toolCall` vs 子表）——这是 golden fixtures 的前置条件，已写入路线图 M0；
- `ci.yml` 实际内容与 `docs/开发流程.md` 描述是否一致；
- `CONTRIBUTING.md` / `SECURITY.md` / PR 模板；
- `crates/tokly-core` 的实现细节（本轮对它的判断基于一次二手勘察，仅用于发现文档缺口，未用作结论依据）。
