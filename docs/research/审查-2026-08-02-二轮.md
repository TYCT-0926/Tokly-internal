# 二轮深度审查报告（2026-08-02，第二轮独立复审）

总判决：**不能按当前文档启动 M1 核心实现**。问题不是措辞不够精细，而是收敛契约、Codex token 公式、成本所有权和物理 schema 仍可能把错误永久写进仓库。当前最多可做 monorepo/CI 等可逆脚手架，不应冻结数据库或实现正式 adapter。

## 1. 修订验证结论

| 关键修订 | 判决 | 核心证据 |
|---|---|---|
| ADR-0002 revision upsert | 有 P0 漏洞 | `>=` 在同 revision、不同 payload 时依到达顺序决定；byte offset/rowid/拉取时刻都不是跨流或跨代版本 |
| token 两条不变量 | 原则成立，六源落实失败 | 只有 Claude 明确满足；Gemini 条件满足；Codex/OpenCode/Copilot/Cursor 未闭合 |
| ADR-0008 与路线图时序 | 顺序成立，语义有漏洞 | M1→M2→M3 自洽，但本机日志不能推出 Claude 官方 usedPct |
| 成本双列 + reprice | 方向成立，但引入新矛盾 | 单一 costBasis 不能标注两列；reprice 会漏 native/estimated 行；"最新价"与事件时点价格冲突 |
| 修订交叉一致性 | 失败 | 风险登记宣称三个丢数点"已修"实际仍有反例；设计、source 类型和路线图多处硬冲突 |

### ADR-0002：收敛契约不成立

1. **不满足交换性**：同 revision 不同 payload 时 A→B 得 B、B→A 得 A，直接反驳"任意重放顺序收敛"。
2. **revision 只局部可比**：fork 文件间 byte offset 无法比较；Cursor VACUUM 后旧代高 rowid 永久压住新代；API 拉取时刻只是观测时刻；同 time_updated 无 tie-break。
3. **"源终态完整扫描"与永久仓库冲突**：源删除后终态不再包含事件，但文档要求永久保留。必须定义"固定 observation 集合上的 fold"，区分缺席/显式删除/排除/tombstone。
4. **派生状态不原子**：事件跨 session 移动须同时 dirty 两端；子表须集合替换；事件、子表、dirty sessions、水位线必须同一事务或持久 dirty queue。

**建议答案**：引入 sourceInstance + originStream + streamGeneration + sourcePosition + payloadHash + normalizerVersion。只有同 origin/generation 的 position 可直接排序；同坐标不同 hash 进冲突表，禁止静默 last-write-wins；跨文件同键 payload 相同则去重，不同则保留 observation 并显式冲突。

### 六源 token 不变量矩阵

| 源 | 判决 | 问题与建议 |
|---|---|---|
| Claude Code | 口径成立；映射未施工化 | 仍写旧 tokens.cacheWrite，未落 5m/1h；aggregate 与明细不相等时无裁决。建议：明细存在且和 aggregate 一致才拆档，否则 fail-visible；无明细全放 5m |
| Codex | **失败，12 倍风险点未真正修完** | 只减 cache read 却另存 cache write。上游测试证明两种 cache 均属 input details（input=100/read=40/write=60/output=10，净 input=0，现公式得 60）。应顺序 clamp 后同时减 read/write |
| OpenCode | **当前版映射明确错误；历史版仍需判别** | v1.18.11 上游固定存 `input = raw input - cacheRead - cacheWrite`、`output = raw output - reasoning`，故当前版必须映射 `output + reasoning`；旧库语义混合，需按 rawSchema/version resolver，无法唯一判别时记录 raw/hash、exclude 并报警 |
| Gemini | 条件成立，异常路径未定义 | total 缺失、无法匹配、双通道冲突无失败策略；$set.messages 全量检查点被跳过 |
| Copilot | 失败 | 只减 cache read，未证明 cache write 与 input 互斥；output/reasoning 包含关系未定义。须按 OTEL/session-state 格式版本分别固定语义 |
| Cursor | 类型与语义均失败 | token 列要求 number 却写 null；共用 text+thinking+toolResults 字符池，可能同内容双算输入输出。建议按 role 分离；不可得维度写 0 但另加 coverage/quality，不能用 0 冒充"已确认没有" |

另有编译级冲突：核心枚举 codex/copilot vs spec 发出 codex-cli/copilot-api/copilot-metrics；多数 spec 仍用 project、tokens.cacheWrite、costUSD、toolCall，核心已改 projectKey/projectLabel、双 cache-write、双成本列和子表。

### ADR-0008：时序成立，产品承诺不成立

Claude 本地日志只能算"本机过去 5 小时 token activity/burn rate"，看不到其他设备、Claude.ai 活动、动态容量、服务端策略。建议：usedPct 允许 null；M2 展示 observedUsage + unit + burnRate；官方端点或用户显式配置容量时才生成百分比，落 provenance('official|local-estimate|user-configured')、ruleVersion、capacity、confidence。

### 成本双列：新矛盾

- 单一 costBasis 无法同时标注两列
- reprice WHERE costBasis='computed' 跳过 native 行→永远无法形成 native/computed 差异；也漏 estimated 行
- adapter 重扫全列 upsert 会把 reprice 后的 computed 值覆盖回旧值
- "用最新价重算"与"按事件发生时有效价格"直接冲突
- OpenCode 的 native 是工具按 models.dev 自算，不是 provider 账单，UI 写"原生"过度背书

**建议答案**：拆成 tokenQuality、nativeCostKind/provider、computedCostStatus、pricingEligibility、displayPolicy。adapter 只拥有 token/native 列；pricing worker 独占 computed 列。reprice 按 pricing eligibility 选择事件，用 event.timestamp 匹配带 effectiveFrom/effectiveTo 的价格规则。

## 2. 阻塞项清单（可施工性）

### M1 核心

| 需要猜的点 | 建议答案 |
|---|---|
| 全局事件身份 | 唯一键改 (sourceInstanceId, eventKey)；source instance 映射账号、机器、源数据根 |
| revision/tie-break | generation+position；相等坐标只允许相同 payload hash；不同 hash 进 conflict observation |
| 删除语义 | observation 永久保留；current projection 可 tombstone/excluded；API 缺席 ≠ 物理删除 |
| 事务边界 | 事件 upsert、旧子表删除、新子表插入、旧/新 session dirty、水位线推进同事务 |
| Claude 扫描范围 | 明写 projects/*/*.jsonl 与 projects/*/*/subagents/*.jsonl |
| Claude eventId fallback | message.id+requestId 为主；缺字段用 uuid 并标 identity quality，无法稳定则入错误/冲突表 |
| Claude"最后一行" | 同一 stream 内最后 offset；跨 stream 不比较 offset；**禁止取 max（实测存在 618→0 回落）** |
| cache_creation 冲突 | 5m+1h 等于 aggregate 才接受；不等时结构化错误并 exclude |
| 坏行与残尾 | 完整非法行记录 hash/长度/位置后推进；无换行残尾不推进；ingest_errors 不存内容摘要 |
| report 汇总 | 只聚合 status=counted；本地时区日界；双列分别展示 |

### 水位线三类源

- **JSONL**：PK=(sourceInstance, channel, streamKey, kind)；另存 cursorVersion/generation/offset/fileId/headerHash；身份断裂 generation++
- **SQLite 活库**：单轮只读事务一致快照；跨轮 safety horizon + 周期全量 reconciliation；Cursor 用 SQLite backup API 建副本 + DB generation
- **API/分页**：整周期写 staging，全部页成功后单事务 reconcile；任何页失败不发布；近期周期滚动重拉

### 三个"已修"丢数点实际判决（风险登记状态错误）

- Cursor VACUUM：**未修**。UNIQUE ON CONFLICT REPLACE 使锚点 key 移到新 rowid 造成误报；全扫后低 rowid 被旧 revision 拒绝
- OpenCode 中断定稿：**未修**。过滤未定稿行后仍推进水位线。必须 pending_messages：每轮先按 ID 重读，完成/error/15 分钟陈旧后计入
- 2 秒回退：仅缓解。须区分"跨轮 checkpoint 回退"与"轮内严格向前分页"；无漏还需固定快照+尾部安全区+周期 reconciliation

### Schema 不能展开为无歧义 DDL（M1 前必须冻结）

- 时间统一 INTEGER epoch_ms；token 非负 INTEGER；金额 **INTEGER micro-USD**（避免 REAL 聚合漂移）
- source_instances、schema migration/version 表
- usage_events PK/UNIQUE/CHECK、normalizerVersion、generation/position/hash
- sessions 完整 PK、空会话删除规则、session_model_stats 独立表
- 子表复合 FK、(event,childId) PK、集合替换规则
- watermark 稳定 PK/cursorVersion/generation/事务语义
- quota 唯一键/provenance/ruleVersion/capacity/unit
- 带生效期的 pricing history 表
- 索引：(status,timestamp)、source/session/project/model+timestamp、quota limit+observedAt
- ingest_errors 仅存错误码、位置、payload hash/长度、计数

## 3. 独立刷新结果

### 证实
- Bun 1.3.14 无 node:sqlite（本机复现）；OpenCode 生产确为 @opentui/solid（1.18.11 无 @opentui/react）；codeburn 9,095 stars/36 integrations
- Gemini CLI v0.53.1 读取 `$set.messages` 时会清空并重建消息 map，且 checkpoint 可携带 tokens；当前 spec 的“跳过用量”会漏恢复后的唯一快照

### 推翻上一轮
1. **"Codex 差分逻辑全部正确"错误**：上游测试证明 cache read/write 都是 input details，现公式双计 cache write
2. **"Claude 同键 usage 随流式递增"过强且错误**：本机重扫（2,384 文件/141,830 usage 行/56,892 逻辑键/44,727 重复组/25,639 组 payload 不同），output 组内 max−min 合计 36,565,353，**至少一处同文件 output 从 618 回落到 0**——不能取 max；同 stream 取最后源记录，跨 stream 必须冲突处理
3. **"Anthropic 资助 codeburn"证据不足**：README 仅 "Codex and Claude for Open Source Recipient" badge，应为"开源计划 recipient"
4. **Bun 旧证据链失效**：oven-sh/bun#27092 已 404；正确表述"文档/主干已前进，Bun 1.3.14 尚未兑现"
5. **OpenTUI Windows 风险过于确定**：issue #152 已关闭称多数改善但仍有闪烁/低帧未完成项；应改为"必须在当前 Windows/Bun 组合实测"

### 新增
- Codex main 的物理 rollout 仍是单 `.jsonl` append；变化是行级 `ordinal`、SQLite 元数据投影与 `.jsonl.zst` 冷存储。`codex-cli.md:104,117` 的风险登记已落后，但不能改写成“分页已落地”
- OpenCode v1.18.11 已固定 input/output 的净值语义，但 `data.cost` 同时容纳 models.dev 自算与 Copilot `totalNanoAiu` billed cost；当前 spec 把两者统一称 native/models.dev 已失真
- 生态版本快照：Codex 0.146.0、Claude Code 2.1.220、OpenCode 1.18.11、Gemini CLI 0.53.1、Copilot CLI 1.0.77、OpenTUI 0.4.5、Tauri 2.11.5

## 4. M1 开工前必须先补（最多三件）

1. **重写收敛契约**：source instance、generation、可比版本域、payload conflict、tombstone、子表替换、事务边界，以交换/乱序/重放/重建 property tests 验收
2. **发布可执行 schema**：完整 DDL、迁移、索引、FK/CHECK、watermark cursor schema、quota provenance、pricing history、dirty-session 算法
3. **冻结统一映射与成本所有权**：修 Codex cache-write；六源逐字段 golden fixtures；拆 token 质量、native/computed 成本溯源、按事件时点生效的 pricing 规则
