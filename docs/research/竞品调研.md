## 被验证的实践（Tokly 采用）

1. **成本 = token × LiteLLM 定价表**（`model_prices_and_context_window.json`），本地缓存 + 用户覆盖 + 模糊匹配模型名。全行业事实标准。
2. **去重用 message-id + request-id 复合键**，分支会话与子代理（sidechain）必须显式处理——ccusage 为此修过两轮。
3. **warehouse 自有仓库**：导入一次永久保留，与源日志生命周期解耦。
4. **溯源标注**：官方数据与本地估算必须可区分，这是竞品 issue 区被投诉最多的点。
5. **轻量是硬指标**：CCSeva 弃 Electron、tokscale 用 Rust 核心，都是对用户抱怨的直接回应。Tauri 2.5–10MB 安装包有多个真实迁移案例佐证（Electron 85–244MB）。

## 没人占住的位置（Tokly 的落点）

- 本地统一仓库 + 三端一致体验 + **跨平台**（CodexBar 官方把 Windows 甩给社区 fork）
- 全源覆盖 + 溯源标注的信任模型（Claude-Code-Usage-Monitor 做了单源，没人泛化）
- 会话/工具调用级分析（不只是 token 和钱）

**威胁重估（2026-08-02 审查）**：codeburn 已占住"多源 + 多形态"的大半（CLI/TUI/Web/菜单栏/多设备，36 源，4 个月 9.1k stars，Anthropic 开源计划 recipient——README badge，非"资助"，二轮审查 §3 证伪），本文成文时的格局判断部分过时。Tokly 剩余差异化收窄为：**持久化仓库层（永久事件级历史）+ 跨工具配额窗口聚合（[ADR-0008](../adr/0008-配额窗口.md)）+ 跨平台质量**。竞品的仓库层随时可能补上，窗口期按月计——这是路线图把核心数据层压到 M1 的外部理由。

## 数据源获取结论（详见 docs/sources/）

| 源 | 通道 | 历史 | 原生成本 |
|---|---|---|---|
| OpenCode | 只读 SQLite | 全量 | ✅ |
| Claude Code | JSONL 解析 | 本地已有部分 | 计算（OTEL 有原生，但需用户自开） |
| Codex | rollout JSONL 差分 | 2025-09 起 | 计算 |
| Gemini | chats 文件 | 易失（tmp） | 计算 |
| Copilot CLI | 本地 OTEL JSONL | 有 | 计算 |
| Copilot IDE | 官方 API（需授权） | ≤1 年 | premium-request 口径 |
| Cursor | state.vscdb 只读 | 部分 | 估算（v3 行 token 为 0） |

**边界**：OTEL 推送与本地代理都要求修改用户配置，违反只读铁律，已放弃（仅被动利用用户自行开启的 OTEL）。Cursor / Copilot IDE 无完整本地数据，接受估算或 API 粒度，明确标注。
