# 代码风格

目标：读起来像一位有十年经验的工程师精心写的——有判断、有克制、有个性但无癖好。这份文档同时是"去 AI 味"的执行标准。

## 结构

- **抽象要有证据**：第三次重复才抽象；一次使用的"通用工具函数"是负债不是资产
- **命名说人话**：领域词汇（`watermark`、`session`、`reprice`），不用 `Util`/`Helper`/`Manager`/`Data` 凑数；布尔用 `is/has/can`；函数名即动词短语
- **函数短**：一屏内读完；超过就在找它的职责边界在哪
- **目录即架构**：看目录树能猜到功能在哪；新建目录需要理由（对应一个包/一个端的边界）

## 代码质地

- 注释稀缺而珍贵：只写"为什么"，且读者看代码推不出来时。`// 递增 i` 级别的注释等于噪音
- 错误处理诚实：能处理的才 catch；不吞错误（空 catch 块永远禁止）；错误信息带上下文（哪个文件、哪个 session）
- 边界处防御，内部信任：解析外部数据（adapter 边界）严格校验+fail-visible；内部函数信任类型系统，不写"防御不可能情况"的代码
- Rust 用 enum/newtype 表达领域状态，让非法状态不可表示；TypeScript 不用 `any`（边界处必须用则附注释）
- 不用魔法数（命名常量）；不用字符串魔法值（Rust 用 enum，TypeScript 用联合类型）
- 早返回优于嵌套；组合优于继承；显式优于隐式（不写"聪明的"代码）

## 依赖

- 每加一个依赖要回答：自己写要多少行？<50 行就不引（左填充教训）
- 依赖必须活跃维护；`Cargo.lock` 与 `pnpm-lock.yaml` 入库；Rust 与 Web 依赖分别审计

## 测试

- 测试名即行为陈述：Rust 用 `skips_synthetic_model_rows`，TypeScript 用 `` `skips synthetic model rows` ``，不用 `test1`/`works correctly`
- 一个测试验一件事；fixtures 最小化（能 3 行样本不用 30 行）
- 不测实现细节，测可观察行为；snapshot 测试的快照必须人工 review 过内容

## 文本与语气

- 代码内一切（标识符、注释、commit、PR）英文；文档中文
- UI 文案：短、具体、无营销腔、无 emoji（见设计原则禁止清单）
- 错误消息三段式：发生了什么 → 为什么 → 用户能做什么。例：`Cannot read opencode.db: file is locked by a running OpenCode instance. Close it or use --offline mode.`

## "不像 AI 写的"检查单

- [ ] 没有过度防御（给不可能的输入写处理）
- [ ] 没有均匀分布的抽象（真实代码的抽象层级是不均匀的——该直写的地方直写）
- [ ] 没有复述代码的注释
- [ ] 没有"为了将来"预留的参数、配置项、抽象层
- [ ] diff 里每一行都能追溯到需求
- [ ] 常量有名字且有出处（注释给来源，如阈值来自哪份文档/issue）
