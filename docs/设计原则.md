# Tokly 设计系统

目标：**仪器感**。像一块精密仪表，不像一个 SaaS 营销页。克制的色彩、精确的数字、即时的响应。

## 原则

1. **数字是主角** — 全局 `font-variant-numeric: tabular-nums`。token 数、成本、模型 ID、时间戳用等宽字体（"仪表读数"声部）；其余用主字体。
2. **色彩即语义** — 一个品牌强调色 + 语义色（成功/警告/错误），其余全中性灰。成本数字用中性色——花费上升不等于红色告警。
3. **交互密度 > 视觉密度** — 视觉留白，但每个元素都有完整的 hover/focus/active/disabled/loading 状态与键盘可达性。本地数据是优势：交互必须即时，不为本地查询放转圈。
4. **渐进披露** — 概览回答常见问题，明细一次点击可达，悬停承载次要指标。

## 字体

- 主字体：**Geist Sans**（备选 Inter），全端唯一，4–6 个字号：12 / 13 / 14 / 16 / 20 / 24
- **中文回退链显式写死**（Geist 无中文字形，禁止交给系统随机发挥）：`"Geist Sans", "PingFang SC", "Microsoft YaHei UI", "Noto Sans CJK SC", sans-serif`。中西文混排以标签为限，数据区永远走西文/数字
- 等宽：**Maple Mono**（中西文等宽对齐 + 连字；备选 Geist Mono），用于一切数据读数：token 数、成本、模型 ID、时间戳
- 正文 14px；KPI 大数字 24–32px，收紧字距，tabular figures

## 主题系统

多主题与用户自定义的架构：三层令牌（原语 → 语义 → 组件），色彩 ramp 用 OKLCH 插值程序化派生；自定义只开放 Tier 1 种子，结构性纪律不可触达（内部 ADR-0005）。首发主题：`amber`（签名默认）/ `mono` / `slate` / `paper`，深浅成对。

## 色彩

- 深色优先（开发者工具 + 终端亲缘），同时提供真正的浅色主题，不是反色糊弄
- 背景用带温度的近黑：**签名主题为暖近黑**（`#0E0C0A` 附近），配合琥珀强调色；不用纯 `#000`
- 中性灰阶约 8 级；分隔用 8–12% 透明度的发丝线（0.5–1px），不用卡片套卡片
- 图表调色板：强调色的单色相明度渐变 + 灰色辅助系列。**第二系列用灰，不用第二个色相**
- 热力图（**品牌签名对象，三端同源**）：单色相明度 ramp，空格用中性色（非纯黑），按用户自身峰值相对标定，悬停显示精确值

## 形状与间距

- 4px 基准网格：4 / 8 / 12 / 16 / 24 / 32 / 48，不允许网格外数值
- 圆角：按钮/输入 6px，卡片 8–10px，上限 12px
- 边框优先于阴影；阴影只用于浮层（popover/modal），且轻微

## 动效

- 只动 `transform` 和 `opacity`；时长 100 / 150 / 250ms 三档；退出快于进入
- 禁止 `transition: all`；入场从 `scale(0.95)` + 淡入开始，不从 `scale(0)`
- 列表首次入场 stagger 30–80ms，期间不阻塞交互
- 时间范围切换用交叉淡化，不重挂载
- 加载用与布局等形的骨架屏，不用通用 spinner
- 完整支持 `prefers-reduced-motion`：保留淡入，移除位移

## 数据可视化细则

- 紧凑记数只用于卡片与轴标签：`3.4M tokens`、`$12.80`；完整精度放 tooltip/钻取
- 百分比保留一位小数；负号统一 `−1,234` 格式
- KPI 结构：平白的指标名 → 大号读数 → 环比变化（方向箭头 + %）→ 可选 sparkline
- 环比只在好坏方向无歧义时才上色，否则中性灰
- 时间范围切换器：分段控件（24h / 7d / 30d / 90d / 自定义），记住选择

## TUI 准则

- 单色底 + 每视图**一个**强调色；细线单线边框，标题嵌入上边框
- 层级靠灰阶 + bold/dim 表达，不给正文文字上色
- 无 emoji（宽度不一致毁对齐）；图标用单宽字符 `✓ ✗ ! ○ ▶`
- 数字与时间戳右对齐，其余左对齐
- 唯一动效：braille spinner 与进度条；不做终端转场动画
- 主题：JSON 主题文件 + `system` 自适应（跟随终端配色）；256 色保底，truecolor 优先，优雅降级
- 状态栏是仪表签名位：`Opus · 12.4K tokens · $0.04 · 3.2s`——TUI 的状态栏与 Web 的 KPI 卡必须一眼认出是同一台仪器

## 禁止清单（AI 味）

- 紫蓝渐变（任何位置）、玻璃拟态、发光体、模糊光斑
- 渐变标题文字、bento 卡片阵、超过 12px 的圆角、24px+ 模糊阴影
- 应用内 hero 区与营销文案、eyebrow 小标签 + 大标题的模板组合
- emoji 标题；"unleash / elevate / seamless / next-gen" 式文案
- 未定制的 shadcn 默认皮肤；每个图表都有的渐变面积填充与数字滚动动画

## 个性预算

整个产品只允许**一个**精心设计的签名时刻（如桌面 Widget 的待机动画，或空状态插图），其余全部保持安静。参考 Claude Code 的 thinking verbs——个性集中在一个点，而不是均匀涂抹。

## 信息架构（Dashboard）

每一屏只回答一个问题，层级即用户提问的顺序：

1. **现在花了多少** — KPI 行（今日 token / 本周成本 / 活跃会话），等宽读数 + 环比
2. **节奏什么样** — 趋势图（uPlot）+ 热力图（签名对象）
3. **花在哪了** — 维度下钻：模型 → 项目 → 会话 → 单次事件，hover 承载次要指标，点击逐级深入

时间范围切换（24h / 7d / 30d / 90d / 自定义）作用于整屏，选择持久化。

## 组件视觉验收要点

- **KPI 卡**：平白指标名 → 大号 tabular 读数 → 环比（方向箭头+%，好坏有歧义时中性灰）→ 可选 sparkline。无图标、无渐变、无背景色块
- **热力图**：见「色彩」节签名对象标准；TUI 用 braille 渲染同一数据，桌面 Widget 为迷你版
- **表格**：数字右对齐、文本左对齐、行 hover 底色仅 4-6% 透明度、斑马纹禁用
- **图表**：单色相 + 灰辅助系列；无渐变面积填充；网格线 8% 透明度；轴标签紧凑记数
- **状态**：加载=等形骨架屏；空态=一句具体指引（不写营销文案）；错误=溯源标注 + 重试入口

## 无障碍与耐看（硬规则）

- **色觉冗余**：状态永不只用颜色编码——成功/警告/错误必须"图标 + 色"双通道（约 8% 男性用户红绿不可分）。琥珀主视觉对色觉障碍天然安全，状态色是唯一风险点
- **键盘可达**：全部交互可键盘完成，焦点环可见（`focus.ring` 令牌）
- **屏幕阅读器**（Web）：图表配 aria 摘要，KPI 读数可读，热力图有表格等价物
- **耐看验收**：新主题/新组件进设计验收时过一道主观评审——连续使用 30 分钟无视觉疲劳（低饱和、正文高对比、暗部有温度是已知手段）

## 主题分享（预留机制）

主题是一行 ThemeFamily JSON，天然可分享。预留 `tokly theme install <url|path>`（校验同用户主题），社区主题库不官方运营——让表现力主题自己长出来。

## 设计验收清单（每个 UI PR 必过）

- [ ] 禁止清单逐项核对（渐变/玻璃/emoji/bento/营销文案）
- [ ] 所有数字 tabular-nums，等宽字体只用于数据读数
- [ ] 动效仅 transform/opacity，时长在 100/150/250ms 档位内
- [ ] hover/focus/active/disabled/loading 五态齐全，键盘可达
- [ ] 深浅两主题截图核对；TUI 快照测试同步更新
- [ ] 80 列终端宽度下 TUI 布局不崩
