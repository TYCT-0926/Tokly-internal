# Tokly 开发流程

适用于核心团队与外部贡献者。开源治理见 [ADR-0006](adr/0006-开源发布.md)。Git 操作与历史卫生见 [git-规范](git-规范.md)，代码质地见 [代码风格](代码风格.md)。

## 节奏

**Spec 先行。** 任何 adapter、任何数据模型变更、任何新端，先在 `docs/` 写清楚再写代码。Adapter 的 spec 就是 `docs/sources/<name>.md`：格式文档不完整，不许开工。

**ADR 记录不可逆决策。** 技术栈、数据模型、分发策略这类改起来代价大的决策，写 `docs/adr/NNNN-<标题>.md`，状态为 `proposed | accepted | superseded`。被取代的 ADR 不删，标记 `superseded by NNNN`。

## 分支与提交

- `main` 永远可发布；外部贡献走 fork + PR，内部走 `feat/<scope>` / `fix/<scope>` 短分支，squash merge 合入。
- Conventional Commits：`feat(core): ...` / `fix(adapter-claude): ...` / `docs(adr): ...` / `chore(ci): ...`。
- 提交信息写"为什么"，不写"改了什么"（diff 自己会说）。
- 一个 PR 只做一件事。重构与功能不混提。
- 每个 PR 带 changeset（`pnpm changeset`），声明版本影响面。

## 测试策略

| 层 | 对象 | 方式 |
|---|---|---|
| golden fixtures | 六个 adapter | 真实脱敏样本 → **逐字段映射快照**（含 Codex legacy/paginated 双格式、OpenCode 两代 schema、Claude cache_creation 裁决、Copilot 格式版本表）。**解析器是本项目最易腐坏的部分**，样本随源工具版本演进持续补充；映射变更必须同步更新 fixtures。M0.5 冻结门交付物 |
| 收敛性 property tests | 摄取引擎 | 同一固定 observation 集合，**交换 / 乱序 / 重放 / 重建**四场景终态逐字节一致（ADR-0002 收敛契约，二轮审查 §4）；含三个静默丢数点的回归用例（风险登记 R4） |
| 单元测试 | core 逻辑（定价、去重、聚合、水位线、令牌派生） | Vitest |
| 集成测试 | 摄取引擎端到端 | 临时目录构造假数据源，验证增量与幂等 |
| TUI 快照 | TUI 视图 | OpenTUI test renderer 文本帧快照 |
| E2E | Web 关键路径 | Playwright，少量，只保主干 |

幂等性是摄取引擎的第一测试公民，定义为**收敛性**（ADR-0002，2026-08-02 二轮审查修订）：不再以「同一数据导入两次」为满足，而是 property tests 四场景——任意两批观测**交换**入库顺序、任意**乱序**重排、同一批**重放** N 次、清空投影/子表/派生表后从 observation 层 fold **重建**，终态都必须与增量摄取终态完全一致。另设**跨 adapter 口径一致性测试**：同一组语义事件经不同 adapter 映射后必须满足 token 口径不变量（input 净值四者互斥——cache read 与 cache write 同时减、output 恒含 reasoning），违规即红。

## CI

`.github/workflows/ci.yml`：三平台矩阵（ubuntu / windows / macos）跑 `typecheck → lint → test → build`；i18n job 校验 zh-CN 与 en 语言包 key 对齐。每个 PR 必须全绿才可合入。

## 发布

changesets 聚合版本与 CHANGELOG → release PR → tag → CI 构建三平台产物 → npm publish（`@tokly/*`）+ GitHub Release（桌面安装包 / 单文件 CLI）。细节见 ADR-0006。

## Definition of Done

- 测试通过，含新增逻辑的新测试
- 类型 `strict` 零警告，无 `any`（除非有注释说明的边界）
- 涉及数据源格式的变更同步更新 `docs/sources/`
- 涉及架构决策的变更同步更新或新增 ADR
- 涉及界面文案的变更同步 zh-CN 与 en（ADR-0007）
- UI 变更对照 `docs/设计原则.md` 验收清单自查

## 代码准则（去 AI 味）

- 最小改动达成目标；不要顺手重构无关代码
- 不写解释废话的注释；注释只写"为什么"，且确实非显而易见时才写
- 不留死代码、TODO 占位、半成品的"未来扩展"
- 与周围代码风格保持一致，不引入个人偏好风格
- 标识符与代码注释用英文；文档用中文；界面文案走语言包（ADR-0007）
