# Tokly 开发流程

适用于核心团队与外部贡献者。Git 操作与历史卫生见 [git-规范](git-规范.md)，代码质地见 [代码风格](代码风格.md)。

## 节奏

**Spec 先行。** 任何 adapter、任何数据模型变更、任何新端，先在 `docs/` 写清楚再写代码。Adapter 的 spec 就是 `docs/sources/<name>.md`：格式文档不完整，不许开工。

**ADR 记录不可逆决策。** 技术栈、数据模型、分发策略这类改起来代价大的决策，以 ADR 形式记录（`proposed | accepted | superseded` 三态，被取代的不删，标记 `superseded by NNNN`）。ADR 目前维护在内部仓库，本仓库引用时以「内部 ADR-NNNN」文字提及。

## 分支与提交

- `main` 永远可发布；外部贡献走 fork + PR，内部走 `feat/<scope>` / `fix/<scope>` 短分支，squash merge 合入。
- Conventional Commits：`feat(core): ...` / `fix(adapter-claude): ...` / `docs(adr): ...` / `chore(ci): ...`。
- 提交信息写"为什么"，不写"改了什么"（diff 自己会说）。
- 一个 PR 只做一件事。重构与功能不混提。
- 有用户可见行为变化时，在 PR 描述中声明版本影响；版本号与 CHANGELOG 由 release PR 统一维护。

## 测试策略

| 层 | 对象 | 方式 |
|---|---|---|
| golden fixtures | 六个 adapter | 人工构造的脱敏样本 → insta **逐字段映射快照**（含 Codex legacy/paginated 双格式、OpenCode 两代 schema、Claude cache_creation 裁决、Copilot 格式版本表）。**解析器是本项目最易腐坏的部分**，样本随源工具版本演进持续补充；映射变更必须人工审查快照并同步更新 fixtures。M0.5 冻结门交付物 |
| 收敛性 property tests | Rust 摄取引擎 | proptest 对同一固定 observation 集合验证**交换 / 乱序 / 重放 / 重建**四场景终态一致（内部 ADR-0002 收敛契约）；含三个静默丢数点的回归用例 |
| 单元测试 | Rust core 逻辑（定价、去重、聚合、水位线、令牌派生） | Rust test harness，由 cargo-nextest 执行 |
| 集成测试 | 摄取引擎端到端 | 临时目录构造假数据源，由 cargo-nextest 验证增量与幂等 |
| 性能基准 | 增量扫描 / 首次全量 / report 查询 | criterion；结果按里程碑 SLO 审查，不用单次共享 runner 耗时作硬门禁 |
| TUI 快照 | Ratatui 视图 | TestBackend + insta 文本帧快照 |
| Web 单元与无障碍 | React 界面 | Vitest + React Testing Library + axe |
| E2E | Web 关键路径 | Playwright，少量，只保主干 |

幂等性是摄取引擎的第一测试公民，定义为**收敛性**（内部 ADR-0002）：不再以「同一数据导入两次」为满足，而是 property tests 四场景——任意两批观测**交换**入库顺序、任意**乱序**重排、同一批**重放** N 次、清空投影/子表/派生表后从 observation 层 fold **重建**，终态都必须与增量摄取终态完全一致。另设**跨 adapter 口径一致性测试**：同一组语义事件经不同 adapter 映射后必须满足 token 口径不变量（input 净值四者互斥——cache read 与 cache write 同时减、output 恒含 reasoning），违规即红。

## CI

`.github/workflows/ci.yml`：Rust 三平台矩阵（Ubuntu / Windows / macOS，版本由 `rust-toolchain.toml` 固定）跑 `cargo fmt --all -- --check → cargo clippy --locked --workspace --all-targets --all-features -- -D warnings → cargo nextest run --locked --workspace --all-features --no-tests pass --profile ci → cargo build --locked --workspace --all-targets --all-features`。M0.5 仅有基建 crate 时 nextest 允许 0 tests；首个领域 crate 落地后实际测试仍由同一命令执行。Web job 只在 `apps/web/package.json` 存在后启用，并严格执行 `typecheck → lint → test → build`；缺脚本直接失败，不用 `--if-present` 掩盖未执行。i18n job 在语言包与校验脚本落地后启用。每个已启用 job 必须全绿才可合入。

guard job（单平台快速）三道防线：① 树内不得出现 `internal/` 或 `docs/` 路径——`git ls-files -z` 以 NUL 分隔枚举真实路径，Bash `read -r -d ''` 逐项做 ASCII 大小写不敏感前缀匹配，命中即红；必须使用 NUL 分隔，逐行输出即使关闭 quotePath，遇换行、Tab、双引号或反斜杠仍会整行 C 转义并破坏行首锚定。扫描结果先落临时文件再重定向给 `while`，避免管道子 shell 丢失命中数组；② **根级 markdown 白名单**——复用同一 NUL 安全枚举，根目录被跟踪的 `.md` 只允许 `README / SECURITY / CONTRIBUTING` 三个，其余（含新克隆上本地排除未重装时误 add 的工作文件、任何个人笔记）一律红：白名单机制不点名非仓库文件，零痕迹（2026-08-03 阶段一裁决，方案 c）；③ 新提交正文不得含工具署名——PR 事件查 `origin/main..HEAD`，push 事件查 `event.before..HEAD`（分支新建的全零 SHA 改查全史），大小写不敏感匹配 `co-authored-by` 与词边界锚定的 `generated with`，命中即红；基线不可解析一律直接红（fail-closed，checkout 需 `fetch-depth: 0`），合法空范围跳过不误杀。已知有意收严：提交正文里 "generated with" 词组会被拦（如 "diagrams generated with mermaid"），换措辞即可。

cargo-deny job（单平台）跑 `cargo deny check`（taiki-e/install-action 安装）：许可证白名单维护在 `deny.toml`（MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / Unicode-3.0 / Zlib，Zlib 为阶段二依 foldhash 传递依赖按"知名 OSI 许可证逐项说理"规则扩入），advisories 按 cargo-deny 默认拒绝，不做静默降级。

## 发布

release PR 统一更新版本与 CHANGELOG → tag → cargo-dist 构建三平台原生 CLI → Tauri 安装包 + npm 原生二进制启动器 → GitHub Release。

## Definition of Done

- `cargo fmt --all -- --check`、Clippy `-D warnings`、cargo-nextest 与 workspace build 通过，新增逻辑有对应测试
- Rust 领域状态优先由 enum/newtype 约束；Web TypeScript `strict` 零警告且无 `any`（除非有注释说明的边界）
- 涉及数据源格式的变更同步更新 `docs/sources/`
- 涉及架构决策的变更同步内部 ADR
- 涉及界面文案的变更同步 zh-CN 与 en
- UI 变更对照 `docs/设计原则.md` 验收清单自查

## 代码准则（去 AI 味）

- 最小改动达成目标；不要顺手重构无关代码
- 不写解释废话的注释；注释只写"为什么"，且确实非显而易见时才写
- 不留死代码、TODO 占位、半成品的"未来扩展"
- 与周围代码风格保持一致，不引入个人偏好风格
- 标识符与代码注释用英文；文档用中文；界面文案走语言包
