## M0.5 · 冻结门（M1 动工前提；2026-08-02 三轮终审修订）

判决框架不变：**冻结完成前，不得启动 M1 核心实现**——当前最多做 workspace/CI 等可逆脚手架，不冻结数据库、不实现正式 adapter（[审查-2026-08-02-二轮](research/审查-2026-08-02-二轮.md) §4）。终审把验收手段更新为**三个竖切 spike**（新栈的端到端证明，各自带验收）：

- [ ] **① Rust 数据竖切**：Claude fixture → adapter crate → rusqlite 入库 → `tokly report` 出终端表。**验收**：proptest 收敛契约四场景（交换 / 乱序 / 重放 / 重建终态一致）在该竖切上跑通——core 最小骨架由此定格；[ADR-0002](adr/0002-数据架构.md) 收敛契约（事件身份 / 可比 revision 域 / 显式冲突 / 观测-投影两层模型 / 事务边界）经此验收即视为定稿
- [ ] **② React UX 竖切**：React Aria 日期范围 + ECharts 趋势 + CSS Grid 热力图 + 虚拟表格同页。**验收**：键盘全流程 / 读屏（aria 树）/ 主题切换（令牌三产物管线）/ 性能预算（首屏 < 300ms、ECharts 懒加载体积达标）
- [ ] **③ 跨端竖切**：同一 Rust application service 同时接 Ratatui + Axum + Tauri IPC 三种 transport。**验收**：三平台安装体积（~10MB 级目标）/ 冷启动 / 空闲内存实测定格；写锁单 owner 在三端并存时成立

原有冻结两件（不变）：

- [ ] **可执行 DDL 冻结**（[数据库-schema](数据库-schema.md)：全表 + 迁移 + 索引 + FK/CHECK + watermark 游标 schema + quota provenance + pricing history）
- [ ] **六源映射 golden fixtures**（逐字段映射快照；含 Codex legacy/paginated 双格式、OpenCode 两代 schema、Copilot 格式版本表、Claude cache_creation 裁决用例）——实现载体为 insta 快照

三 spike 验收 + 两件冻结 + 评审通过，才准动工 M1。

## M1 · 核心数据层（第一优先级）

目标：一条命令 `tokly scan`，把 Claude Code 的全部历史导入本地仓库；`tokly report` 出终端汇总表——里程碑可 dogfood 才成立。

- [ ] `crates/core`：SQLite schema 全表落地（以 [数据库-schema](数据库-schema.md) 为规范：source_instances / usage_events / conflict_observations / sessions / session_model_stats / tool_calls / event_charges / pending_messages / ingest_errors / watermarks / quota_snapshots / pricing_history；rusqlite + 迁移）
- [ ] 增量摄取引擎：三类源水位线（JSONL / SQLite 活库 / API staging）+ 收敛契约 upsert（事件身份 + 可比 revision 域 + 显式冲突 + 同事务边界，见 ADR-0002）
- [ ] `crates/adapter-claude`：Claude Code adapter（首个 crate，serde 流式解析，数据最丰富）
- [ ] 去重与收敛：`(sourceInstanceId, eventKey)` 主键；message-id + request-id 复合键防分支重复；**同 stream 取最后源记录**，跨流冲突进 `conflict_observations`（禁止取 max，二轮审查 §3）
- [ ] `crates/pricing`：LiteLLM 定价 JSON + 本地缓存 + 用户覆盖 + 模糊匹配；按事件时点匹配 `pricing_history` 生效区间计价
- [ ] `crates/cli` `tokly report`：终端汇总表（今日/本周/总成本与 token；只聚合 `status='counted'`，native/computed 双列分别展示）——第一个可 dogfood 的使用面
- [ ] golden fixtures + 收敛性 property tests：六源真实样本（脱敏）逐字段映射快照（insta）；交换/乱序/重放/重建四场景终态一致（proptest，公开仓 docs/开发流程.md）

## M3 · 数据广度 + 配额完整化

- [ ] Codex adapter（rollout JSONL，legacy+paginated 双格式；`token_count` 累计值差分 + cache read/write 双减净输入公式；`rate_limits` 独立采集 → quota_snapshots）
- [ ] Gemini CLI adapter（chats 文件，含 `$set.messages` 全量检查点；用户已自开 OTEL 时被动利用 + 权威通道裁决）
- [ ] 配额窗口完整化：**范围明确只指 Claude + Codex 两源**（Claude 本地重建规则完善 + Codex 官方 rate_limits 快照；其余源有能力即补，不作承诺——二轮审查 §2）；窗口规则可配置（ADR-0008）
- [ ] `tokly statusline`：嵌入 Claude Code 状态栏的用量行（用户自行配置接入，不违反只读铁律；最强自传播面）
- [ ] `tokly serve --demo`：假数据模式（增长三件套之一，降低围观门槛）
- [ ] 能力矩阵：每个 adapter 声明字段能力，UI 按能力降级渲染

## M4 · TUI

- [ ] Ratatui + Crossterm（与 core 同进程直调 service，无 IPC 层）：实时监控视图 + 历史浏览
- [ ] **Windows Terminal 兼容性冒烟前置**（ConPTY 路径、truecolor → 256 → 16 降级链实测；原 OpenTUI 实测前置条目随 R1 关闭作废）；TestBackend 快照进 CI
- [ ] 主题机制：构建期 TUI 主题产物（ADR-0005）+ system 自适应

## M5 · 桌面端

- [ ] Tauri 2 **直嵌 Rust core**（无 sidecar / Node / 独立进程，见 ADR-0004）：系统托盘实时用量、可钉 Widget、完整窗口（复用 Web 构建产物，经 Tauri IPC/events 取数）
- [ ] 安装体积（~10MB 级）/ 冷启动 / 空闲内存按 M0.5 spike ③ 基线验收；macOS Accessory 激活策略、Linux 默认不透明、webkit2gtk-4.1 / macOS 12+ 下限落地（ADR-0004，风险 R6/R7）
- [ ] 桌面通知：配额窗口将尽、异常消耗 spike（油表的价值一半在"快没油时响一声"；阈值规则可配置）

## M6 · 补盲与洞察

- [ ] Copilot：官方 API（用户授权 PAT，premium-request 粒度，标注口径差异；staging 整周期事务发布）
- [ ] Cursor：state.vscdb 只读解析（backup API 副本 + DB generation），v3 行 token 缺失时按 role 分离字符池估算并标注 `tokenQuality='estimated'`
- [ ] adapter 广度：Cline / Roo / Kilo 家族（一套 globalStorage 解析覆盖约 900 万安装）；Qwen Code（复用 Gemini adapter ~80%）
- [ ] adapter 贡献套件：spec 模板 + golden fixtures 脚手架 + 能力声明 checklist（社区扩源的包装；同时是 Rust adapter 的贡献门槛封顶，见 ADR-0001 代价节）
- [ ] 智能洞察：异常消耗提醒、缓存命中率分析、模型成本对比建议
- [ ] **MCP Server**：本地 MCP 接口，让 AI 工具自查用量（"问 Claude：我这个月花了多少"——完全本地，闭环）
- [ ] **Tokly Wrapped**：年度回顾（年度 token、最爱模型、最烧钱的一天；热力图为视觉主角，可导出分享卡片）

## 明确不做（当前阶段）

- 本地代理拦截（违反只读铁律）
- 替用户开启 OTEL / 修改任何配置
- 云同步、账号体系、排行榜（与本地优先冲突，远期再议）
- 数据库加密（本地单用户工具，威胁模型不成立；见公开仓 SECURITY.md）
- 多设备同步（M6 后评估，aitrack 式 git-repo 同步为候选思路）

## 性能 SLO（验收硬指标）

| 指标 | 目标 |
|---|---|
| CLI 启动 | < 100ms |
| 增量扫描 | < 1s（水位线命中）；首次全量 < 30s（万级文件） |
| daemon 常驻内存 | < 50MB |
| Dashboard 任意聚合查询 | < 100ms |
| Dashboard 首屏 | < 300ms（本地数据） |
| 数据库体积（分层保留后） | 每年重度使用 < 100MB |
