## M0.5 · 冻结门（M1 动工前提）

判决框架不变：**冻结完成前不得启动 M1 核心实现**——当前最多做 workspace / CI 等可逆脚手架，不冻结数据库、不实现正式 adapter。

### 三个竖切 spike

- [ ] **① Rust 数据竖切**：Claude fixture → adapter crate → rusqlite 入库 → `tokly report` 出终端表
  **验收**：proptest 收敛契约四场景（交换 / 乱序 / 重放 / 重建）终态一致，且快照**含全部派生表**（原实现的比对快照漏了 `session_model_stats`）；另测三项实测并定格——STRICT 表开销、`cache_size` 在 rusqlite 下的真实收益（原 4–5 倍结论出自 Bun 栈）、窄表 `WITHOUT ROWID` 的收益
- [ ] **② React UX 竖切**：React Aria 日期范围 + ECharts 趋势 + CSS Grid 热力图 + 虚拟表格同页，**数据经 TanStack Query + SSE 失效、导航经 TanStack Router（URL 即状态）**（ADR-0001 前端数据与导航层）
  **验收**：键盘全流程 / 读屏 aria 树 / 首屏 < 300ms / ECharts 懒加载体积达标；ECharts 渲染器定格（SVG 优先，dataZoom 实测不达标则回落 canvas + 过渡编排）；**主题切换时图表与页面同帧**（逐帧截图断言无中间帧）；虚拟化方案以 10 万行实测定格（Aria Virtualizer vs TanStack Virtual）；React Compiler × React Aria 兼容性冒烟；**刷新/后退/直链三操作下 URL 完整复现视图状态**
- [ ] **③ 跨端竖切**：同一 application service 同时接 Ratatui + Axum + Tauri IPC
  **验收**：三平台安装体积（~10MB 级）/ 冷启动 / 空闲内存实测定格；**写入单 owner 在三端并存时成立**（文件锁抢占、崩溃后自动接管、并发启动无双 daemon）

## M1 · 核心数据层（第一优先级）

目标：`tokly scan` 把 Claude Code 全部历史导入本地仓库；`tokly report` 出终端汇总表——里程碑可 dogfood 才成立。

- [ ] `crates/tokly-core`：schema 全表落地（以[数据库-schema](数据库-schema.md)为规范，rusqlite + 迁移）
- [ ] 增量摄取引擎：三类源水位线 + 收敛契约 fold（事件身份 + 可比 revision 域 + 显式冲突 + 同事务边界）
- [ ] `crates/tokly-adapter-claude`：首个 adapter（serde 流式解析，数据最丰富），含**已验证格式版本集合**声明
- [ ] `crates/tokly-pricing`：LiteLLM JSON + 本地缓存 + 用户覆盖 + 模糊匹配；按事件时点计价；**舍入与精度按 [ADR-0015](adr/0015-计价精度.md)**（i128 中间累加、round-half-even、price_kind 字典序求和）
- [ ] `crates/tokly-format`：两 locale 数字与日期规则 + 跨语言测试向量（`tokly report` 需要它）
- [ ] **配置子系统**（[ADR-0010](adr/0010-配置子系统.md)）：`config.toml` 读取校验 + `machine` 持久化 + `tokly config check|get|set`
- [ ] **`tokly doctor`**（[ADR-0014](adr/0014-诊断与格式演进.md)）：源状态、水位线、坏行与冲突计数、各层行数
- [ ] `tokly report`：终端汇总表（只聚合 `status='counted'`，native/computed 双列分别展示）
- [ ] `quota_snapshots` 表随 schema 落地（采集在 M2/M3）
- [ ] golden fixtures + 收敛性 property tests（四场景，快照含全部派生表）

## 广度与质量的优先级判据（新增）

六源 × 三端 × 三平台的范围与"每个点打磨到极致"直接竞争。判据固定为一条：

**任何新 adapter 不得先于已有 adapter 的 golden fixtures、口径一致性测试与已验证格式版本集合完成。** 广度是可以推迟的，已入库的错数据不可逆。（对应[风险登记](风险登记.md) R10）

## 明确不做（当前阶段）

- 本地代理拦截（违反只读铁律）· 替用户开启 OTEL 或修改任何配置
- 云同步、账号体系、排行榜 · 遥测与崩溃上报（[ADR-0014](adr/0014-诊断与格式演进.md) 显式决策）
- 数据库加密（本地单用户工具，威胁模型不成立）
- 多设备同步（M6 后评估）
- RTL 与更多预置语言（社区贡献通道留在 CONTRIBUTING）

## 性能 SLO（验收硬指标）

**基准数据集**（没有它，下面的延迟指标不可验收）：合成数据集 `bench-3y`——三年跨度、六源、120 万事件、8 万会话、1,100 天日聚合，由 `cargo xtask bench-fixture` 确定性生成。所有延迟指标在该数据集上用 criterion 测量。

| 指标 | 目标 | 数据集 |
|---|---|---|
| CLI 启动 | < 100ms | — |
| 增量扫描 | < 1s（水位线命中） | bench-3y |
| 首次全量导入 | < 30s（十万级事件；原"万级文件"单位不对，文件数不是负载的度量） | bench-3y |
| daemon 常驻内存 | < 50MB | bench-3y |
| Dashboard 概览查询 | < 100ms | bench-3y |
| Dashboard 任意下钻查询 | < 100ms | bench-3y |
| Dashboard 首屏 | < 300ms（本地数据） | bench-3y |
| 数据库稳态体积 | **< 1 GB** | bench-3y 稳态（观测 90d / 事件 180d） |
| 永久层年增 | **< 50 MB** | 日聚合 + 会话汇总 |

体积口径的推导见 [ADR-0011](adr/0011-存储生命周期.md)——旧的"每年 < 100MB"未计索引与观测层，不成立；"三年 GB 级"是无分层时的数字，同样不是本设计下的口径。
