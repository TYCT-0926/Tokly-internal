## 关键数据流

1. **摄取**：`tokly scan` → adapter 发现数据文件 → 水位线跳过已读 → 流式解析为 UsageEvent → 批量事务入库（收敛契约：事件身份 + 可比 revision 域 + 显式冲突，事件/子表/session dirty/水位线同事务）→ 受影响 sessionKey 两侧局部重算 sessions
2. **重算**：`tokly reprice` → 按事件时刻匹配 `pricing_history` 生效区间定价 × 事件归一化 token 列 → 更新 costComputed 列（pricing worker 独占，adapter 重扫不覆盖）→ sessions 局部重算
3. **展示**：三端查询同一 SQLite（Web/桌面经 daemon 的本地服务，TUI 优先连接 daemon、降级只读直连），查询一律走聚合与索引

## 包职责

| 包 | 职责 | 边界 |
|---|---|---|
| `@tokly/core` | UsageEvent 类型、SQLite（SqlDriver 抽象 + 迁移）、IngestEngine、daemon 与本地服务、i18n | 不识任何源格式 |
| `@tokly/pricing` | 定价表加载链（快照<缓存<覆盖）、成本计算、版本标识 | 纯函数，无 IO 依赖注入 |
| `@tokly/adapter-*` | 一源一包：discover + parse + 能力声明 | 只读源数据，不写 |
| `@tokly/design-tokens` | 三层令牌、OKLCH 派生、CSS/TUI 导出、主题校验 | 无 UI 框架依赖 |
| `apps/cli` | `tokly scan / report / reprice / serve` | 只做编排，无业务逻辑 |
| `apps/web` | Dashboard SPA（Vite + React + uPlot） | 经 core API 取数，不碰文件 |
| `apps/tui` | 终端监控（OpenTUI / @opentui/solid） | 同上 |
| `apps/desktop` | Tauri 壳（托盘/Widget/窗口） | 复用 web 构建产物 |

数据面补充（ADR-0002）：`usage_events` 是事件主表，也是**观测/投影两层模型**的投影侧——观测（observation）永久保留，**缺席 ≠ 删除**，只有显式删除证据才把投影标 `tombstoned`；同坐标或跨流同键不同 payload 一律进 `conflict_observations` 显式处理，**禁止静默 last-write-wins**（二轮审查 §1）。`tool_calls`（工具调用，含 status/时长）与 `event_charges`（非 token 计费项，如 premium-request 数）是以事件身份关联的子表，替代"零 token 独立事件"；`pending_messages` 承载流式消息的定稿状态机；`ingest_errors` 让解析坏行/跳过行可见（只存错误码/位置/hash/长度/计数，不存内容）；`quota_snapshots` 承载订阅配额窗口（[ADR-0008](adr/0008-配额窗口.md)）。

## 进程模型（2026-08-02 审查 §三 P1-11 / §四 盲区 8）

**写入单 owner：单 daemon 所有权。**

- 第一个启动的进程（`tokly serve` / TUI / 桌面 sidecar，任一）成为 **daemon**：独占摄取与写库，托管本地 HTTP 服务（仅 127.0.0.1）。
- **端口文件发现**：daemon 把 `{port, pid, token, schema_version}` 写到用户数据目录的 `daemon.json`；后启动的端发现已有 daemon 即连接之，不各自起摄取。
- **TUI 降级**：daemon 不可达或版本协商失败时，TUI 降级为**只读直连** SQLite（`mode=ro`）——能看历史，不做摄取，并在界面标注降级态。
- **摄取节奏**：文件源走 watcher（fsnotify，写爆发期 debounce ~2s）；不支持 watch 的走轮询兜底（Cursor `state.vscdb` 轮询 mtime；API 源按周期幂等拉取，详见各源 spec）。
- **schema_version 协商**：连接握手时比对库版本，版本漂移**拒开**并提示迁移/升级——防新旧版本混写同一库。
- **本地服务鉴权**：127.0.0.1 上任意进程都能读端口，无鉴权等于把全部用量与项目路径暴露给本机其他进程（审查 §四 盲区 8）。首次启动生成**随机 token** 写入 `daemon.json`（文件权限仅用户可读），本地 API 一律要求携带。

## 不可违反的架构约束

1. **只读零侵入**（[ADR-0003](adr/0003-只读采集原则.md)）：对源工具零写入零配置变更
2. **只存指标不存内容**（[ADR-0002](adr/0002-数据架构.md)）：永不存储对话内容
3. **摄取收敛性幂等**：同一固定 observation 集合，交换/乱序/重放/重建四场景终态逐字节一致（ADR-0002 收敛契约 + property tests）
4. **core 不识源格式，adapter 不写库**：两者经 UsageEvent 单向解耦
5. **三端不各自实现展示逻辑**：共享 design-tokens 与查询层
6. **写入单 owner**：一切摄取经 daemon，其余端连接或只读降级（见「进程模型」）

## 性能预算（实测依据见 ADR-0001 spike 注记）

- 增量扫描：< 1s（水位线命中）；首次全量导入：万级文件 < 30s
- Dashboard 任意聚合查询：< 100ms（`PRAGMA cache_size=-16000` 已固化）
- 数据库体积：**三年重度使用 GB 级**（2026-08-02 审查 §四 7 修正，原「每年 < 100MB」口径不含索引与页开销，乐观 5–10 倍；缓解措施见 ADR-0002 资源纪律）；内存：解析期恒定（流式）
