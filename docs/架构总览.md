## 关键数据流

1. **摄取**：`tokly scan` → adapter 发现数据文件 → 水位线跳过已读 → serde 流式解析 → 写 `usage_observations` → 决定论 fold 出投影与冲突 → 受影响 sessionKey 两侧 dirty 标记。事件、子表、dirty 标记、水位线同一事务提交。
2. **重算**：`tokly reprice` → 按事件时刻匹配 `pricing_history` 生效区间取价 × 归一化 token 列 → 更新 computed 三列（pricing worker 独占，adapter 重扫不覆盖）→ 会话与日聚合局部重算。精度与舍入见 [ADR-0015](adr/0015-计价精度.md)。
3. **收敛**：`tokly compact` → 日聚合与工具日聚合写入 → 会话汇总刷新 → 投影层过期行删除 → 观测层过期行删除 → 受影响永久层行标 `frozen_at`。单事务，任一步失败整体回滚（[ADR-0011](adr/0011-存储生命周期.md)）。
4. **展示**：三端查询同一 application service——浏览器经 Axum HTTP+SSE，桌面窗口经 Tauri IPC/events（进程内），TUI 同进程直调或连接既有 daemon、必要时降级只读直连。查询一律走聚合与索引。
5. **诊断**：`tokly doctor` 汇总各源格式版本、水位线、坏行与冲突计数、各层行数——同一份数据同时供给 UI 的「数据健康」面板（[ADR-0014](adr/0014-诊断与格式演进.md)）。

## 包职责

| crate / 包 | 职责 | 边界 |
|---|---|---|
| `tokly-core` | UsageEvent 类型、SQLite（rusqlite + 迁移）、IngestEngine、fold | 不识任何源格式 |
| `tokly-pricing` | 定价表加载链（快照<缓存<覆盖）、按事件时点计价、舍入规则、版本标识 | 纯函数，IO 依赖注入 |
| `tokly-tokens` | DTCG 解析、OKLCH 派生、gamut 映射、对比度救济、质量门、ANSI 降级链 | 无 IO；构建期与安装期共用（[ADR-0017](adr/0017-令牌派生引擎.md)） |
| `tokly-format` | zh-CN / en 两 locale 的数字与日期格式规则 | 与 Web 侧 `Intl` 由共享测试向量对齐（[ADR-0016](adr/0016-i18n运行期.md)） |
| `tokly-adapter-*` | 一源一 crate：discover + parse（serde 流式）+ 能力声明 + **已验证格式版本集合** | 只读源数据，不写 |
| `tokly-service` | application service：查询/聚合、写连接单 owner；DTO 经 ts-rs 出 TS 类型 | transport 无关；**不做本地化，DTO 不含成品字符串** |
| `tokly-server` | Axum + SSE transport（仅 127.0.0.1 + token + `Origin` 校验） | 薄适配，无业务逻辑 |
| `tokly-cli` | `tokly scan / report / reprice / serve / compact / doctor / config / theme` | 只做编排，无业务逻辑 |
| `tokly-tui` | 终端监控（Ratatui + Crossterm，同进程调 service） | 消息渲染在本层，Fluent 关闭双向隔离符 |
| `apps/web` | Dashboard SPA（Vite + React 19 + React Aria + ECharts 6 懒加载） | 经 HTTP/SSE 取数；DTO 用生成类型，禁止手抄领域模型 |
| `apps/desktop` | Tauri 壳（托盘 / Widget / 窗口，直嵌 service） | 经 IPC/events；复用 web 构建产物 |
| `packages/design-tokens`（构建期） | DTCG 令牌源 + preview 验证页 | **不含派生算法**（算法在 `tokly-tokens`） |

数据面补充（[ADR-0002](adr/0002-数据架构.md) / [ADR-0011](adr/0011-存储生命周期.md)）：`usage_observations` 是只追加的观测层，也是 fold 的输入与「重建」property test 的依据；`usage_events` 是由固定观测集合决定论 fold 出的投影，**缺席 ≠ 删除**，只有显式删除证据才标 `tombstoned`；同坐标或跨流同键不同 payload 一律进 `conflict_observations`，**禁止静默 last-write-wins**，而"曾发生冲突"由投影层的 `has_conflict` 永久保留。`tool_calls` 与 `event_charges` 是以事件身份关联的子表，替代"零 token 独立事件"；`pending_messages` 承载可随机重读的源的定稿状态机；`ingest_errors` 让坏行、跳过行与未验证格式版本可见；`quota_snapshots` 承载订阅配额窗口（[ADR-0008](adr/0008-配额窗口.md)）。

## 进程模型

**写入单 owner**，协议见 [ADR-0012](adr/0012-进程与本地服务.md)。要点三条，细节不在本页复述：

- 所有权由 `daemon.lock` 的 **OS 咨询文件锁**承担——拿到锁即 daemon，进程崩溃时内核自动释放，无陈旧状态与心跳超时；`daemon.json` 只是发现缓存。
- 本地服务鉴权 = 随机 token（文件权限 POSIX `0600` / Windows DACL）+ `Origin`/`Host` 校验；token 经 URL fragment 交给浏览器，不进访问日志。
- `schema_version` 握手不匹配拒开；**只读直连降级路径走同一判据**，不做尽力解析。摄取节奏用 `notify` watcher，写爆发期 debounce 2s，不支持 watch 的走轮询兜底。

## 不可违反的架构约束

1. **只读零侵入**（[ADR-0003](adr/0003-只读采集原则.md)）：对源工具零写入零配置变更
2. **只存指标不存内容**（[ADR-0002](adr/0002-数据架构.md)）：永不存储对话内容，日志与错误表同此红线
3. **摄取收敛性幂等**：同一固定观测集合，交换/乱序/重放/重建四场景终态逐字节一致；重建的适用域是观测保留窗口内（[ADR-0011](adr/0011-存储生命周期.md)）
4. **core 不识源格式，adapter 不写库**：两者经 UsageEvent 单向解耦
5. **三端不各自实现展示逻辑**：共享令牌产物与 application service 查询层
6. **写入单 owner**：一切摄取经 daemon，其余端连接或只读降级
7. **DTO 不含成品字符串**：本地化在展示端（[ADR-0016](adr/0016-i18n运行期.md)）
8. **不做遥测**：出站网络只有定价表刷新与用户显式授权的 API 源，新增需新 ADR（[ADR-0014](adr/0014-诊断与格式演进.md)）

## 性能预算

| 指标 | 目标 |
|---|---|
| CLI 启动 | < 100ms |
| 增量扫描 | < 1s（水位线命中） |
| 首次全量导入 | < 30s（十万级事件量级；原文的"万级文件"单位不对，文件数不是负载的度量） |
| Dashboard 任意聚合查询 | < 100ms |
| Dashboard 首屏 | < 300ms（本地数据） |
| daemon 常驻内存 | < 50MB |
| 数据库稳态体积 | **< 1 GB；永久层年增 < 50 MB**（口径与依据见 [ADR-0011](adr/0011-存储生命周期.md)，此处不复制推导） |

解析期内存恒定（流式，禁止整文件读入）。基准数据集与测量方法见[路线图](路线图.md)性能 SLO 节——**没有定义数据集规模的延迟指标不可验收**。
