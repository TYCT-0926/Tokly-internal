# ADR-0003: 采集边界——只读零侵入原则

- 状态：accepted
- 日期：2026-08-02

## 背景

获取更多数据的常见手段包括：本地代理拦截（改 `ANTHROPIC_BASE_URL` 等）、替用户开启 OTEL（写 `settings.json` / 环境变量）、cookie/JWT 抓取（Cursor 等）。产品要求：**绝不能对用户的原有工具造成任何影响**。

## 决策

Tokly 对源工具**只读、零写入、零配置变更**。允许的采集通道按优先级：

1. **只读解析本地文件/数据库**——主力通道。打开源 SQLite 一律用只读模式（`mode=ro` + `busy_timeout`）；`immutable=1` 仅用于静态副本（如 Cursor state.vscdb 必须先复制再读）——对活动库用 immutable 可能读到 WAL 撕裂页（2026-08-02 审查 §四 盲区 9）。
2. **被动利用用户已自行开启的机制**——如用户自己配置了 Claude / Gemini 的 OTEL，Tokly 可消费其输出；Tokly 永不替用户开启。
3. **官方 API（显式授权）**——Copilot 等本地无解的源，由用户主动提供 PAT 并知晓粒度差异（premium-request 单位 ≠ token）。凭据仅存系统钥匙串。

明确放弃：

- ❌ 本地代理拦截（需重定向各 CLI 的 base URL）
- ❌ 修改任何配置文件、环境变量
- ❌ cookie / JWT 抓取非官方私有端点（Cursor web API 等，ToS 灰色且脆弱——tokscale 与 cursor-stats 的下场已知）

## 后果

- Gemini 的实时数据质量取决于 chats 文件（易失），接受；历史深度以本地已有数据为界。
- Cursor 只能提供标注为 `estimated` 的数据；Copilot IDE 只能提供日粒度 premium-request 口径。这些限制在 UI 中原样呈现，不掩饰。
- 此原则是产品级承诺，写入 README；任何采集相关 PR 需在描述中声明不违反本 ADR。
