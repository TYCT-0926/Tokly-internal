# ADR-0001: Monorepo 形态与运行时选型

- 状态：accepted（2026-08-02 二轮修订，依据 [审查-2026-08-02](../research/审查-2026-08-02.md)：node:sqlite 双运行时兼容被推翻、OpenTUI 改 @opentui/solid、Bun 单点风险登记）
- 日期：2026-08-02

## 背景

Tokly 需要三端（Web / TUI / 桌面）共享同一份数据采集与存储逻辑。核心工作是解析各家格式各异的本地日志并归一化。硬性要求：极致性能与轻量安装、顶级视觉、单一代码库。

## 决策

- **语言**：全栈 TypeScript。core 为 TS 库，三端直接复用类型与逻辑，无跨语言边界。
- **运行时**：**Bun**。`bun build --compile` 产出零依赖单文件。代码保持 Node 兼容，且「**core 在 Node 24+ 无损运行**」升为硬约束——它是全部 Windows 风险的逃生通道（见「Bun 单点风险」）。
- **SQLite 驱动（spike 实测修正，2026-08-02；二审再修正）**：三驱动（node:sqlite / bun:sqlite / better-sqlite3）在 Tokly 的真实负载（批量写 + 聚合扫描）上**性能实质等价**（差距 ≤25%，node:sqlite 略快）——"bun:sqlite 快数倍"的网传基准是微型点查负载，不适用于聚合负载。真正的性能杠杆是 `PRAGMA cache_size`（默认 2MB → 16MB 带来 4–5 倍查询提升，已在 SqlDriver 初始化固化）。决策：**显式双驱动适配**——SqlDriver 抽象下运行时检测，Bun → `bun:sqlite`，Node → `node:sqlite`（两者 API 不同，需一层薄适配，约 50 行）；不引入 better-sqlite3 原生依赖。原决策「node:sqlite 双运行时兼容」被审查推翻：**Bun 未实现 node:sqlite**（官方参考页长期标 "Not implemented"；旧追踪 issue oven-sh/bun#27092 已 404——官方文档/主干已前进，Bun 1.3.14 尚未兑现，本机实测仍 "No such built-in module"，二轮审查 §3；实现它的是 Deno）。
- **Monorepo**：pnpm workspaces + Turborepo。小团队共识方案，不引入 Nx 的配置复杂度。
- **TUI**：**OpenTUI**，走 **@opentui/solid** 路径（二审查证：opencode 生产用的是 Solid 而非 React reconciler，见 opencode tui/package.json；原「React 经 opencode 生产验证」的表述有误）。Zig 原生渲染、亚毫秒帧、一等鼠标支持。Ink 有硬编码 30fps 上限与内存问题，blessed 已停止维护。风险诚实标注：OpenTUI pre-1.0，锁定版本应对；**Windows 端质量未证实**——issue anomalyco/opentui#152 已关闭（称多数改善）但仍留闪烁/低帧未完成项（二轮审查 §3），**必须在当前 Windows/Bun 组合实测验证后再定级**（M4 开工前置，见风险登记 R1）——降级预案为降帧/禁特效，仍不达标则引导 Windows 用户走 Web Dashboard，不承诺完美体验。
- **桌面**：**Tauri 2**。真实应用安装包 2.5–10MB（Electron 85–244MB）；托盘 / 置顶 Widget / 多窗口一等支持。弃选 Electron（体积）与 Neutralino（生态过弱）。
- **图表**：**uPlot**（约 45KB，Grafana / SigNoz 同款，15 万数据点约 90ms）+ 手写 CSS Grid 热力图（顶级产品均手写）。ECharts 6 模块化构建作为后备升级路径。

## 取舍

- 性能问题靠架构解决（水位线增量摄取，见 ADR-0002），而非靠 Rust 核心的原始速度——tokscale 的 Rust 路线我们明确不跟，换取单语言迭代速度。
- 桌面端内嵌 Bun sidecar 会使总安装体积升至约 60–80MB（仍为 Electron 的 1/3）。接受为 v1 代价，v2 演进路径见 ADR-0004。
- Linux 上 Tauri 依赖 WebKitGTK，需要专项 QA；Windows 依赖 WebView2（Win10/11 已事实普及）。

## Bun 单点风险（2026-08-02 审查新增）

Windows 侧的四类风险同源于 Bun：OpenTUI Windows 质量未证实（issue #152 已关闭但留未完成项，须当前 Windows/Bun 组合实测）、node:sqlite 缺失（文档/主干已前进，Bun 1.3.14 尚未兑现）、94MB 编译体积地板、sidecar 孤儿进程。对冲策略统一为：**双驱动适配层 + 「core 在 Node 24+ 无损运行」硬约束**，任一 Bun 环节塌方时由 Node 接管，产品不死。逐条证据与状态见 [风险登记](../风险登记.md)。

## 后果

- `apps/`（web、tui、desktop）+ `packages/`（core、pricing、design-tokens）的目录结构由此确定。
- CI 需要 Bun + Rust 两条工具链（Tauri）。
