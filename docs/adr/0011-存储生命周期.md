# ADR-0011: 存储生命周期、保留策略与可重建性

- 状态：accepted
- 日期：2026-08-03

## 背景

[ADR-0002](0002-数据架构.md) 同时写了两条互相冲突的约束：

- 收敛契约：「observation 永久保留」「败方 observation 永不物理删除——fold 可从 observation 层随时重建 projection」，且这是"重建"property test 的依据；
- 分层保留：「raw 事件保留 90 天（可配置）」，`tokly compact` 同事务完成"聚合写入 → raw 删除"。

90 天后观测层不再完整，"任何时候可重建"随之失效。冲突在 DDL 层就已跑不通：`conflict_observations` 的外键指向 `usage_events` 且无 `ON DELETE` 子句，而 `foreign_keys = ON`——删 raw 会被外键直接拒绝，schema 备注里描述的"清空投影后按 fold 重放"同样执行不了。

三个连带问题：

1. `sessions` 号称"派生表、任何时候可从 `usage_events` 全量重建"，但清理后不可重建——它实际变成了权威表；
2. `tool_calls` 随事件级联删除，而日聚合层没有工具调用维度——[竞品调研](../research/竞品调研.md)里列为差异化位置的"会话/工具调用级分析"被保留策略静默砍到 90 天；
3. [组件规格](../design/组件规格.md)承诺"模型→项目→会话→事件"四级下钻，事件层在窗口外不存在，UI 无对应形态。

实现侧已先行给出部分答案：`tokly-core` 建了一张文档中不存在的 `usage_observations`（完整观测日志）——那正是上述矛盾的正解，但它的代价（约为投影层 2.5 倍行数，依据本机实测 141,830 usage 行 / 56,892 逻辑键）从未进入存储预算。

## 决策

### 四层模型与各层寿命

| 层 | 表 | 寿命 | 可重建性 |
|---|---|---|---|
| **观测** | `usage_observations`（只追加）、`conflict_observations` | 保留 `retention.observations_days`，默认 **90 天** | — |
| **投影** | `usage_events`、`tool_calls`、`event_charges` | 保留 `retention.events_days`，默认 **180 天** | 观测窗口内可由 fold 重建 |
| **会话汇总** | `sessions`、`session_model_stats` | **永久** | 投影窗口内可重建，窗口外定格 |
| **日聚合** | `daily_usage_rollups`、`daily_tool_rollups` | **永久** | 投影窗口内可重建，窗口外定格 |

硬约束：`observations_days ≤ events_days`（配置校验强制）。

### "永久保留"承诺的准确边界

产品承诺是"导入一次永久保留，源日志被清理不影响 Tokly 数据"。本决策把它精确化为：**永久的是会话汇总与日聚合，不是事件明细。**

用户可见的历史曲线、热力图、会话列表、年度回顾全部永久；受限的只有"某一次具体请求的逐字段明细"。这个边界必须在 README、设置界面与超出窗口的下钻处原样呈现，不掩饰。

### 可重建性的定义域（替代旧「任何时候可重建」）

- **重建 property test 的适用域 = 观测保留窗口内。** 窗口外的投影行标 `observations_pruned_at`，fold 不再对其生效。
- 投影清理时，受影响的会话汇总与日聚合行标 `frozen_at`。此后 `rollup_version` / `normalizer_version` 变更**只重建未定格的部分**；定格部分保留旧版本号并在 UI 可见。
- 定格不是错误状态，是有记录的历史口径。

### 工具调用的永久层

新增 `daily_tool_rollups`（day × source_instance × tool_name → 调用数、成功/失败数、总时长）。工具名基数低、体积小，使工具调用分析在事件清理后依然永久可用——修正上文问题 2。

### 外键与冲突表

`conflict_observations` **不再外键引用 `usage_events`**：它属观测层，与 `usage_observations` 同寿命，独立成表加索引。"该事件曾发生冲突"这一事实由投影层的 `has_conflict` 标志永久保留，冲突明细随观测窗口过期。这解开上文的 DDL 死锁。

### 时区与日界

日聚合按本地日界切分，但**日界所用时区随行记录**：`daily_usage_rollups` 增列 `tz`（IANA 名）与 `utc_offset_minutes`。

- 检测到有效时区变更时，在**投影保留窗口内**自动重算受影响天；
- 窗口外的旧行保留原 `tz`，UI 标注口径差异，**不静默改写历史**；
- `[general] timezone` 可锁定为固定 IANA 时区，锁定后不再随系统漂移（[ADR-0010](0010-配置子系统.md)）；
- **rollup 失效可判性缺口（2026-08-05 M1 记录，M2 验收前置）**：`daily_usage_rollups` 行不记录自身覆盖范围，compact 之后的摄取或 reprice 会使若干天失效且**不可探测**（reprice 只动成本不动计数，按天计数比对亦不可判；compact 未跑时该表为空）。M1 的 `tokly report` 经维护者追认改读 `sessions` 永久层（`dirty_since` 由 fold 与 pricing worker 同事务维护，陈旧可判；实测总量与事件级真值逐字段相等）。M2 的按日查询面（趋势/热力图）落地前必须为 rollup 补失效追踪——候选：行携 `rollup_version` 对照 `data_version`，或 fold 同事务维护 dirty-day 集合；
- **偏移提供者分级（2026-08-04 M1 追认）**：行内 `utc_offset_minutes` 的语义 = **该本地日实际生效的偏移**（逐日，DST 感知）。M1 允许以固定偏移作**已声明的降级**（默认 UTC；文档明示 DST 时区在夏令时切换期间至多一小时事件错分本地日、且 compact 后按 frozen 规则定格）——键形状与列语义不变，缺的只是提供者。M2 时区子系统落地 IANA 逐日计算后**仅替换偏移提供函数**：保留窗口内经上文"自动重算"通道修正，窗口外沿用"不静默改写历史"。

旧设计把本地日界字符串写死而不记录时区，用户换时区后历史永久错误且不可修正——本条是对它的修正。

### 存储预算（替代「三年 GB 级」与「每年 < 100MB」两个互斥口径）

事件层是滚动窗口不累积，永久层年增很小：

| 项 | 预估 |
|---|---|
| 观测层（90 天） | 投影层的约 2.5 倍行数 |
| 投影层（180 天，六源重度） | 事件 50–150 万行 |
| 永久层年增 | 日聚合 + 工具日聚合 + 会话汇总，10 MB 量级 |
| **稳态总体积** | **目标 < 1 GB** |

性能 SLO 由"每年 < 100MB"改写为「**稳态 < 1 GB；永久层年增 < 50 MB**」——前者在计入索引与观测层后不成立，后者可验收。

### `tokly compact`

单事务顺序：日聚合与工具日聚合写入 → 会话汇总刷新 → 投影层过期行删除（子表级联）→ 观测层过期行删除 → 受影响会话/日聚合行标 `frozen_at`。`VACUUM` 作为独立步骤，不进同一事务。任一步失败整体回滚，不留半清理状态。

## 为什么现在做

这是 M0.5 冻结门内的问题，不是可以留给 M2 的运维细节：

1. DDL 冻结是冻结门交付物，而当前 DDL 在 `foreign_keys = ON` 下**执行不了自己文档里描述的 compact 与重建**——冻结一份跑不通的 schema 等于没冻结。
2. 保留策略决定 schema 形状（观测表、定格标记、时区列）。事后加列容易，**事后改语义不可能**：已按旧口径写入的日聚合行无法追溯它当时用的是哪个时区，那批数据永久错误。

## 代价与备选

- **投影层 90 → 180 天**：体积换钻取深度。90 天覆盖不了"与上季度对比"这类真实提问；180 天在滚动窗口下不累积。代价是稳态体积上限从约 0.5 GB 抬到约 1 GB。
- **新增 `daily_tool_rollups`**：一张小表，换"工具调用级分析"这个已写进[竞品调研](../research/竞品调研.md)的差异化位置在窗口外继续成立。这是取舍不是白拿——多一张表要维护、要进重建路径、要进一致性测试。不加的代价是 UI 与文档继续承诺一个 180 天后就消失的能力。
- **备选一：事件层永久保留，不做分层。** 弃选理由：六源三年量级下体积进入数 GB，违反"数据持续增长不得拖累用户机器"的资源纪律。
- **备选二：观测层永久、投影层滚动。** 弃选理由：观测层比投影层大约 2.5 倍，方向正好反了。
- **备选三：日聚合按 UTC 日界，绕开时区问题。** 弃选理由：所有 UI 的"今天"会与用户的今天错位——对一个按天看用量的工具，这是产品级缺陷，不是技术妥协。
- **承诺收窄的诚实成本**：把"永久保留"从"事件明细永久"收窄为"汇总永久"，是对外承诺的实质缩小。它必须写进 README 与 UI，而不是靠用户自己撞上才发现——这也是本决策最需要被公开的部分。

## 后果

- [数据库-schema](../数据库-schema.md) 按本决策重写：新增 `usage_observations` 与 `daily_tool_rollups`；去掉 `conflict_observations` 的外键；日聚合增 `tz` / `utc_offset_minutes` / `rollup_version`；投影增 `has_conflict` / `observations_pruned_at`；派生层增 `frozen_at`。
- ADR-0002 的「数据分层保留」节被本 ADR 取代；收敛契约的其余部分不变。
- [路线图](../路线图.md) 的性能 SLO 与 M2「数据分层保留落地」条目按本决策更新。
- [组件规格](../design/组件规格.md)需要"超出保留窗口"的下钻形态与设置界面的保留期项。
