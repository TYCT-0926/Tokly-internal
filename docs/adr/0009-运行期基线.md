# ADR-0009: 运行期基线与平台支持矩阵

- 状态：accepted
- 日期：2026-08-03

## 背景

[ADR-0004](0004-桌面端分发.md) 定了 macOS 12+ 与 `webkit2gtk-4.1`，[风险登记](../风险登记.md) R7 的对冲写"Lightning CSS 按目标浏览器基线自动降级"——但**基线从未被定义**。且 `webkit2gtk-4.1` 是 API/ABI 版本号而非引擎版本号：同一个 4.1 API 下 WebKitGTK 引擎跨越多个大版本，CSS 能力差距显著，用它当能力下限是一处精度错误。

后果不止于兼容性。桌面窗口经系统 WebView 渲染，OS 下限直接决定可用的 CSS 能力，从而决定[动效规格](../design/动效规格.md)能否用平台原生实现。下限停在 2021 年的 macOS 12（Apple 已于 2024 年停止其安全更新）时，弹簧曲线只能靠 JS 动画库补齐——**OS 下限是设计能力决策，不只是兼容性决策**。

## 决策

### 平台支持矩阵

| 平台 | 下限 | WebView | 依据 |
|---|---|---|---|
| macOS | **14（Sonoma）+** | 系统 WKWebView | 对齐 Apple 自身支持线（当前 + 前两个大版本），随该线滚动 |
| Windows | **10 21H2 / 11** | WebView2 Evergreen Runtime | 常青分发，引擎能力不构成约束；安装期检测 Runtime 缺失并引导安装 |
| Linux | glibc ≥ 2.31 | WebKitGTK **引擎 ≥ 2.44**（API `webkit2gtk-4.1`） | 引擎版本才是能力口径；低于下限见降级路径 |

CLI 与 TUI 不依赖 WebView，其平台下限只受 Rust stable 三平台 target 约束。

### 浏览器基线

browserslist：`Chrome >= 120, Edge >= 120, Firefox >= 129, Safari >= 17.5`

Lightning CSS 的 targets 由此生成，是**唯一**降级配置源。构建期任何超出基线的特性必须显式降级或拒绝合入。`tokly serve` 与桌面窗口共用同一基线——两个 transport 不允许有两套视觉能力。

> 2026-08-03 已按 caniuse / MDN 逐项复核完毕（MDN browser-compat-data 8.0.8 与 caniuse-db 1.0.30001806 双集交叉一致，明细见 [阶段三A-独立核验](../reports/阶段三A-独立核验.md)）。**Safari 由推定值 17.4 修正为 17.5**：`@starting-style` 的 Safari 门槛是 17.5，17.4 只覆盖 `transition-behavior`。Firefox 129 门槛成立；Chrome/Edge 硬基线实际门槛 117，取 120 保留裕量。

| 特性（完整支持最低版本） | Chrome/Edge | Firefox | Safari |
|---|---|---|---|
| `linear()` 缓动 | 113 | 112 | 17.2 |
| `@starting-style` | 117 | 129 | **17.5** |
| `transition-behavior: allow-discrete` | 117 | 129 | 17.4 |
| Cascade Layers | 99 | 97 | 15.4 |
| `:has()` | 105 | 121 | 15.4 |
| `color-mix()` | 111 | 113 | 16.2 |
| 容器查询（size） | 105 | 110 | 16.0 |
| subgrid | 117 | 71 | 16.0 |
| View Transitions（渐进增强） | 111 | 144 | 18.0 |

### CSS 特性预算

| 特性 | 状态 | 用途 |
|---|---|---|
| `linear()` 缓动 | 可用 | 弹簧曲线的原生表达（见下节） |
| `@starting-style` / `transition-behavior: allow-discrete` | 可用 | 浮层入场退场无需 JS 管理挂载态 |
| Cascade Layers · `:has()` · `color-mix()` · 容器查询 · subgrid | 可用 | 栈内既定用法 |
| View Transitions | **渐进增强** | 下钻过渡的优选实现；基线内不保证，必须有 WAAPI 等价路径 |
| OKLCH 运行期色彩 | 不使用 | 派生全部在构建期或安装期完成，运行期只消费 sRGB 字面量（[ADR-0017](0017-令牌派生引擎.md)） |
| 滚动驱动动画 · `text-wrap: balance` · Popover API | 不使用 | 超出基线且无必需用途 |

### Linux 降级路径

引擎低于 2.44：安装期明示警告；桌面图形壳**拒绝启动**，引导至 Web Dashboard 与 TUI（两者不依赖 WebKitGTK）。不做"能跑但很难看"的中间态——诚实标注优于劣化体验。

## 动效后果（本 ADR 的主要收益）

三个签名时刻原先依赖 Motion for React，而其中唯一不可由平台替代的能力是弹簧曲线。基线抬升后：

- 弹簧改为**构建期生成的 `linear()` 缓动令牌**（由令牌管线产出，[ADR-0017](0017-令牌派生引擎.md)），与其余令牌同源同管线；
- 浮层入场退场用 `@starting-style` + `transition-behavior: allow-discrete`；
- 下钻优先 View Transitions，无支持时回落 WAAPI。

因此 **Motion for React 移出依赖**（[ADR-0001](0001-技术栈与运行时.md) 同步修订）。收益不止体积：合成器驱动的原生动画不受主线程阻塞，直接服务动效规格的"动画期主线程 ≤16.7ms"帧预算。

## 为什么现在做

基线不是可推迟的细节，它是三处已定条款的前提：R7 的对冲「Lightning CSS 按目标浏览器基线自动降级」在基线未定义时是空转；动效规格的弹簧参数在不知道能否用 `linear()` 时定不了实现路径；M0.5 的 React UX 竖切 spike 必须按目标基线构建，否则体积与首屏结论无效。

推迟的具体代价：spike ② 在错误基线上验收，M2 大规模写 UI 之后再改基线等于把降级配置与三平台视觉回归重做一遍。

## 代价与备选

- **代价**：macOS 12 / 13 用户不受支持。二者在 2026-08 均已无 Apple 安全更新；安装器在低版本上明示原因，不静默失败。
- **代价**：支持线随 Apple 滚动意味着每年一次复核，评估结论追加在本 ADR 末尾。
- **备选一：保持 macOS 12 下限，动效靠 Motion for React 补齐。** 弃选理由：为一个已无安全更新的系统常驻一个 JS 动画库，且把签名动效放在主线程上——代价直接落在帧预算这条硬指标上。
- **备选二：下限提到 macOS 15+。** 弃选理由：多解锁的能力（主要是 View Transitions 从"渐进增强"变为"确定可用"）不足以抵消再排除一个仍在 Apple 支持线内的版本。
- 取 14 的关键不是这个数字，而是**采用"对齐 Apple 支持线"这条外部客观标准**：它可被独立验证，且随时间自动保持正确，不需要我们每年重新辩论一次。

## 后果

- ADR-0004 的「最低系统版本 macOS 12+」与「Linux 依赖 webkit2gtk-4.1」两条被本 ADR 取代。
- [风险登记](../风险登记.md) R6 / R7 的对冲条款按本矩阵重写。
- CI 视觉回归矩阵按本矩阵取平台与引擎版本。
