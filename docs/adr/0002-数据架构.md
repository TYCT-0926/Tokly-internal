# ADR-0002: 数据架构——归一化事件模型与本地仓库

- 状态：accepted（2026-08-02 三轮修订，依据 [审查-2026-08-02-二轮](../research/审查-2026-08-02-二轮.md)：收敛契约重写为「身份 + 可比 revision 域 + 显式冲突」、观测/投影两层模型、成本所有权五列拆分、水位线三类源操作语义、存储类型定死。此前一轮修订见 [审查-2026-08-02](../research/审查-2026-08-02.md)）
- 日期：2026-08-02

## 背景

各源数据格式完全不同（JSONL 事件流 / SQLite / OTEL 导出），且源工具会清理历史（Claude 默认 30 天，Gemini 用 tmp 目录）。ccusage 的最大短板是无持久化、每次全量重扫。

## 决策

### 唯一事实源：本地 SQLite 仓库

导入一次，永久保留。源日志被清理不影响 Tokly 数据。数据库文件位于用户数据目录（`~/.local/share/tokly/` 或平台等价路径），三端共享。

### 归一化事件模型

所有 adapter 输出统一的 `UsageEvent`（逻辑视图；物理 DDL 以 [数据库-schema](../数据库-schema.md) 为规范）：

```ts
interface UsageEvent {
  // ── 事件身份与 revision（裁决规则见「收敛契约」）──
  source: 'claude-code' | 'codex' | 'opencode' | 'gemini-cli' | 'copilot' | 'cursor';
  sourceInstanceId: string;     // source_instances.id：账号 × 机器 × 源数据根
  eventKey: string;             // 源内去重键（各源 spec 的规则，如 sha1(message.id+requestId)）
  identityQuality: 'strong' | 'weak';  // 键强度：由 fallback（如行级 uuid）构成时为 weak
  revision: {                   // 仅同 (originStream, streamGeneration) 内可比，跨域禁止比较
    originStream: string;       // 观测到该事件的流（文件相对路径 / 库内表 / API 端点+周期）
    streamGeneration: number;   // 流身份代际：身份断裂即 ++，旧代 position 不可比
    sourcePosition: string;     // 流内位置（字节偏移 / rowid / (time_updated,id) / API 页序）
  };
  payloadHash: string;          // 源 payload 的 sha256：同坐标不同 hash = 冲突
  normalizerVersion: number;    // 映射器版本：映射规则演进时 ++（重归一化的锚点）

  // ── 归属与时间 ──
  sessionKey: string | null;    // 源内会话键；API 聚合事件可为 null
  parentSessionKey?: string;
  projectKey: string;           // 归一化项目键（core 统一纯函数归一化）
  projectLabel?: string;        // 展示用原始项目名/路径
  timestamp: number;            // epoch_ms（UTC 存储，本地时区在查询层换算）
  durationMs?: number;
  model: string | null;         // 禁止魔法值：未知即 null，由 UI/计价层降级
  agent?: string;               // 代理/模式标识（opencode agent/mode、claude subagent 等）
  mode?: string;
  gitBranch?: string;
  cliVersion?: string;          // 源工具版本（格式演进排查用）
  status: 'counted' | 'excluded' | 'tombstoned';  // 见「收敛契约」两层模型
  excludeReason?: string;
  channel?: string;             // 采集通道（同 source 多通道并存时区分，见 copilot/gemini spec）
  granularity?: 'event' | 'session' | 'day' | 'month';  // 缺省 event
  periodEnd?: number;           // epoch_ms；granularity ≠ event 时必填
  serviceTier?: string;         // priority / fast / standard 等计费率档

  // ── token（口径不变量见下）──
  tokens: {
    input: number;
    output: number;
    cacheRead: number;
    cacheWrite5m: number;       // 缓存写入按档拆分（价格不同）
    cacheWrite1h: number;
    reasoning?: number;         // 信息性子集，不重复计价
  };
  tokenQuality: 'native' | 'estimated' | 'partial';  // token 数据质量（估算源必须标注）
  tokenCoverage?: string[];     // 不可得/低覆盖维度清单（如 ['cache-read','reasoning']）

  // ── 成本所有权：adapter 只写 native 侧；computed 侧由 pricing worker 独占 ──
  costNativeMicroUSD: number | null;   // 源原生成本（micro-USD）
  nativeCostKind?: 'provider-bill' | 'tool-computed' | 'premium-requests' | 'ai-credits';
  nativeCostProvider?: string;  // 原生成本出具方（'github-billing' / 'opencode:models.dev' / …）
  pricingEligibility: 'standard' | 'estimated-tokens' | 'disabled';  // reprice 选择依据
  displayPolicy: 'native-preferred' | 'computed-preferred' | 'both' | 'native-only' | 'computed-only' | 'estimate-only';
  rawUsage?: string;            // 原始 usage 对象的 JSON——仅在有损映射时存
  rawSchema?: string;           // 源数据格式版本标识（格式演进排查与版本化 resolver 用）
}
```

pricing worker 独占的列不出现在 UsageEvent 上：`costComputedMicroUSD`、`computedCostStatus`、`pricingVersion`（见「成本所有权与可重算」）。账号与机器维度收进 `source_instances`，不再作为事件预留列。

扩列判据（审查 §三 P1-5）：只加入库后**不可逆**的列——事后无法从已存数据重建的维度必须在入库时落定；能从已有列派生的不加。`identityQuality`、`tokenQuality/tokenCoverage` 与成本所有权各列同属此类：源数据被清理后，键是如何构成的、token 是实测还是估算、原生成本是什么口径，都无法再考证。

`cacheWrite5m/cacheWrite1h`：源不提供分档时全部计入 `cacheWrite5m`（默认值），提供方精确拆分。无分档概念的源（Codex/OpenCode）按各自语义映射并计入对应档位。

`projectKey/projectLabel`：项目归一化（路径规范化、大小写、尾部分隔符）由 core 提供统一纯函数完成，adapter 只交原始值——同一物理项目跨源/跨平台路径写法不同也归并到同一 `projectKey`。

工具调用与非 token 计费项不再挂在 UsageEvent 上：分别落 `tool_calls` / `event_charges` 子表（以事件身份关联），废弃"零 token 独立事件"（见「表结构」）。源原生金额一律落 `costNativeMicroUSD` 并按 `nativeCostKind/nativeCostProvider` 标注口径——premium-request 数、AI-credit 等**非 USD 数量**不折算进成本列，进 `event_charges`。

### token 口径不变量（硬约束）

所有 adapter 的映射**必须**满足以下两条，由跨 adapter 口径一致性测试与六源 golden fixtures 强制：

1. **`input` 为净值**：`input` 与 `cacheRead` / `cacheWrite5m` / `cacheWrite1h` 四者互斥，总输入 = 四者之和。源给出含缓存毛值的（Codex `input_tokens` 含 cached），adapter 必须先减去缓存部分再入库——不改则与净值口径的源混算时虚高约 12 倍。**cache read 与 cache write 都是 input 的 details**（二轮审查 §1：上游测试 input=100 / read=40 / write=60 → 净 input=0）：须顺序 clamp 后**同时**减（先 clamp read、再 clamp write 到剩余、最后求净），只减 read 会双计 write。
2. **`output` 恒含 `reasoning`**：reasoning 仅为信息性子集，不重复计价。源把 reasoning 独立计数的（Gemini 的 thoughts、部分 provider 的 OpenCode 数据），adapter 映射时并入 output。

不变量之外的一切源特异性由 adapter 在映射层消化，core 与 pricing 只见统一口径。**无法唯一判别包含关系的（OpenCode 的 reasoning 归属、Gemini 的 total 方程不成立、Copilot 未验证的格式版本）一律 fail-visible**：事件 `status='excluded'` + 冲突/错误留证，禁止默认任一语义猜着入库（各源 spec 的版本化 resolver 节）。

### 表结构（逻辑）

规范 DDL（含全部 PK/UNIQUE/CHECK/FK/索引与迁移机制）见 [数据库-schema](../数据库-schema.md)，是 M0.5 冻结门交付物。逻辑清单：

- `source_instances`：源实例表——账号 × 机器 × 源数据根的稳定映射，事件身份的一半。
- `usage_events`：**current projection**——每个 `(sourceInstanceId, eventKey)` 一行的当前状态；幂等与去重的根基（防 ccusage issue #19 式分支重复计数）。
- `conflict_observations`：冲突观测表——同坐标/跨流同键不同 payload 的显式留证（见「收敛契约」），禁止静默 last-write-wins。
- `sessions` / `session_model_stats`：会话级聚合（整体与按模型两粒度）。**派生表**：任何时候可从 `usage_events` 全量重建，不作为权威数据；事件变更后按「受影响 sessionKey 局部重算」增量维护（`dirty_since` 持久标记），全量重建留作兜底。**空会话删除规则**：局部重算后无 counted 事件的会话行直接删除，不留空壳。
- `tool_calls`：工具调用子表（事件外键、childId、工具名、status、时长）。废弃"零 token 独立事件"（审查 §三 P1-9）。
- `event_charges`：非 token 计费子表（kind、quantity、unit、单价口径）——web search / code execution / premium-request 数 / AI-credit 等按次/按额度计费项可索引聚合，不再塞进 JSON 数组或成本列。
- `pending_messages`：流式未定稿消息的定稿状态机（OpenCode 中断轮次等，见「增量摄取」）。
- `ingest_errors`：摄取错误表（错误码、位置、payload hash/长度、计数）。**解析坏行/跳过行必须可见**（审查 §四 6）：源会清理历史，静默丢弃 = 永久丢弃。**永不存内容摘要**。
- `watermarks`：增量摄取游标（见「增量摄取」）。
- `quota_snapshots`：订阅配额窗口快照（含 provenance/ruleVersion/capacity/unit/confidence），见 [ADR-0008](0008-配额窗口.md)。
- `pricing_history`：带生效期（effectiveFrom/effectiveTo）的价格规则，见「成本所有权与可重算」。
- `schema_migrations`：迁移记录，`schema_version` 协商的权威来源（见架构总览·进程模型）。

### 收敛契约（二轮审查 §1 重写，替代旧「带 revision 的 upsert」）

旧契约被证伪：同 revision 不同 payload 时结果依到达顺序（不满足交换性）；byte offset / rowid / 拉取时刻都不是跨流或跨代的版本；「源终态完整扫描」与永久仓库冲突（源删除后终态不再包含事件）。新契约：

**事件身份 = `(sourceInstanceId, eventKey)`**。`source_instances` 把源类型 × 账号 × 机器 × 源数据根映射为稳定实例 ID：同一物理事件在不同实例间永不撞键，跨实例同 eventKey 也**不**互相去重（两台机器上的 Claude 用量本就是两笔消耗）。

**revision = `(originStream, streamGeneration, sourcePosition)`，仅同 originStream 且同 generation 内可比。** 字节偏移只在同一文件同一代内有序；rowid 只在同一数据库同一代内有序；`(time_updated, id)` 只在同一库内有序；API 页序只在同一拉取周期内有序。跨流、跨代的 position **没有任何序关系，禁止比较**——fork 文件间 offset 不可比；Cursor VACUUM 后旧代高 rowid 不能压新代；API 拉取时刻只是观测时刻。

**观测/投影两层模型**：每次看到的源记录是一条 **observation**，永久保留；`usage_events` 是由固定 observation 集合**决定论 fold** 出的 **current projection**（可标 `excluded`/`tombstoned`）。**缺席 ≠ 删除**：源终态扫描中未出现的事件不作废；只有源给出显式删除证据时才把 projection 标 `tombstoned`，observation 层永不删行。

**裁决规则**（fold 的定义，全部决定论、与到达顺序无关）：

1. 同流同代、position 更大、payloadHash 相同 → 重复观测，跳过。
2. 同流同代、position 更大、payloadHash 不同 → 流式重写的正常覆盖，更新 projection。
3. **同坐标（同流同代同 position）payloadHash 不同 → 冲突**：记 `conflict_observations`，projection 取 payloadHash 字典序较小者——源自身矛盾必须显式可见，**禁止静默 last-write-wins**。
4. **跨流/跨代同 (instance, eventKey)**：payloadHash 相同 → 复制型重复（fork/迁移），去重；不同 → 各流终态全部保留（projection + conflict_observations），projection 取 `(originStream, streamGeneration)` 字典序最小流的终态并标冲突可见。
5. 败方 observation 永不物理删除——fold 可从 observation 层随时重建 projection（「重建」property test 的依据）。

实现形态：应用层先 SELECT 现有行，按上表分支（跳过 / 覆盖 / 冲突），在**单事务**内写出；`ON CONFLICT DO UPDATE` 仅作兜底，不作为裁决逻辑本身。

**事务边界（硬约束）**：单事件写入是原子的——事件 upsert + 旧子表（`tool_calls`/`event_charges`）**集合删除** + 新子表插入 + **新旧两侧 sessionKey 的 dirty 标记** + 水位线推进，同一事务提交。事件跨 session 移动（upsert 改 sessionKey）必须同时 dirty 两端。崩溃恢复：`sessions.dirty_since` 是持久标记，重启后先清 dirty 队列再服务查询；水位线不越过未提交事件。

**幂等 = 收敛性，验收用 property tests（第一测试公民）**：对同一固定 observation 集合，四场景终态必须逐字节一致——**交换**（两批观测互换入库顺序）、**乱序**（任意重排）、**重放**（同一批重复导入 N 次）、**重建**（清空 projection/子表/派生表后从 observation 层 fold 重建 = 增量摄取终态）。「同一数据导入两次 = 导入一次」只是重放场景的特例。测试策略详见 docs/开发流程.md。

### 增量摄取：水位线与三类源操作语义（二轮审查 §2）

水位线表 `watermarks`：PK = `(source_instance_id, channel, stream_key, kind)`；行内另存 `cursor_version` / `generation` / `position` / `file_id` / `header_hash`。PK 四元组加行内 cursor_version、generation 合称**逻辑游标六元组**——position 只在同六元组内可比；身份断裂（文件替换、DB 重建/VACUUM、游标格式升级）→ `generation++` 并归零 position 全量重读。

- **JSONL 类**（Claude / Codex / Gemini / Copilot 文件通道）：比对 mtime/大小 → 字节偏移续读；每轮只消费到最后一个完整换行；**完整非法行**记 `ingest_errors`（错误码/hash/长度/位置）后推进，**无换行残尾**不推进；截断/替换（大小回退、file_id/header_hash 不连续）→ `generation++` 全量重读，幂等由事件身份保证。
- **SQLite 活库类**（OpenCode / Cursor）：**每轮在单一只读事务的一致快照内严格向前分页**（轮内 cursor 不回退）；**跨轮 checkpoint 用 safety horizon**（重叠回退窗口，重复由 upsert 吸收）**+ 周期全量 reconciliation** 兜底。「跨轮 checkpoint 回退」与「轮内严格分页」是两种机制，**分开实现、禁止混用**（二轮审查：2 秒回退仅缓解；无漏还需固定快照 + 尾部安全区 + 周期 reconciliation）。Cursor 额外两条：**用 SQLite backup API 建副本**（含 WAL 的一致快照，替代活动 WAL 下可能撕裂的裸 cp）+ **DB generation 追踪**（DB 头 change counter + schema cookie + 首 N 行 (rowid,key) 采样哈希），代际断裂即全量重扫。
- **API/分页类**（Copilot C/D 通道）：整周期先写 staging，**全部页成功后单事务 reconcile 发布**；任何页失败不发布（保留上一周期 projection）；近期周期滚动重拉，历史周期成功后封存。

三个曾宣称"已修"的静默丢数点，真实状态与修法（二轮审查 §2；[风险登记](../风险登记.md) R4 已同步更正）：

1. **Cursor VACUUM 后 rowid 重编——未修，方案已定待实现**：旧「水位线 rowid→key 反查」被证伪（`UNIQUE ON CONFLICT REPLACE` 是 delete+insert，会把锚点 key 移到新 rowid 造成误报；全扫后低 rowid 又被旧 revision 拒绝）。真实修法：backup API 副本 + DB generation（上文），rowid 只在同 generation 内作 position。
2. **OpenCode 中断轮次定稿——未修，方案已定待实现**：过滤未定稿行后继续推进水位线 = 永久丢轮次。必须走 `pending_messages` 状态机：未定稿消息按 id 登记，每轮先按 id 重读；`finish` 非空 → 定稿；`error` 非空 → 定稿（**error 但已有 token 的轮次照常计数**）；**15 分钟**无更新 → 陈旧定稿。**水位线不得越过任何 pending id。**
3. **页边界同毫秒漏行——仅缓解，方案已定待实现**：轮内严格分页（单只读事务快照内 `(time_updated, id)` 向前）+ 跨轮 safety horizon 重叠 + 周期 reconciliation，三者齐备才算修。

OpenCode 的 SQLite 以 `mode=ro` + `busy_timeout` 只读打开，不与运行中的实例争锁；不用 `immutable=1` 读活库（活库 WAL 下可能读到撕裂页；`immutable=1` 仅对 backup API 产出的静态副本安全，见 docs/sources/opencode.md、docs/sources/cursor.md）。

### 成本所有权与可重算（二轮审查 §1 重写）

旧「双列 + 单一 costBasis」模型被证伪：单一 costBasis 无法同时标注两列；`reprice WHERE costBasis='computed'` 漏掉 native/estimated 行，永远无法形成 native/computed 差异；adapter 重扫全列 upsert 会把 reprice 后的 computed 值覆盖回旧值；"用最新价重算"与"按事件发生时有效价格"直接冲突。新模型按**列所有权**拆分：

| 列 | 所有者 | 语义 |
|---|---|---|
| `tokenQuality` / `tokenCoverage` | adapter | token 数据质量与不可得/低覆盖维度（0 不冒充"已确认没有"） |
| `costNativeMicroUSD` / `nativeCostKind` / `nativeCostProvider` | **adapter 独占** | 源原生成本及口径（provider 账单 / 工具自算 / premium-request / AI-credit） |
| `costComputedMicroUSD` / `computedCostStatus` / `pricingVersion` | **pricing worker 独占** | 计价结果；adapter 重扫 upsert **不含这些列**，重扫永不覆盖计价结果 |
| `pricingEligibility` | adapter 设定 | reprice 选择依据：standard / estimated-tokens / disabled |
| `displayPolicy` | adapter 设定 | UI 展示策略（双列分别展示、何者优先、估算样式） |

规则：

1. **reprice 按 `pricingEligibility` 选事件**（不再按 costBasis）——native 行同样重算，native/computed 差异可展示（OpenCode 历史低估 bug #28494 因此变成可展示的差异化提示而非数据缺陷）；estimated-tokens 行重算但全程带估算标注。
2. **按事件时点计价**：用 `event.timestamp` 匹配 `pricing_history` 的 `[effectiveFrom, effectiveTo)` 区间取价，禁止"最新价回算历史"（[风险登记](../风险登记.md) R2 的落地）。远程价目无历史时自建覆盖层（按抓取时间归档价目快照）。
3. **OpenCode 的 native 是工具按 models.dev 自算**（`nativeCostKind='tool-computed'`、`nativeCostProvider='opencode:models.dev'`），**不是 provider 账单**——UI 不得写"原生/官方成本"，按 displayPolicy 展示 native vs computed 差异。
4. 模型匹配不到 → `costComputedMicroUSD=NULL`、`computedCostStatus='unmatched'`，缺口可见而非虚报。
5. 聚合只算 `status='counted'`；日界按本地时区（UTC 存储，查询层换算）；native/computed **双列分别展示**，不合并成单数。

**保鲜链**（不变）：bundled 快照（随版本发布更新）< 远程 LiteLLM 缓存（stale-while-revalidate：缓存立即可用，后台刷新；刷新失败继续用陈旧缓存并标记 `stale`，UI 可见）< 用户覆盖 `pricing.json`。任何一层失效都不阻塞使用。每条计价结果另存 `pricingVersion`（远程表取抓取时间/etag，内置快照取包版本）。

`rawUsage` **仅在有损映射时存**（源指标无法无损落入归一化列时才保留原始 JSON 兜底）——reprice 从归一化 token 列重算，pricing 层不应懂六种源格式，且源文件 30 天后即消失。

### 存储类型约定（硬约束，二轮审查 §2）

- **时间**：一律 INTEGER **epoch_ms**（UTC）。
- **金额**：一律 INTEGER **micro-USD**（10⁻⁶ 美元）——REAL 聚合漂移不可接受。
- **token**：非负 INTEGER，CHECK 约束强制。
- 以上由 [数据库-schema](../数据库-schema.md) 的 DDL 固化，不靠代码自觉。

### 能力矩阵

每个 adapter 声明字段能力（逐消息 token / 原生成本 / 工具调用 / 历史深度）。UI 按能力降级渲染，不为数据少的源硬撑展示。

### 资源纪律（硬约束）

数据持续增长不得拖累用户机器：

- **只存指标，不存内容**：`usage_events` 只含时间、模型、token 计数、成本，**永不存储对话内容**；`ingest_errors` 只存错误码/位置/hash/长度/计数。存储预算修正（审查 §四 7）：早期「每条约 500 字节、数年百 MB 级」的口径不含索引与页开销，乐观 5–10 倍；现实预估为**三年重度使用 GB 级**。缓解措施：计价字段升一等列后 `rawUsage` 仅在有损映射时存；派生表与明细表可重建/清理；提供 `tokly compact`（VACUUM + 旧 `ingest_errors` 清理）。
- **流式解析**：JSONL 按行流式读取，内存占用恒定，不随文件大小增长；禁止整文件读入内存。
- **有界扫描**：增量摄取只读水位线之后的字节；全量重扫仅限首次导入与水位线失效（generation 断裂）。
- **查询有界**：UI 查询一律走聚合与索引，禁止全表扫描进内存再计算。

### 数据分层保留（2026-08-02 增补）

GB 级存储预估的结构性对冲（对齐 Grafana/Prometheus 的降采样实践）：

- **raw 事件保留 90 天**（可配置）：事件级钻取覆盖近期，这是明细真正被查看的时间窗
- **日聚合永久保留**：`daily_usage_rollups`（source/model/project × day 的 token 与双成本汇总）在 raw 清理前生成——热力图、趋势图、年度 Wrapped 永久不受影响
- 清理由 `tokly compact` 或后台调度执行，同事务完成「聚合写入 → raw 删除」；清理不触碰 quota_snapshots 与 sessions 汇总
- 效果：存储从「三年 GB 级」回到**每年 < 100MB**（性能 SLO，见路线图）

## 后果

- 历史数据问题从架构上解决：首次导入即回填本地全部已有历史，之后增量保鲜。
- 收敛契约的代价是 revision 三元组、冲突表与决定论 fold 的复杂度，换来六源在**交换/乱序/重放/重建**下的可证明收敛；收敛性 property tests 取代朴素的「导入两次」测试（测试策略见 docs/开发流程.md）。
- 成本五列拆分使计价可重入：adapter 重扫与 pricing worker 互不覆盖；reprice 按事件时点生效价重算，历史成本永远可修正且不被污染。
- 冲突不再被静默吞掉：所有 last-write-wins 的诱惑路径都被 `conflict_observations` 显式化，坏行被 `ingest_errors` 显式化。
- 存储预算从「百 MB 级」修正为 GB 级现实预估后，资源纪律从口号变为需要主动管理的约束（rawUsage 按需存储、compact 命令）。
- 任何 UI 查询都打在本地 SQLite 上，亚秒响应，无需缓存层。
- adapter 开发模板固定：格式文档（docs/sources/）→ 解析器 → golden fixtures → 能力声明。
