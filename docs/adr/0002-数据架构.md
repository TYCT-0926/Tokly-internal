# ADR-0002: 数据架构——归一化事件模型与本地仓库

- 状态：accepted（2026-08-02 三轮修订，依据 [审查-2026-08-02-二轮](../research/审查-2026-08-02-二轮.md)：收敛契约重写为「身份 + 可比 revision 域 + 显式冲突」、观测/投影两层模型、成本所有权五列拆分、水位线三类源操作语义、存储类型定死。此前一轮修订见 [审查-2026-08-02](../research/审查-2026-08-02.md)。**2026-08-03 四轮修订**：「数据分层保留」节被 [ADR-0011](0011-存储生命周期.md) 取代——旧节与收敛契约的「observation 永久保留」在 DDL 层就跑不通；计价的舍入与精度移交 [ADR-0015](0015-计价精度.md)；未知源格式版本的处置移交 [ADR-0014](0014-诊断与格式演进.md)。依据 [审查-2026-08-03](../research/审查-2026-08-03.md)。**同日晚间：裁决规则 4 修订**——阶段二对抗评审以可复现实验证明旧规则与截断恢复的 generation++ 相撞（同流新代永远输给旧代，report 永久聚合截断前旧值），修订为「同流取最大代际、跨流取最小流」，见「收敛契约」节内修订注记）
- 日期：2026-08-02

## 背景

各源数据格式完全不同（JSONL 事件流 / SQLite / OTEL 导出），且源工具会清理历史（Claude 默认 30 天，Gemini 用 tmp 目录）。ccusage 的最大短板是无持久化、每次全量重扫。

## 决策

### 唯一事实源：本地 SQLite 仓库

导入一次即与源日志的生命周期解耦——源工具清理历史不影响 Tokly 数据。数据库文件位于用户数据目录（`~/.local/share/tokly/` 或平台等价路径），三端共享。

**"永久保留"的准确边界（[ADR-0011](0011-存储生命周期.md)）**：永久的是**会话汇总与日聚合**，不是事件明细。历史曲线、热力图、会话列表、年度回顾永久可用；事件级明细按保留窗口滚动。这个边界必须在 README、设置界面与超窗下钻处原样呈现——把它写在这里，是为了不让后续文档再把"永久保留"当成无条件承诺来引用。

### 归一化事件模型

所有 adapter 输出统一的 `UsageEvent`（逻辑视图；物理 DDL 以 [数据库-schema](../数据库-schema.md) 为规范）：

```ts
interface UsageEvent {
  // ── 事件身份与 revision（裁决规则见「收敛契约」）──
  source: string;               // 开放源标识（kebab-case；adapter 声明即注册，首发六源见 sources/——ADR-0018）
  sourceInstanceId: string;     // source_instances.id：账号 × 机器 × 源数据根
  eventKey: string;             // 源内去重键（各源 spec 的规则，如 sha1(message.id+requestId)）
  identityQuality: 'strong' | 'weak';  // 键强度：由 fallback（如行级 uuid）构成时为 weak
  revision: {                   // 仅同 (originStream, streamGeneration) 内可比，跨域禁止比较
    originStream: string;       // 观测到该事件的流（文件相对路径 / 库内表 / API 端点+周期）
    streamGeneration: number;   // 流身份代际：身份断裂即 ++，旧代 position 不可比
    sourcePosition: string;     // 流内位置（字节偏移 / rowid / (time_updated,id) / API 页序）
  };
  payloadHash: string;          // 源 payload 的 sha256：同坐标不同 hash = 冲突
  normalizerVersion: number;    // 映射器版本：映射规则演进时 ++（重归一化的锚点）

  // ── 归属与时间 ──
  sessionKey: string | null;    // 源内会话键；API 聚合事件可为 null
  parentSessionKey?: string;
  projectKey: string;           // 归一化项目键（core 统一纯函数归一化）
  projectLabel?: string;        // 展示用原始项目名/路径
  timestamp: number;            // epoch_ms（UTC 存储，本地时区在查询层换算）
  durationMs?: number;
  model: string | null;         // 禁止魔法值：未知即 null，由 UI/计价层降级
  agent?: string;               // 智能体标识（opencode agent/mode、claude subagent 等）——一等聚合维度，进入日聚合与会话统计主键（ADR-0018）
  mode?: string;
  gitBranch?: string;
  cliVersion?: string;          // 源工具版本（格式演进排查用）
  status: 'counted' | 'excluded' | 'tombstoned';  // 见「收敛契约」两层模型
  excludeReason?: string;
  channel?: string;             // 采集通道（同 source 多通道并存时区分，见 copilot/gemini spec）
  granularity?: 'event' | 'session' | 'day' | 'month';  // 缺省 event
  periodEnd?: number;           // epoch_ms；granularity ≠ event 时必填
  serviceTier?: string;         // priority / fast / standard 等计费率档

  // ── token（口径不变量见下）──
  tokens: {
    input: number;
    output: number;
    cacheRead: number;
    cacheWrite5m: number;       // 缓存写入按档拆分（价格不同）
    cacheWrite1h: number;
    reasoning?: number;         // 信息性子集，不重复计价
  };
  tokenQuality: 'native' | 'estimated' | 'partial';  // token 数据质量（估算源必须标注）
  tokenCoverage?: string[];     // 不可得/低覆盖维度清单（如 ['cache-read','reasoning']）

  // ── 成本所有权：adapter 只写 native 侧；computed 侧由 pricing worker 独占 ──
  costNativeMicroUSD: number | null;   // 源原生成本（micro-USD）
  nativeCostKind?: 'provider-bill' | 'tool-computed' | 'premium-requests' | 'ai-credits';
  nativeCostProvider?: string;  // 原生成本出具方（'github-billing' / 'opencode:models.dev' / …）
  pricingEligibility: 'standard' | 'estimated-tokens' | 'disabled';  // reprice 选择依据
  displayPolicy: 'native-preferred' | 'computed-preferred' | 'both' | 'native-only' | 'computed-only' | 'estimate-only';
  rawUsage?: string;            // 原始 usage 对象的 JSON——仅在有损映射时存
  rawSchema?: string;           // 源数据格式版本标识（格式演进排查与版本化 resolver 用）
}
```

pricing worker 独占的列不出现在 UsageEvent 上：`costComputedMicroUSD`、`computedCostStatus`、`pricingVersion`（见「成本所有权与可重算」）。账号与机器维度收进 `source_instances`，不再作为事件预留列。

扩列判据（审查 §三 P1-5）：只加入库后**不可逆**的列——事后无法从已存数据重建的维度必须在入库时落定；能从已有列派生的不加。`identityQuality`、`tokenQuality/tokenCoverage` 与成本所有权各列同属此类：源数据被清理后，键是如何构成的、token 是实测还是估算、原生成本是什么口径，都无法再考证。

`cacheWrite5m/cacheWrite1h`：源不提供分档时全部计入 `cacheWrite5m`（默认值），提供方精确拆分。无分档概念的源（Codex/OpenCode）按各自语义映射并计入对应档位。

`projectKey/projectLabel`：项目归一化（路径规范化、大小写、尾部分隔符）由 core 提供统一纯函数完成，adapter 只交原始值——同一物理项目跨源/跨平台路径写法不同也归并到同一 `projectKey`。

工具调用与非 token 计费项不再挂在 UsageEvent 上：分别落 `tool_calls` / `event_charges` 子表（以事件身份关联），废弃"零 token 独立事件"（见「表结构」）。源原生金额一律落 `costNativeMicroUSD` 并按 `nativeCostKind/nativeCostProvider` 标注口径——premium-request 数、AI-credit 等**非 USD 数量**不折算进成本列，进 `event_charges`。

### token 口径不变量（硬约束）

所有 adapter 的映射**必须**满足以下两条，由跨 adapter 口径一致性测试与六源 golden fixtures 强制：

1. **`input` 为净值**：`input` 与 `cacheRead` / `cacheWrite5m` / `cacheWrite1h` 四者互斥，总输入 = 四者之和。源给出含缓存毛值的（Codex `input_tokens` 含 cached），adapter 必须先减去缓存部分再入库——不改则与净值口径的源混算时虚高约 12 倍。**cache read 与 cache write 都是 input 的 details**（二轮审查 §1：上游测试 input=100 / read=40 / write=60 → 净 input=0）：须顺序 clamp 后**同时**减（先 clamp read、再 clamp write 到剩余、最后求净），只减 read 会双计 write。
2. **`output` 恒含 `reasoning`**：reasoning 仅为信息性子集，不重复计价。源把 reasoning 独立计数的（Gemini 的 thoughts、部分 provider 的 OpenCode 数据），adapter 映射时并入 output。

不变量之外的一切源特异性由 adapter 在映射层消化，core 与 pricing 只见统一口径。**无法唯一判别包含关系的（OpenCode 的 reasoning 归属、Gemini 的 total 方程不成立、Copilot 未验证的格式版本）一律 fail-visible**：事件 `status='excluded'` + 冲突/错误留证，禁止默认任一语义猜着入库（各源 spec 的版本化 resolver 节）。

### 表结构（逻辑）

规范 DDL（含全部 PK/UNIQUE/CHECK/FK/索引与迁移机制）见 [数据库-schema](../数据库-schema.md)，是 M0.5 冻结门交付物。逻辑清单：

- `source_instances`：源实例表——账号 × 机器 × 源数据根的稳定映射，事件身份的一半。
- `usage_observations`：**观测日志**（只追加）——每次看到的源记录一行，fold 的输入。它是「重建」property test 的实际依据；保留期见 [ADR-0011](0011-存储生命周期.md)。
- `usage_observations`：**观测日志**（只追加）——每次看到的源记录一行，fold 的输入，也是「重建」property test 的实际依据；保留期见 [ADR-0011](0011-存储生命周期.md)。
- `usage_events`：**current projection**——每个 `(sourceInstanceId, eventKey)` 一行的当前状态；幂等与去重的根基（防 ccusage issue #19 式分支重复计数）。
- `conflict_observations`：冲突观测表——同坐标/跨流同键不同 payload 的显式留证（见「收敛契约」），禁止静默 last-write-wins。属观测层，与 `usage_observations` 同寿命、不外键引用投影层；"曾发生冲突"这一事实由投影层的 `has_conflict` 永久保留。
- `sessions` / `session_model_stats`：会话级聚合（整体与按模型两粒度）。**派生表**：任何时候可从 `usage_events` 全量重建，不作为权威数据；事件变更后按「受影响 sessionKey 局部重算」增量维护（`dirty_since` 持久标记），全量重建留作兜底。**空会话删除规则**：局部重算后无 counted 事件的会话行直接删除，不留空壳。
- `tool_calls`：工具调用子表（事件外键、childId、工具名、status、时长）。废弃"零 token 独立事件"（审查 §三 P1-9）。
- `event_charges`：非 token 计费子表（kind、quantity、unit、单价口径）——web search / code execution / premium-request 数 / AI-credit 等按次/按额度计费项可索引聚合，不再塞进 JSON 数组或成本列。
- `pending_messages`：流式未定稿消息的定稿状态机（OpenCode 中断轮次等，见「增量摄取」）。
- `ingest_errors`：摄取错误表（错误码、位置、payload hash/长度、计数）。**解析坏行/跳过行必须可见**（审查 §四 6）：源会清理历史，静默丢弃 = 永久丢弃。**永不存内容摘要**。
- `watermarks`：增量摄取游标（见「增量摄取」）。
- `quota_snapshots`：订阅配额窗口快照（含 provenance/ruleVersion/capacity/unit/confidence），见 [ADR-0008](0008-配额窗口.md)。
- `pricing_history`：带生效期（effectiveFrom/effectiveTo）的价格规则，见「成本所有权与可重算」。
- `schema_migrations`：迁移记录，`schema_version` 协商的权威来源（见架构总览·进程模型）。

### 收敛契约（二轮审查 §1 重写，替代旧「带 revision 的 upsert」）

旧契约被证伪：同 revision 不同 payload 时结果依到达顺序（不满足交换性）；byte offset / rowid / 拉取时刻都不是跨流或跨代的版本；「源终态完整扫描」与永久仓库冲突（源删除后终态不再包含事件）。新契约：

**事件身份 = `(sourceInstanceId, eventKey)`**。`source_instances` 把源类型 × 账号 × 机器 × 源数据根映射为稳定实例 ID：同一物理事件在不同实例间永不撞键，跨实例同 eventKey 也**不**互相去重（两台机器上的 Claude 用量本就是两笔消耗）。

**revision = `(originStream, streamGeneration, sourcePosition)`，仅同 originStream 且同 generation 内可比。** 字节偏移只在同一文件同一代内有序；rowid 只在同一数据库同一代内有序；`(time_updated, id)` 只在同一库内有序；API 页序只在同一拉取周期内有序。跨流、跨代的 position **没有任何序关系，禁止比较**——fork 文件间 offset 不可比；Cursor VACUUM 后旧代高 rowid 不能压新代；API 拉取时刻只是观测时刻。

**观测/投影两层模型**：每次看到的源记录是一条 **observation**，永久保留；`usage_events` 是由固定 observation 集合**决定论 fold** 出的 **current projection**（可标 `excluded`/`tombstoned`）。**缺席 ≠ 删除**：源终态扫描中未出现的事件不作废；只有源给出显式删除证据时才把 projection 标 `tombstoned`，observation 层永不删行。

**裁决规则**（fold 的定义，全部决定论、与到达顺序无关）：

1. 同流同代、position 更大、payloadHash 相同 → 重复观测，跳过。
2. 同流同代、position 更大、payloadHash 不同 → 流式重写的正常覆盖，更新 projection。
3. **同坐标（同流同代同 position）payloadHash 不同 → 冲突**：记 `conflict_observations`，projection 取 payloadHash 字典序较小者——源自身矛盾必须显式可见，**禁止静默 last-write-wins**。
4. **跨流/跨代同 (instance, eventKey)**（2026-08-03 修订，原文见本节末修订注记）：payloadHash 相同 → 复制型重复（fork/迁移/截断重读），去重。不同 → **先定流、再定代**：胜出流 = `originStream` 字典序最小者（跨流无自然序，字典序是决定论 tiebreak，双向留证 `conflict_observations`）；**胜出流内取其最大 `streamGeneration` 的终态**——同一流的 generation++ 意味着流身份重建（文件替换/截断重读），新代即该流的当前现实，属规则 2 同族的正常覆盖，不记冲突（代际断裂已由水位线可见）。
5. 败方 observation 不因裁决而删除——fold 可从 observation 层重建 projection（「重建」property test 的依据）。**该重建的定义域是观测保留窗口内**（[ADR-0011](0011-存储生命周期.md)）：窗口外的投影行标 `observations_pruned_at`，fold 不再对其生效。旧文的"永不物理删除"是无条件表述，与分层保留冲突，此处收窄为"不因裁决而删除，只因保留期而清理"。

实现形态：应用层先 SELECT 现有行，按上表分支（跳过 / 覆盖 / 冲突），在**单事务**内写出；`ON CONFLICT DO UPDATE` 仅作兜底，不作为裁决逻辑本身。

### 阶段二对抗复审的逐轮定案（2026-08-03 至 08-04）

**规则 4 原文被证伪**（旧「取 (流,代) 字典序最小」把二元组当独立流比较，同流截断重读后磁盘上唯一存在的新内容永远输给旧代——决定论成立但新鲜度倒置，属数据腐坏级缺陷）。修订后的"先定流、再定代"保持决定论，四场景收敛性不受影响。

**二轮修订（四条语义）**：

1. **冲突是观测集合的历史性质，不是当前终态的比较结果**：`has_conflict` 与冲突明细由集合中**曾构成的冲突对**派生（全配对闭包）——后续观测使当前终态一致**不消除**已构成的冲突；增量路径只补插永不删，重建路径从集合重新派生出同一批。（全配对是唯一同时满足"增量不删"与交换收敛的定义：组终态粒度对集合增长不单调，会在特定顺序丢对。推论：良性 fork 的中间草稿与复制终态也构成历史冲突，冲突行量级上升——由展示层两档对冲，见[组件规格](../design/组件规格.md) §9。）
2. **normalizer 三分裁决**：(a) 升级替换（同坐标同源 hash、更高版本）= 重归一化锚点的**正常路径**，替换 normalized、**不记 conflict**（整批重归一化会产生百万级"冲突"，把信号淹没）；(b) **同版本、同坐标同源 hash、normalized 不同 = 实现级分歧**：决定论 tiebreak（取 normalized 内容字典序较小者）+ **必记** `conflict_observations` kind=`normalizer-divergence`（first-wins 依到达顺序、违反交换收敛，不采纳）；(c) 低版本到达 → 函数首行短路跳过。
3. **收敛比较域精确化**：四场景"终态逐字节一致"的比较域 = fold 拥有的全部逻辑终态——所有表所有列，**排除代理自增 `id` 与 `sqlite_sequence`**；冲突行集合按全逻辑列规范排序作 multiset 比较。代理 id 只作行寻址，**禁止任何逻辑依赖**。重建 property 必须**真实清空** fold 拥有的投影/子表/冲突表/派生表后重放（pricing 三列保留），测试侧排除项与本条一字对应。
4. **pruned/frozen 边界（四入口统一）**：`observations_pruned_at` 非空的投影行**恒不可变**——ingest / normalizer 替换 / dirty 重算 / 全量重建四入口一律跳过；该键新到的观测照常入观测层，并记 `ingest_errors`（`pruned-key-reobserved`，计数合并）。`frozen_at` 非空的 sessions/rollups **恒不重算不删除**（零 counted 删除仅适用于非 frozen）；compact 的聚合写入为**按键整片重算的幂等写**且跳过 frozen 键。

**三轮微裁（时间与身份细则）**：冲突对身份 = **逻辑坐标**（两侧流/代/位置/hash），**不含 observed_at**；冲突行时间字段由当前集合**置值派生**（非 min 记忆——记忆型在跨版本替换抬高观测时间下增量停旧值而重建取新值）。normalizer 时间两条：观测行时间 = **胜者内容自身各次到达的 min**；divergence 证据行时间 = **全部同版本到达的 min 累积**（含胜者重复到达）。孤儿清除谓词 = 「键**不在** pruned 投影中」即随真清空消失。

**四轮定案（两项均为契约措辞缺陷，修在源头）**：

- **零触碰的域精确化**：跳过类结局的零触碰域 = **fold 拥有的持久状态 + 证据表**；**水位线明确排除**——它是流消费游标，跳过的观测同样消费了流位置，**必须照常推进**（否则降级 adapter 在同一位置永久打转）。
- **两条全称性质入约（P5/P6，与四场景同级）**：**P5 跳过零副作用**——凡结局为跳过类的调用，fold 态与证据表在调用前后逐字节不变（水位线按上条排除并断言推进）；**P6 证据正当性**——终态中每一条证据行 ⟺ 其契约谓词对（观测集合, 终态）成立，生成器持真值双向断言。**配套流程规则**：新增任何跳过路径或证据码，必须**同批**携带其 P5/P6 覆盖。

**五轮定案（两项均为验证机构缺陷，按类封死）**：

- **证据行字段全称置值条款**：一切证据行的**每一个字段**都是观测集合的置值派生——时间取既定 min 语义、payload_hash 类取构成到达集合的**字典序最小**、计数取集合基数；**禁止任何 first/last-wins 的到达序记忆**。
- **跳过类结局显式清单**：duplicate（同流重复观测）、**跨流/跨代同 hash 去重**、低版本到达——全部适用零触碰域（`updated_at` 在域内）。
- **P5/P6 构造规则**：P5 的结局分类必须取自 **P6 模型的独立判定**，禁止询问被测系统；P6 模型**只准从本 ADR 条文直译**构造，禁止参照实现行为——条文缺口使模型无从直译时，停下补条文，不许照抄实现。
- **补文**：证据行 = **聚合非代表元**（各字段各自独立从集合派生，不做元组配对）；**投影行时间字段 = 胜者派生**（非全集合 min/max——后者随集合增长必然移动，与同 hash 去重零触碰数学不相容）。

**六轮定案**：写判据 = **内容比较，非结局分类**——每次到达重 derive 投影候选，与现行投影**逐字节比较**（含冲突标志），未变即完全不写（不写行、不换子表、不标 dirty）；"胜者未变"指**胜者派生内容**未变，不是胜者坐标未变。**禁止任何 force-write 类旁路**（败方坐标的 normalizer 升级只改观测层）。

**2026-08-03 修订与追认（依据阶段二对抗评审的可复现实验，[阶段二-裁决](../reports/阶段二-裁决.md)）**：

- **规则 4 原文**（「各流终态全部保留，projection 取 `(originStream, streamGeneration)` 字典序最小流的终态」）**被证伪**：它把 (流, 代) 二元组当独立流比较，同流截断重读（generation++）后，磁盘上唯一存在的新内容永远输给旧代投影——决定论成立但新鲜度倒置，属数据腐坏级缺陷。修订后的"先定流、再定代"保持决定论（generation 是存储数据，与到达顺序无关），交换/乱序/重放/重建四场景收敛性不受影响。
- **观测层语义收窄（追认）**：观测坐标只追加；唯一的替换例外 = 同坐标同 payloadHash 的**更高 `normalizerVersion`**（重归一化锚点语义——旧行为的静默丢弃会使锚点永久失效），版本分歧记 `conflict_observations`（kind = normalizer-divergence 类）留证。
- **重建的列所有权读法（追认）**：「清空后重建」经与增量同一条 upsert/fold 路径重折叠，**pricing worker 独占列（computed 三列）在重建下同样不被触碰**——列所有权是跨路径不变量，不是增量路径的特例；收敛比对按所有权处理这三列。

**2026-08-03 二轮修订（阶段二对抗复审四项必须修复的语义裁决，[阶段二-复审](../reports/阶段二-复审.md)）**：

1. **冲突是观测集合的历史性质，不是当前终态的比较结果**：`has_conflict` 与冲突明细由**集合中曾存在的任何冲突构成对**（规则 3 同坐标异 hash、规则 4 跨流异 hash）派生——后续观测使当前终态一致**不消除**已构成的冲突；增量路径不得删除既有冲突行，重建路径从集合重新派生出同一批。这使"曾发生冲突永久可见"与"重建 = 增量"同时成立（旧实现按当前终态算标志，两者只能得一）。
2. **normalizer 三分裁决**：(a) 升级替换（同坐标同源 hash、更高版本）= 重归一化锚点的**正常路径**，替换 normalized、**不记 conflict**（整批重归一化会产生百万级"冲突"，把信号淹没在例行事务里；版本列即记录）；(b) **同版本、同坐标同源 hash、normalized 不同 = 实现级分歧信号**：决定论 tiebreak（取 normalized 内容字典序较小者），**必记** `conflict_observations` kind=`normalizer-divergence`——复审建议的"先到者保留"不采纳，first-wins 依到达顺序、违反交换收敛；(c) 低版本到达 → 跳过（锚点单调）。DDL 的 `conflict_kind` 白名单同步扩充。
3. **收敛比较域精确化**：四场景"终态逐字节一致"的比较域 = **fold 拥有的全部逻辑终态**——所有表所有列，**排除代理自增 `id` 与 `sqlite_sequence` 元表**；冲突行集合按规范排序（全逻辑列字典序）作 multiset 比较。代理 id 只作行寻址，**禁止任何逻辑依赖**（无外键引用、无游标语义）——物理 id 决定论买不到任何语义，却把 fold 耦合进插入顺序机制。重建 property 必须**真实清空** fold 拥有的投影/子表/冲突表/派生表后重放（pricing 三列保留），测试侧的排除必须与本条一字对应，不得自行扩大。（**2026-08-04 M1 追认**：**基础设施簿记表恒在域外**——`meta`（schema_version / data_version）由写事务层拥有而非 fold 拥有；交换/重放/重建的**提交次数**对同一观测集合必然不同，将 data_version 纳入比较域会使四场景对**任何实现**不可满足。[ADR-0019](0019-数据新鲜度与变更传播.md) 的代次递增与本条自此显式相容；"不得自行扩大"的约束对象精确化为 **fold 拥有的列**，簿记表的排除是定义而非扩大。）
**三轮微裁（2026-08-03，三轮复审四项的语义精确化——时间与身份细则）**：冲突对身份 = **逻辑坐标**（两侧流/代/位置/hash 等），**不含 observed_at**；冲突行时间字段由当前集合**置值派生**（非 min 记忆——记忆型在"跨版本替换抬高观测时间"下增量停旧值而重建取新值，破坏三路径一致）。normalizer 时间两条：观测行时间 = **胜者内容自身各次到达的 min**（不并败者时间，并了反序不可复现）；divergence 证据行时间 = **全部同版本到达的 min 累积**（含胜者重复到达）。孤儿清除谓词 = 「键**不在** pruned 投影中」即随真清空消失（pruned 键证据保留）。

**四轮定案（2026-08-03，四轮复审两项均为契约措辞缺陷，修在契约源头）**：

- **零触碰的域精确化**（替代三轮"全域零触碰"的过宽表述——过宽源自维护者上收措辞）：跳过类结局（duplicate / 低版本 / 任何不改变 fold 态的结局）的零触碰域 = **fold 拥有的持久状态 + 证据表**；**水位线明确排除**——它是流消费游标，跳过的观测同样消费了流位置，**必须照常推进**（否则降级 adapter 在同一位置永久打转；重放场景的 duplicate 本就是"跳过但推进"，两者语义必须一致）。
- **frozen-reactivated 谓词精确化**（替代"fold 实际执行"的模糊表述）：留证条件 = **该键投影发生实际写入（胜者变化）且所属会话 frozen**——跨流败方、duplicate、低版本等不改投影的到达一律不留证。
- **两条全称性质入约（P5/P6，与四场景同级的第一公民）**：
  **P5 跳过零副作用**——任意生成的观测序列中，凡结局为跳过类的调用，fold 态与证据表在调用前后逐字节不变（水位线按上条排除并断言推进）；
  **P6 证据正当性**——终态中每一条证据行（冲突/ingest_errors 各码）⟺ 其在本 ADR 中的定义谓词对（观测集合, 终态）成立：生成器持有真值，双向断言——无谓词支撑的证据行与谓词成立却缺失的证据行同为失败。
  **配套流程规则**：新增任何跳过路径或证据码，必须**同批**携带其 P5/P6 覆盖——只有定向反例回归的提交打回（写入 docs/开发流程.md 测试策略）。

**五轮定案（2026-08-04，终审两项均为验证机构缺陷而非引擎缺陷——按类封死，不做点裁决）**：

- **证据行字段全称置值条款**：一切证据行（冲突两类、normalizer-divergence、pruned-key-reobserved、frozen-session-reactivated 及未来任何证据码）的**每一个字段**都是观测集合的置值派生——时间取既定 min 语义、payload_hash 类取构成到达集合的**字典序最小**、计数取集合基数；**禁止任何 first/last-wins 的到达序记忆**。逐字段裁决到此终止：新证据码的字段语义若无法从本条推出，属契约缺口，停下补条文。
- **跳过类结局显式清单**：duplicate（同流重复观测）、**跨流/跨代同 hash 去重**、低版本到达——全部适用零触碰域（`updated_at` 在域内）；水位线照常推进。
- **P5/P6 构造规则（对验证机构自身的机构性约束）**：P5 的结局分类必须取自 **P6 模型的独立判定**，禁止询问被测系统——oracle 依赖 SUT 等于性质随实现一起错（五轮必修 1 的根因）；P6 模型**只准从本 ADR 条文直译**构造，禁止参照实现行为——条文缺口使模型无从直译时，停下补条文，不许照抄实现（五轮必修 2 的根因：payload_hash 语义当时缺文，模型作者抄了实现的 first-wins）。

**五轮修复的补文（2026-08-04，随 426dab7 上收）**：

- **证据行 = 聚合，非代表元**：置值条款下各字段**各自独立**从集合派生（hash 取字典序最小、len 取 MIN、first/last_seen 取 MIN/MAX……），不做"配对到某一代表到达"的元组派生——跨字段可能来自不同到达是聚合语义的自然结果；诊断需要单一到达全貌时查观测层。
- **投影行时间字段 = 胜者派生**：由当前胜者到达（集合置值）导出，非全集合 min/max——后者随集合增长必然移动，与"同 hash 去重零触碰"数学不相容；胜者派生是同时满足零触碰与集合纯度的唯一形态。配套守卫入约（2026-08-04 六轮措辞收紧）：**写判据 = 内容比较，非结局分类**——对每次到达重derive投影候选，与现行投影**逐字节比较**（含冲突标志），未变即完全不写（不写行、不换子表、不标 dirty）；"胜者未变"指**胜者派生内容**未变，不是胜者坐标未变。**禁止任何 force-write 类旁路**：败方坐标的 normalizer 升级只改观测层，投影候选不变即零触碰（六轮反例：升级败方却写 dirty_since，即此类旁路）。

4. **pruned/frozen 边界（四入口统一）**：`observations_pruned_at` 非空的投影行**恒不可变**——ingest/normalizer 替换/dirty 重算/全量重建四入口一律跳过；该键新到的观测照常入观测层（只追加），并记 `ingest_errors`（`pruned-key-reobserved`，计数合并）可见。`frozen_at` 非空的 sessions/rollups **恒不重算不删除**（dirty 扫描与全量重建排除之；零 counted 删除仅适用于非 frozen）；compact 的聚合写入为**按键整片重算的幂等写**且跳过 frozen 键——窗口外事件被重现再清理时，聚合不二次吸收。字面组合「frozen 会话又出现窗口内新事件」：事件照常入投影与（非 frozen 日的）日聚合，session 汇总保持定格，记 `frozen-session-reactivated` 可见项——是否需要解冻语义，留待 M1 实测出现后再裁，不预设。

**事务边界（硬约束）**：单事件写入是原子的——事件 upsert + 旧子表（`tool_calls`/`event_charges`）**集合删除** + 新子表插入 + **新旧两侧 sessionKey 的 dirty 标记** + 水位线推进，同一事务提交。事件跨 session 移动（upsert 改 sessionKey）必须同时 dirty 两端。崩溃恢复：`sessions.dirty_since` 是持久标记，重启后先清 dirty 队列再服务查询；水位线不越过未提交事件。

**2026-08-05 M1 对抗复审定案（四项语义裁决，[阶段四-复审](../reports/阶段四-复审.md)）**：

1. **API 周期 reconcile 的缺席键语义（B3）**：成功枚举的完整周期是 reconcile 边界——新代对旧代的**缺席键不得静默保留**：投影转 `excluded`（退出 counted，聚合与报表经 dirty 重算收缩），记证据 `api-reconcile-absent`（字段按置值条款派生）；观测层照旧只追加。「非空→空」与「非空→缺一键」同律。
2. **pending 源行消失（B4）**：pending 观测到时**持久化 position 与最后归一化 payload**（仅用量字段与元数据，不含对话内容——红线不破）；下一轮源行消失 → 以最后 payload 走陈旧定稿路径并记证据 `pending-vanished`；「水位线不越过未定稿 pending」的既有约束不变。生产 OpenCode/Cursor adapter 仍属阶段八，但三机制 + pending 的**端到端合成回归**（模拟完整发布轮含行消失情形）属 M1 阻断内交付。
3. **data_version 谓词域 = fold 域 ∪ health 域（D1）**：递增谓词从「fold 可见变化」扩为「任何查询面可见变化」——`ingest_errors`、水位线戳、pending 等诊断可见写同样递增（事件 scope 标 `health`；批内共享批提交的一次递增）；**不另立 health 版本**（新机制未过必要性检验）。[ADR-0019](0019-数据新鲜度与变更传播.md) 同步括注。
4. **冻结会话的总账语义（F1——完成上文「留待 M1 实测出现后再裁」的裁决）**：`frozen_at` 定格的是**汇总行**，不是总账真值。报表总账 = 非冻结会话汇总 + 冻结会话定格汇总 + **冻结后到达事件**（第四腿；识别谓词由实现选定，验收 = reactivation 情形下报表与事件级真值逐字段相等）。仍不引入解冻语义。
5. **胜者坐标 = 最小坐标规范代表元，结局三分（G1 修复的语义定案，2026-08-05 批 1 后追认）**：投影坐标列 = 携带胜者派生内容的观测中**坐标全序最小者**（集合纯函数，坐标在比较域内保留——移出比较域将迫使"先到者留"式到达序记忆，违反置值条款，弃）。由此结局精确化为**三类**：(a) **跳过类零触碰** = 不改变规范代表元的同内容到达（更大坐标副本——五轮清单的原两例即此类）；(b) **规范化写** = 改变代表元的更小坐标同内容到达（乱序/重建先大后小）——仅坐标列与胜者时间列按置值移动，**内容谓词域（子表/dirty/证据/reactivation）恒零触碰**，`data_version` 照常递增；(c) **内容写** = 胜者派生内容改变（含反向守卫：更高 position 的不同内容必须真正覆盖）。P5/P6 模型按三分独立判定；三难取舍（域内 × 集合纯函数 × 全向零触碰不可兼得）以牺牲 (b) 类的行零触碰为解，收敛四场景在此形态下成立。
6. **冻结会话 = 不可变基线 + 尾账（批 3 冲突裁决，2026-08-05）**——F1 第四腿与 C1 冻结零触碰、ADR-0015 禁永久 pending 三者的相容形态：
   - **基线成员按到达持久标记**：compact 冻结会话时，为当时已计入汇总的事件落永久标记（迁移 v3，append-only；判据 = fold 到达是否早于冻结，**禁用源时间戳判**——迟到旧事件是新到达，属尾侧）；
   - **零触碰域 = 基线事件全列**（含 computed 三列，reprice/一切入口跳过）；**尾侧事件走完整正常生命周期**：照常计价（frozen guard 不得挡 worker——这就是本次冲突的解）、照常入非 frozen 日聚合、记 `frozen-session-reactivated` 证据，但**不 dirty 该冻结会话**（汇总行恒定格）；
   - **尾账**：compact 在**删除过期尾侧事件的同一事务**内将其累加进该会话的尾账行（exactly-once 由删除触发保证）；第四腿 = 尾账 + 存活尾侧事件，验收不变（reactivation 情形逐字段等于事件级真值）；
   - **冻结与计价解耦（点 5 重裁，2026-08-05 批 3 上报后修订——原"pending 不冻结"字面形态使存储回收被计价子系统健康度挟持：全库默认 pending、不可计价模型永久 pending 皆致回收停摆，且安全形态必须连过期删除一起推迟 → 库无界增长，弃）**：(a) **存储生命周期永不被计价无限期推迟**——compact 恒可推进；(b) **注入式尽力排序**（执行者方案 2 采纳）：compact 入口接受计价扫描能力（trait 注入，CLI/daemon 提供，公共签名改动批准），冻结阶段前尽力清 pending；(c) **冻结时仍 pending 的基线事件在冻结事务内落章 `skipped`**（金额与 pricing_version 保持 NULL）——这是列所有权墙上唯一的受裁边界穿越：事件此刻永久退出 worker 域，落章属于冻结自身，此后零触碰绝对；(d) 该会话以 `has_partial_cost=1` 定格（F2 展示「部分」），诚实降级取代无限期等待；(e) 执行者已实现的"过期删除与冻结同批"安全形态保留并**启用**（撤销空临时表停用）。迁移编号以实际序为准（v4——定案原文"v3"是裁决时点序号，语义=新增 append-only 迁移）；
   - 尾账行归 compact 独占、只累加不重算（尾侧存活事件仍在窗口内时不预吸收）；P5/P6 零触碰域与证据模型随基线标记列同批扩展。
7. **回收后重读的防护（定案 7，2026-08-05 二轮对抗复审证伪定案 6 的 exactly-once 论证后补）**——定案 6 把尾账的 exactly-once 论证为「删除即触发器，只累加的账不可能重复吸收已取走的行」，**该论证的隐含前提「被删事件永不回来」为假**：本 ADR《增量摄取》规定文件替换/截断、DB 重建或 VACUUM、游标格式升级一律 `generation++` 并归零 position **全量重读**，而「幂等由事件身份保证」的身份载体（投影行）恰已被保留期回收——复审实测三条反例（尾侧吸收后重读致总账 4≠3、连续三轮重读致尾账 [2,3,4]、已封存基线过期删除后重读致总账 3≠2），且**不可纠正**（尾账只累加、冻结会话永不重算）。该缺陷只存在于**只累加/不重算**的结构（尾账、冻结汇总）；非冻结会话按现存事件整片重算，天然免疫。
   - **不变量**：**已永久计入（冻结汇总或尾账）且随后被回收的事件，其再次到达必须零触碰**——不得二次计入任何永久层。
   - **约束**：机制须**存储有界**（禁为每个曾存在的事件永久保留标识——违反 [ADR-0011](0011-存储生命周期.md) 永久层年增预算）；须可判定（禁概率结构）；**不可区分「迟到的真新事件」与「重读的已计入事件」时，取不二次计入**——多计是不可纠正的资金错算，少计至少在证据层可见，这是本项目「缺口可见而非虚报」原则在此处的应用。
   - **留证（新证据码 `reclaimed-key-reobserved`）**：因本防护而未计入的到达必须留证，使少计可见；字段按置值条款与下方补文表。
   - **机制由实现者选定并论证**（候选：按 `source_instance` 维护「已回收时间水位」O(1) 形态；窄墓碑表 + 时间界；或等价形态）。选定形态须在报告中给出存储量级估算与「真新事件被判为重读」的可见性说明。F1 的 reactivation 验收随之精确化为：**时间水位之上**的新事件必须逐字段计入。
   - ~~**已选定形态（2026-08-05 实现并追认）**：`source_reclaim_watermarks`（迁移 v5，每源实例一行）……判据读派生胜者的 timestamp，故为观测集合的纯函数，四场景收敛不破。~~ **（2026-08-05 三轮对抗复审证伪，撤回）**
   - **时间水位形态判定为不可用（三轮复审 MF-1）**：判据确实读派生胜者，但**派生胜者的 timestamp 本身在动**——`usage_observations` 按各行自己的 `event_timestamp` 剪枝，观测集合被裁剪后胜者换人、时间戳上移，而水位不动。复审复现四条，最短形态跑在**出厂默认 90/180** 上：一个键有两条时间戳相差超观测窗的观测（同坐标异 hash，即规则 3 冲突，契约本就为它建模），fold 胜者是旧的那条；观测剪枝删掉胜者留下败者；该键下一次 refold 选出败者，其时间戳在水位之上 → 投影重建 → 经尾账永久双计，且 `reclaimed-key-reobserved` 计数为 0（代价连可见性都没有）。另一条复现直接给出增量腿与重建腿终态不一致，故"四场景收敛不破"一句为假，一并撤回。**根因一般化：任何以「可随观测集合剪枝而移动的派生量」为判据的形态都不成立；判据必须挂在剪枝不变量上——事件身份 `(source_instance_id, event_key)` 是唯一这样的量。**
   - **机制约束修订（替代上文"禁概率结构"一句）**：判别器必须以**事件身份**为输入。存储有界仍是硬约束，因此**允许单边误差的紧凑结构**（如 Bloom 类）——条件是误差方向单边且安全：对「已计入」**不得有假阴性**（故绝不双计），假阳性（把真新事件判为重读）允许存在且**必须留 `reclaimed-key-reobserved` 证据**，与本定案「不可区分时取不二次计入、少计可见」的取舍方向一致。选定形态须给出：假阳性率与容量规划、随事件量增长的存储曲线、以及该曲线与 [ADR-0011](0011-存储生命周期.md) 永久层预算的对账。
   - **覆盖范围（三轮复审 MF-2）**：判别器的覆盖面 = **一切永久层计入**，含 `session_key IS NULL` 的事件——它们不进会话汇总，但其日聚合键同样被 compact 定格，属永久计入。现实现以 `session_key IS NOT NULL` 过滤水位推进而删除无此过滤，两侧不自洽；替代形态须对齐。
   - **已选定形态（2026-08-05 三轮后实现，维护者追认）**：按 `(source_instance_id, event_key)` 键控的**分片可扩展 Bloom 过滤器**（`crates/tokly-core/src/reclaimed.rs`，迁移 v5 就地替换）。键是剪枝不变量，故裁决不随「剪枝把冲突败方提升为胜者」而移动；只置位、只追加切片，**无假阴性**（绝不双计）；链式假阳性率封顶 2⁻¹⁵ 且与链长无关；假阳性即少计，恒留 `reclaimed-key-reobserved`。约 3.5–7 B/身份 → 按 ADR-0011 六源上限约 11–21 MB/年，在永久层 <50 MB/年 预算内。推进侧与删除侧**共用同一 SQL 谓词**（`STRANDED_ROWS`），两侧不可结构性分叉。增量腿 = 重建腿由构造成立。
   - **验证机构要求（三轮复审的覆盖缝教训）**：MF-1 未被前两轮抓到的原因是 P5/P6 用手写 SQL 模拟回收，**从未驱动 compact 侧真正的推进查询**。因此立为通则：**凡影响永久层的写路径，其真实查询必须进性质模型**，不得以模型内重写的等价 SQL 替代。为此允许暴露仅供模型驱动的公共接缝（如 `reclaim_expired_projections`），条件是它与产品路径**共用同一谓词**而非各写一份。
   - **零触碰的域边界（②的追认，2026-08-05）**：本防护与 pruned/frozen 三者同律——**零触碰的域是投影层与永久层，不含观测层与冲突证据**。被拒到达照常入观测层（只追加），并**照常参与冲突仲裁**：冲突是观测集合的历史性质（见上文二轮修订 1），与投影是否接纳无关。因此「回收使基线期观测重新进入 fold 域」不是契约缺口——观测恒在集合内，只是不提升为投影（实现称 shadow 集合，仲裁可见、fold 运行时才提升，与本条一致）。
   - **`frozen-session-reactivated` 的会话归属（①的追认，2026-08-05）**：该证据行的 session 取**投影胜者**的 session，非到达观测的 session。依据两条既有条款：证据行字段全称置值派生、投影行时间字段 = 胜者派生；且事件可跨 session 移动（见「事务边界」的双端 dirty 规定），到达观测的 session 未必是终态归属。定案 7 使该路径首次可达，故在此明确。

**幂等 = 收敛性，验收用 property tests（第一测试公民）**：对同一固定 observation 集合，四场景终态必须逐字节一致——**交换**（两批观测互换入库顺序）、**乱序**（任意重排）、**重放**（同一批重复导入 N 次）、**重建**（清空 projection/子表/派生表后从 observation 层 fold 重建 = 增量摄取终态）。「同一数据导入两次 = 导入一次」只是重放场景的特例。测试策略详见docs/开发流程.md。

### 增量摄取：水位线与三类源操作语义（二轮审查 §2）

水位线表 `watermarks`：PK = `(source_instance_id, channel, stream_key, kind)`；行内另存 `cursor_version` / `generation` / `position` / `file_id` / `header_hash`。PK 四元组加行内 cursor_version、generation 合称**逻辑游标六元组**——position 只在同六元组内可比；身份断裂（文件替换、DB 重建/VACUUM、游标格式升级）→ `generation++` 并归零 position 全量重读。

- **JSONL 类**（Claude / Codex / Gemini / Copilot 文件通道）：比对 mtime/大小 → 字节偏移续读；每轮只消费到本轮打开句柄首次取到的 `size` 边界内最后一个完整换行（扫描中 append 留待下轮，禁止 position 越过其 change stamp 描述的字节边界）；**完整非法行**记 `ingest_errors`（错误码/hash/长度/位置）后推进，**无换行残尾**不推进；截断/替换（大小回退、file_id/header_hash 不连续，或游标已在 EOF 而同长文件的 change stamp 变化）→ `generation++` 全量重读，幂等由事件身份保证。普通 append 的大小增长不得因 change stamp 变化误增代；position 与对应 change stamp 必须同事务推进，禁止留下新 EOF + 旧 stamp 的崩溃窗口。
- **SQLite 活库类**（OpenCode / Cursor）：**每轮在单一只读事务的一致快照内严格向前分页**（轮内 cursor 不回退）；**跨轮 checkpoint 用 safety horizon**（重叠回退窗口，重复由 upsert 吸收）**+ 周期全量 reconciliation** 兜底。「跨轮 checkpoint 回退」与「轮内严格分页」是两种机制，**分开实现、禁止混用**（二轮审查：2 秒回退仅缓解；无漏还需固定快照 + 尾部安全区 + 周期 reconciliation）。Cursor 额外两条：**用 SQLite backup API 建副本**（含 WAL 的一致快照，替代活动 WAL 下可能撕裂的裸 cp）+ **DB generation 追踪**（DB 头 change counter + schema cookie + 首 N 行 (rowid,key) 采样哈希），代际断裂即全量重扫。旧 generation 的 pending payload 仍可定稿，但其 position 与新代不可比，**禁止用旧 pending position 推进新代水位线**；新代 checkpoint 只能由新快照本身派生。
- **API/分页类**（Copilot C/D 通道）：整周期先写 staging；页号从 0 连续，调用者收到并显式登记 provider 的完整枚举终止后，才允许**全部页成功后单事务 reconcile 发布**；任何页失败、缺页或未终止的成功前缀均不发布（保留上一周期 projection）；近期周期滚动重拉，历史周期成功后封存。

三个曾宣称"已修"的静默丢数点，真实状态与修法（二轮审查 §2；[风险登记](../风险登记.md) R4 已同步更正）：

1. **Cursor VACUUM 后 rowid 重编——未修，方案已定待实现**：旧「水位线 rowid→key 反查」被证伪（`UNIQUE ON CONFLICT REPLACE` 是 delete+insert，会把锚点 key 移到新 rowid 造成误报；全扫后低 rowid 又被旧 revision 拒绝）。真实修法：backup API 副本 + DB generation（上文），rowid 只在同 generation 内作 position。
2. **OpenCode 中断轮次定稿——未修，方案已定待实现**：过滤未定稿行后继续推进水位线 = 永久丢轮次。必须走 `pending_messages` 状态机：未定稿消息按 id 登记，每轮先按 id 重读；`finish` 非空 → 定稿；`error` 非空 → 定稿（**error 但已有 token 的轮次照常计数**）；**15 分钟**无更新 → 陈旧定稿。**水位线不得越过任何 pending id。**
3. **页边界同毫秒漏行——仅缓解，方案已定待实现**：轮内严格分页（单只读事务快照内 `(time_updated, id)` 向前）+ 跨轮 safety horizon 重叠 + 周期 reconciliation，三者齐备才算修。

OpenCode 的 SQLite 以 `mode=ro` + `busy_timeout` 只读打开，不与运行中的实例争锁；不用 `immutable=1` 读活库（活库 WAL 下可能读到撕裂页；`immutable=1` 仅对 backup API 产出的静态副本安全，见docs/sources/opencode.md、docs/sources/cursor.md）。

### 成本所有权与可重算（二轮审查 §1 重写）

旧「双列 + 单一 costBasis」模型被证伪：单一 costBasis 无法同时标注两列；`reprice WHERE costBasis='computed'` 漏掉 native/estimated 行，永远无法形成 native/computed 差异；adapter 重扫全列 upsert 会把 reprice 后的 computed 值覆盖回旧值；"用最新价重算"与"按事件发生时有效价格"直接冲突。新模型按**列所有权**拆分：

| 列 | 所有者 | 语义 |
|---|---|---|
| `tokenQuality` / `tokenCoverage` | adapter | token 数据质量与不可得/低覆盖维度（0 不冒充"已确认没有"） |
| `costNativeMicroUSD` / `nativeCostKind` / `nativeCostProvider` | **adapter 独占** | 源原生成本及口径（provider 账单 / 工具自算 / premium-request / AI-credit） |
| `costComputedMicroUSD` / `computedCostStatus` / `pricingVersion` | **pricing worker 独占** | 计价结果；adapter 重扫 upsert **不含这些列**，重扫永不覆盖计价结果 |
| `pricingEligibility` | adapter 设定 | reprice 选择依据：standard / estimated-tokens / disabled |
| `displayPolicy` | adapter 设定 | UI 展示策略（双列分别展示、何者优先、估算样式） |

规则：

1. **reprice 按 `pricingEligibility` 选事件**（不再按 costBasis）——native 行同样重算，native/computed 差异可展示（OpenCode 历史低估 bug #28494 因此变成可展示的差异化提示而非数据缺陷）；estimated-tokens 行重算但全程带估算标注。
2. **按事件时点计价**：用 `event.timestamp` 匹配 `pricing_history` 的 `[effectiveFrom, effectiveTo)` 区间取价，禁止"最新价回算历史"（[风险登记](../风险登记.md) R2 的落地）。远程价目无历史时自建覆盖层（按抓取时间归档价目快照）。**首次安装之前的事件没有价目历史可匹配**——按最早快照计价并标 `computedCostStatus='priced-at-snapshot'`；舍入与精度规则见 [ADR-0015](0015-计价精度.md)。**首次安装之前的事件没有价目历史可匹配**——它们按最早快照计价并标 `computedCostStatus='priced-at-snapshot'`，缺口可见；舍入与精度规则见 [ADR-0015](0015-计价精度.md)。
3. **OpenCode 的 native 是工具按 models.dev 自算**（`nativeCostKind='tool-computed'`、`nativeCostProvider='opencode:models.dev'`），**不是 provider 账单**——UI 不得写"原生/官方成本"，按 displayPolicy 展示 native vs computed 差异。
4. 模型匹配不到 → `costComputedMicroUSD=NULL`、`computedCostStatus='unmatched'`，缺口可见而非虚报。
5. 聚合只算 `status='counted'`；日界按本地时区（UTC 存储，查询层换算）；native/computed **双列分别展示**，不合并成单数。

**保鲜链**（不变）：bundled 快照（随版本发布更新）< 远程 LiteLLM 缓存（stale-while-revalidate：缓存立即可用，后台刷新；刷新失败继续用陈旧缓存并标记 `stale`，UI 可见）< 用户覆盖 `pricing.json`。任何一层失效都不阻塞使用。每条计价结果另存 `pricingVersion`（远程表取抓取时间/etag，内置快照取包版本）。

`rawUsage` **仅在有损映射时存**（源指标无法无损落入归一化列时才保留原始 JSON 兜底）——reprice 从归一化 token 列重算，pricing 层不应懂六种源格式，且源文件 30 天后即消失。

### 存储类型约定（硬约束，二轮审查 §2）

- **时间**：一律 INTEGER **epoch_ms**（UTC）。
- **金额**：一律 INTEGER **micro-USD**（10⁻⁶ 美元）——REAL 聚合漂移不可接受。同理，`event_charges.quantity` 等**会被求和的数量**也不得用 REAL（存放大整数倍数并记单位倍率）。
- **token**：非负 INTEGER，CHECK 约束强制。
- **全表 `STRICT`**（2026-08-03 增补）：SQLite 默认动态类型，往 INTEGER 列写字符串会成功入库而 CHECK 拦不住——"由 DDL 固化，不靠代码自觉"只有在 STRICT 表下才真正成立。附带收益：STRICT 表的 PRIMARY KEY 列隐含 NOT NULL，消除普通表中"PK 列可为 NULL 导致去重失效"的整类缺陷。
- 以上由 [数据库-schema](../数据库-schema.md) 的 DDL 固化。

### 资源纪律（硬约束）

数据持续增长不得拖累用户机器：

- **只存指标，不存内容**：`usage_events` 只含时间、模型、token 计数、成本，**永不存储对话内容**；`ingest_errors` 只存错误码/位置/hash/长度/计数。存储预算修正（审查 §四 7）：早期「每条约 500 字节、数年百 MB 级」的口径不含索引与页开销，乐观 5–10 倍；现实预估为**三年重度使用 GB 级**。缓解措施：计价字段升一等列后 `rawUsage` 仅在有损映射时存；派生表与明细表可重建/清理；提供 `tokly compact`（VACUUM + 旧 `ingest_errors` 清理）。
- **流式解析**：JSONL 按行流式读取，内存占用恒定，不随文件大小增长；禁止整文件读入内存。
- **有界扫描**：增量摄取只读水位线之后的字节；全量重扫仅限首次导入与水位线失效（generation 断裂）。
- **查询有界**：UI 查询一律走聚合与索引，禁止全表扫描进内存再计算。

### 数据分层保留 —— 已被 [ADR-0011](0011-存储生命周期.md) 取代（2026-08-03）

旧节（raw 90 天 + 日聚合永久）有三处不成立，故整体移交 ADR-0011 重写：

1. 与本 ADR 收敛契约的「observation 永久保留」直接冲突，且在 `foreign_keys=ON` 下 compact 会被 `conflict_observations` 的外键拒绝——**DDL 层就执行不了**；
2. 「清理不触碰 sessions 汇总」使 `sessions` 从派生表变成不可重建的权威表，与本 ADR 对派生表的定义矛盾；
3. `tool_calls` 随事件级联删除而日聚合无工具维度，"工具调用级分析"被静默砍到保留期内。

新模型为观测 / 投影 / 会话汇总 / 日聚合四层各自定寿命，并新增 `daily_tool_rollups`；存储 SLO 由「每年 < 100MB」改为「稳态 < 1 GB、永久层年增 < 50 MB」。**引用分层保留一律指向 ADR-0011，不引本节。**

## 后果

- 历史数据问题从架构上解决：首次导入即回填本地全部已有历史，之后增量保鲜。
- 收敛契约的代价是 revision 三元组、冲突表与决定论 fold 的复杂度，换来六源在**交换/乱序/重放/重建**下的可证明收敛；收敛性 property tests 取代朴素的「导入两次」测试（测试策略见docs/开发流程.md）。
- 成本五列拆分使计价可重入：adapter 重扫与 pricing worker 互不覆盖；reprice 按事件时点生效价重算，历史成本永远可修正且不被污染。
- 冲突不再被静默吞掉：所有 last-write-wins 的诱惑路径都被 `conflict_observations` 显式化，坏行被 `ingest_errors` 显式化。
- 存储预算从「百 MB 级」修正为 GB 级现实预估后，资源纪律从口号变为需要主动管理的约束（rawUsage 按需存储、compact 命令）。
- 任何 UI 查询都打在本地 SQLite 上，亚秒响应，无需缓存层。
- adapter 开发模板固定：格式文档（docs/sources/）→ 解析器 → golden fixtures → 能力声明。

## 未决缺口：实例身份稳定性（2026-08-05 三轮复审 S-5 立案，路由阶段八）

`source_instances.id` = `(source, account, machine, data_root)` 的哈希。adapter **渐进发现** account（先不知道、后学到）会使同一物理源换 id，而**几乎所有结构都以它键控**——`watermarks`、`usage_events` 主键、`sessions`、日聚合、尾账、定案 7 判别器。后果是整段历史在新 id 下重新计入（复审实测 report total = 3 / truth 2），**且零 compaction 即可复现**——比定案 7 覆盖的回收窗口宽得多。

**判定**：不在 M1 内修。它是 adapter 侧的身份形成问题，而 M1 只有一个 adapter；在定案 7 内打补丁是有害的半修（判别器换 id 后同样空白，治标不治本）。**路由阶段八（adapter 成熟期）独立裁决**。

**倾向方向**（供阶段八起点，非定案）：身份改为 `(source, machine, data_root)`，`account` 降为**可变属性列**；account 变化记为属性变更并留证，不产生新实例。需在阶段八一并回答：同机同 data_root 下真实切换账号（登出换号）应合并还是分离——这正是把 account 移出身份要付的代价，须以真实多源数据判定。

**M1 内的最低要求（缺口可见原则）**：`tokly doctor` 增一项健康检查——同 `(source, machine, data_root)` 出现于多个实例 id 时报告为发现项，使该缺口在被修复前**至少可见**，不静默双计。

## 2026-08-05 M1 对抗复审证据字段补文

五轮定案的置值条款不足以唯一推出 B3/B4 新证据码在 `ingest_errors` 每一列的映射，现补齐如下；P6 只按本表直译，不得参照实现反推：

| error_code | stream_key | source_position | detail_key | payload_hash | payload_len | 时间与计数 |
|---|---|---|---|---|---|---|
| `api-reconcile-absent` | API 周期的 `originStream`（端点 + 参数） | `streamGeneration` 十进制 + `:` + 周期 checkpoint 的 canonical position | 缺席的 `eventKey` | canonical excluded `UsageEvent` JSON UTF-8 字节的 SHA-256；同证据集合取字典序最小 | 同一 canonical JSON 的 UTF-8 字节数；同证据集合取最小 | `first_seen_at=MIN`、`last_seen_at=MAX`、`occurrence_count` 为不同合成 observation 的集合基数；同一 observation 重放不计数、不改时间 |
| `pending-vanished` | pending 行持久化的 `originStream` | pending 行持久化的 canonical SQLite position | `pendingKey` | pending 行持久化的最后 payload hash | pending 行持久化的 `UsageEvent` JSON UTF-8 字节数 | 消失定稿一次即删 pending，故集合基数为 1；首次与末次时间均为该原子提交的定稿时刻 |
| `reclaimed-key-reobserved` | 到达观测的 `originStream` | 到达观测的 canonical position | 该 `eventKey` | **到达观测的源 payload SHA-256**（即 `usage_observations.payload_hash`，与 schema 该列语义一致）；同证据集合取字典序最小 | **同一源 payload 的 UTF-8 字节数**；同证据集合取最小 | `first_seen_at=MIN`、`last_seen_at=MAX`、`occurrence_count` 为不同 observation 的集合基数；同一 observation 重放不计数、不改时间 |

**两列同源原则（2026-08-05 三轮复审 MF-3 修订）**：`payload_hash` 与 `payload_len` **必须描述同一个对象**，否则消费者无法互验。凡存在真实到达观测的证据码，两列一律描述**该观测的源 payload**（与 `usage_observations.payload_hash`「源 payload 的 sha256」同义）；`api-reconcile-absent` 是唯一例外——缺席键没有到达观测，两列改描述 canonical excluded `UsageEvent` JSON。初版 `reclaimed-key-reobserved` 行把 hash 绑在 canonical JSON、实现又把 len 写成 canonical JSON 长度而 hash 写源 payload，两侧各错一半，现按本原则统一。**两者缺一时置 NULL，禁止用另一对象的值填充**（NULL 是诚实的"取不到"，混填是静默的自相矛盾）——`pending-vanished`（pending 行只持久化了 hash 未存长度）与 `pruned-key-reobserved` 当前即以 len=NULL 落地，属合规形态；pending 恢复字段下次修订时补存长度。**验收要求**：该项回归必须对**契约**求值（独立算出期望值），不得断言 `row.payload_hash == obs.payload_hash` 式的对实现求值——后者永远分辨不出此类偏差。

`pending_messages` 的 v3 恢复字段在 schema 升级时允许为 NULL，仅用于无从补造 payload 的旧未决行；v3 起的新写入必须六列（origin stream / generation / position / normalizer version / observed time / normalized payload）成组非空。旧行若下一轮仍能按 id 读到，立即以当前观测补齐；若源行也已消失，返回显式不可恢复错误并保持 pending 与水位线不动，禁止静默删除或伪造用量。

## 2026-08-05 定案 6 的验证机构补文（点 6 规格，P6 只按本节直译）

定案 6 引入的基线/尾侧二分在 P5 结局分类与 P6 证据谓词上都是**新的一类**，模型必须随之扩展；执行者已核实零触碰域因定义为「全列快照」而自动纳入 `frozen_baseline_at`，无需改域。要补的是判定：

1. **P5 结局分类增第四类：基线键跳过。** 投影行 `frozen_baseline_at` 非空的键上，任何新到达一律零触碰（含 computed 三列）——它与 `pruned` 跳过是**两条独立边界**，不得合并判定：pruned 键留 `pruned-key-reobserved` 证据，**基线键不留该证据**（它未被清理，只是已封存）。模型判定序：pruned 优先，其次基线，其次定案 5 的三分。
2. **基线键跳过的证据面 = 空。** 冻结会话上的新到达按其归属分流：属基线键 → 零触碰零证据；属该会话的**新事件键** → 尾侧路径，记 `frozen-session-reactivated`（既有码，字段照置值条款）。P6 双向断言据此写：基线键上出现任何证据行即失败，尾侧新键缺失 reactivation 证据亦失败。
3. **`skipped` 三因的证据枚举**：`pricing_eligibility` 判定、配置关闭、**生命周期封存**（[ADR-0015](0015-计价精度.md)）。第三因的谓词 = 「该事件在冻结事务中成为基线成员且当时 `computed_cost_status='pending'`」⟺ 终态 `skipped` 且 **`frozen_baseline_at` 非空** 且金额与 `pricing_version` 均 NULL。前两因的金额列语义不受本条影响。
   **2026-08-05 修订（执行者证伪，维护者追认）**：初版右侧写作「…且所属会话 `has_partial_cost=1`」，**该双条件为假**——第一因（`pricing_eligibility` 判定不计价）的事件落在任何部分计价会话中同样满足该右侧，故右侧不能唯一识别第三因。修正为以 `frozen_baseline_at` 非空作判别项（封存身份本身才是区分特征）；会话的 `has_partial_cost` 是**后果**不是**判据**，从右侧移除。实现已按此收窄并在测试中明示，与本条一致。
   **第二因（配置关闭计价）在 M1 为空析取**：尚无关闭计价的配置键，故 P6 对该因的覆盖为空**是正确的，不是缺口**；写入者随配置面落地（M2）后补，届时同批带 P6 覆盖（流程规则照旧）。
4. **生成器语料要求**：必须能产出「先冻结、后到达」序列——至少覆盖 (a) 基线键上的同内容重放、(b) 基线键上的更高 position 不同内容（仍须零触碰，这是与定案 5 (c) 类的关键分界）、(c) 冻结会话的全新事件键（尾侧）、(d) 冻结时会话内既有 pending 事件（触发封存落章）。四类各自的期望终态由上文 1–3 直译得出。


   - **判据的最终形态（MF-4 重裁，2026-08-05 四轮对抗复审证伪「由构造成立」）**：三轮换成身份键控后，实现仍把判据写作 `projection_absent && was_reclaimed(identity)`——**第一个合取项不是剪枝不变量**：`projection_absent` 就是「哪些投影恰好存活」，而全量重建的作用正是把它们全删再重折。复审实测：判别器对一个**投影仍存活**的键给出假阳性时，增量腿正常接受、重建腿把投影/会话汇总/日聚合三层同时归零，且 `store.rs:1210` 的重建路径丢弃 `FoldOutcome.reclaimed`、**一行证据都不写**——这直接打掉本定案给假阳性背书的那半条理由（「少计可见」）。按 1/14,500 实测率与 ADR-0011 投影层上界，任一时刻约百个存活投影处于「下一次重建即消失」状态。
     **定案**：(i) **判据 = 身份单项**（`was_reclaimed(identity)`），不得含任何随重建/剪枝移动的合取项；(ii) `projection_absent` 从判据移出，改作**清除范围**的守卫——被判别器拒绝的键，其投影行**并入既有的"重建清除例外类"**（与 rule 4 的 `observations_pruned_at`、定案 6 的 `frozen_baseline_at` 同类：四入口一律跳过、不清除也不重建），两腿由此真正一致；(iii) **一切腿都必须落证据**——重建腿、`adjudicate` 分支等任何丢弃 `FoldOutcome.reclaimed` 的路径一律补齐，或就地注释论证为何该处不落（同坐标同 hash 属同一观测重放，按补文不计数）。
   - **FPR 数值追认作废（四轮实测证伪）**：「链式 FPR 封顶 2⁻¹⁵」被三次独立测量否定，实测约 **1/14,500（≈2.2×）**；机制已定位为双散列的 `h2` 只强制为奇数而片宽非 2 的幂（`185×8=1480=2³·5·37`），`gcd(h2,width)` 落在大奇因子上时 k 个下标塌缩成 8–15 个互异位（约千分之一身份只检 8 位）。**裁决：修几何而非降指标**——片宽取 2 的幂使其与奇 `h2` 互质（或改用增强双散列 `h1+j·h2+j²`），使 2⁻¹⁵ 成为真实上界；该数字不是装饰，它同时是本定案的少计率、ADR-0011 存储对账与 MF-4 触发率的共同输入。
   - **共用谓词的字面兑现**：上文「推进侧与删除侧共用同一 SQL 谓词」为**待兑现要求**，复审实测删除侧是手写的第二份同义 SQL（差 `status='counted'`）。差异须做成**参数**而非第二份文本——MF-2 的失败模式正是两份 SQL 各自演化。
   - **源头两列不同源的既有例外**：Claude adapter 对 subagent 文件取 `payload_hash = SHA256(payload ‖ 0x1f ‖ agent)` 而 `payload_len = payload.len()`，两列在**源头**即描述不同对象。该偏离对 fold 去重前提是必要的（同一 payload 归属不同 agent 必须区分），故**记为两列同源原则的既有例外**并在此明示，不作为缺陷；新增证据码不得援引本例外。
   - **观测层统一律（2026-08-05 四轮后定案；P6 红灯的契约根因）**：一切零触碰类——rule 4 的 `pruned`、定案 6 的 `baseline`、定案 7 的 `reclaimed`——**只跳过投影层与永久层的写入，不跳过观测层**。到达一律：入观测层（只追加）、参与**同坐标裁定**（normalizer 升级替换、divergence、规则 3/4 冲突派生）、按补文落各自证据。实现若在这些分支上短路到 `adjudicate_known_coordinates` 之前，即违约——观测层唯一的替换例外被静默丢弃；checked-in 种子 `[Reclaim, Ingest v2@10, Ingest v1@10]` 使 P6 双向性质在该输入上确定性变红。本条把定案 7 ② 从"回收"一类推广到全部零触碰类。
     - **P5 零触碰域随之精确化**：跳过类的零触碰域 = **fold 拥有的投影层 + 永久层**，**明确不含**观测层与冲突证据面（后者由 P6 的全表双向比较兜住）。
     - **`IngestOutcome` 须能区分**「投影跳过但观测已处理」与「完全跳过」——前者可产出证据并可能递增 `data_version`。
     - **`data_version`** 按 [ADR-0019](0019-数据新鲜度与变更传播.md) 谓词判：裸观测追加不改变查询可见结果则不递增；产出证据行（冲突 / divergence / 生命周期码）属 health 域，递增。
   - **FPR 修法的裁决更正（2026-08-05，维护者药方被实测证伪）**：上文「**裁决：修几何而非降指标**——片宽取 2 的幂」经受控实验**证伪**：取 2 的幂后实测率反而劣化到 **1/2,614**——旧的 1480 位宽是被 u64 回绕意外充当混合器救回来的，取 2 的幂恰好移除了这个意外。实验显示 `h1+j·h2` 在所试各宽度下均偏离理想 **19–27×**，本 ADR 曾并列的 `h1+j·h2+j²` 也只到 10–17×。**真实根因是下标推导而非片宽几何**：每个身份的 k 个下标构成等差数列，而等差数列彼此相关。正确修法 = **逐下标独立雪崩**。实测降至 **1/36,364**，落回 2⁻¹⁵ 上界内；存储 3.45 B/身份，ADR-0011 的 11–21 MB/年 对账不变。执行者按「禁止静默取舍」停手上报而未按错误药方施工，**判定正确**——本条同时作为先例：维护者开出的修法同样受实测约束。
   - **未发布迁移的替换必须诚实失败（A1，2026-08-06 跨模型复审）**：定案「迁移仅在未发布期间允许就地改」被实现读作「无条件删旧表建新表」——旧 v5 的水位表若已记录事件，删它等于抹掉唯一的「已计入」记忆，同一事件重读即再次进入永久层（复审实测 `total=2`，应为 1）。**旧结构的内容无法重建为新判别器的输入时，迁移必须拒绝并给出可读诊断**（指示用户重建库或重扫），**禁止静默清空后双计**——v5 从未发布，无用户数据需保全，响亮失败的代价远低于永久错算。
   - **报表的腿必须覆盖每一条永久计入路径（A5，2026-08-06 跨模型复审）**：`store_totals` 的 sessionless 腿只读存活 `usage_events`，而 compact 删除 sessionless 明细后其**唯一真值是永久日聚合**——复审实测 `rollup_events=1` 而 CLI 打印 `no counted events yet`，是**用户可见漏计**，违反 [ADR-0011](0011-存储生命周期.md) 的永久层承诺。此洞由两条既有裁决交叠而生：报表改读 `sessions`（因 rollup 不可判陈旧）× sessionless 事件根本不在 `sessions` 里。**不变量**：报表总账 = 全部永久计入路径之和，任一路径无腿即违约。机制由实现者选定，须**可判陈旧**（这正是当初把 rollup 排除在外的理由）；候选：与 `session_tail_ledger` 同构的 sessionless 永久账（按实例键控）。复审探针须成为永久回归。
   - **定案 5 (b) 的证据面精确化（S-4 重裁，2026-08-05——初裁"证据行集合恒零触碰"过强，执行者以实测证伪）**：(b) 类到达是**观测集合的新成员**，它可能真实构成跨流冲突对；按本定案 ② 条「冲突是观测集合的历史性质，与投影是否接纳无关」，压制该冲突反而会让证据依赖于投影是否被改写。故精确化为两面分治：**生命周期证据面**（`pruned-key-reobserved` / `frozen-session-reactivated` / `reclaimed-key-reobserved` 等描述投影生命周期的码）在 (b) 下**恒零触碰，含时间字段**——判定序保证这些码在 (b) 路径上根本不触发；**冲突证据面**为**单调只增**——(b) 可合法新增冲突行，既有行的集合派生时间字段按置值条款移动，但**永不删除行**。
   - **迁移就地编辑规则（第 4 项上报追认）**：迁移版本**仅在未发布期间**（未合入 main、未进任何已分发构建）允许就地修改；v5 在本 PR 内被替换是正确的——为修正未发布的 v5 而追加 v6 只会留下死 schema。一旦合入 main 即冻结，此后只许追加。
