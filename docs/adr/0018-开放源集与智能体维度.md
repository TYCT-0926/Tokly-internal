# ADR-0018: 开放源集与智能体维度

- 状态：accepted
- 日期：2026-08-03

## 背景

维护者澄清了两条产品事实，均与现有设计冲突：

1. **源集合是开放的**：当前覆盖的 AI 工具只是首发集合（六个），未来会持续扩增（更多 CLI、IDE 集成、自研或第三方智能体）。而现有设计把"六"硬编码进了三处——DDL 的 `CHECK (source IN (六个字面量))`、Rust 侧的封闭 `Source` 枚举、全部文档的"六源"措辞。每加一个源都要 schema 迁移 + 核心枚举改动，且封闭枚举出现在 core 里本身就违反既有架构约束「**core 不识任何源格式**」——core 连源的完整清单都不应该知道。
2. **统计要能按"智能体 × 模型"细分**：既要总量一套数据，也要按智能体（agent——工具内的子代理/模式，如 claude subagent、opencode agent）和模型分别下钻。事件模型已有 `agent` 列，但**永久聚合层没有这个维度**——`daily_usage_rollups` 的键是 (day, tz, instance, model, project)。按 [ADR-0011](0011-存储生命周期.md)，事件明细 180 天后清理，届时智能体维度的历史统计**永久不可得**。这不是缺功能，是数据在被静默丢弃。

## 决策

### 1. 源标识开放化：格式约束替代封闭枚举

- **DDL**：`source_instances.source` 的 CHECK 从封闭枚举改为**格式约束**（非空、仅小写字母/数字/连字符）。新源 = 新 adapter crate + spec 文档，**零 schema 迁移**。
- **Rust**：`Source` 从封闭枚举改为**校验型 newtype**（构造时验证格式）。core 对源标识完全不透明——这使「core 不识源格式」第一次在类型层面成立。
- **注册表 = adapter 能力声明**：哪些源存在、各自能力如何，由每个 adapter 的能力声明承载（既有机制，[ADR-0002](0002-数据架构.md) 能力矩阵）；UI 的源清单从已注册 adapter 枚举，不从 schema 枚举。
- 首发六份 spec（`sources/`）地位不变：它们是**当前已验证集合**，不是上限。文档措辞统一为「多源（首发六源，持续扩增）」。

### 2. 智能体升为一等聚合维度

- `daily_usage_rollups` 增 `agent` 列（`'' = 无智能体`）**并入主键**：(day, tz, source_instance_id, model, **agent**, project_key)。
- `session_model_stats` 同样增 `agent` 入主键——会话内"哪个智能体用哪个模型烧了多少"可查。
- 下钻维度链更新为：**源 → 模型 → 智能体 → 项目 → 会话 → 事件**（[组件规格](../design/组件规格.md) §6、路线图 M2）。
- `agent` 的取值由各 adapter 按 spec 归一化（无智能体概念的源恒 `''`）；总量视图 = 对该维度求和，两种统计诉求（总账 + 细分）由同一张表同时满足。

## 为什么现在做

阶段二（冻结竖切）即将实现 DDL 与 domain 类型——封闭枚举一旦随冻结门定稿，之后每个新源都是一次迁移；`agent` 不进聚合主键，则每过一个保留窗口就永久丢一段智能体维度的历史。两处都是**入库后不可逆**的形状问题，恰好是冻结门存在的意义。

## 代价与备选

- **备选一：保留封闭枚举，每加源做一次迁移。** 弃选：迁移 churn 随源数线性增长；且枚举在 core 里违反 core 源无关的边界——这不是风格问题，封闭枚举会诱使 core 代码 match 源做特判，正是架构要禁止的。
- **备选二：独立 `agents` 注册表。** 弃选：智能体是事件的**属性**不是可预先枚举的实体（用户自定义 subagent 名不可穷举）；注册表只会制造"未注册即丢弃/报错"的伪问题。属性列 + 聚合键就是全部所需。
- **代价**：聚合主键加一列，永久层行数上升（× 每源智能体数，实际基数很低，个位数常见）；[ADR-0011](0011-存储生命周期.md) 的"永久层年增 < 50 MB"预算经此仍成立（agent 基数远小于 project 基数）。
- **代价**：失去 CHECK 枚举的拼写保护。由 Rust 侧 newtype 校验 + adapter 声明补偿——拼错的源标识根本进不了摄取管线。
- **说明**：若"Hermes"指某个具体工具/自研智能体框架，它在本设计下就是未来的一个 adapter（自带 source id 与 spec），或某源下的一个 `agent` 取值——两种形态都零 schema 改动。

## 后果

- [数据库-schema](../数据库-schema.md)：source CHECK 改格式约束；两张聚合表增 agent 入键（2026-08-03 已改）。
- [ADR-0002](0002-数据架构.md)：UsageEvent.source 类型改开放标识；agent 语义指向本 ADR。
- 全仓"六源"措辞改「多源（首发六源）」；[执行计划](../执行计划.md)阶段二 Prompt 的 domain 任务同步（Source newtype 而非枚举）。
- 能力矩阵新增一项声明：该源的 `agent` 归一化规则（或声明"无智能体概念"）。
