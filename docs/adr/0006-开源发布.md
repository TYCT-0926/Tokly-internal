# ADR-0006: 开源策略与发布分发

- 状态：accepted
- 日期：2026-08-02

## 背景

Tokly 是开源项目，托管 GitHub。需要确定许可证、发布渠道、版本管理。

## 决策

### 许可证

**MIT**。理由：同类工具的事实标准（ccusage/tokscale 均为 MIT）；本项目目标是最大化采用，无商业保护诉求；依赖侧（LiteLLM 定价 JSON、culori 等）全部 MIT 兼容。

### 发布渠道（双轨）

1. **npm**：`@tokly/cli` 为主包，`npx tokly` 是开发者用户的主流通路（ccusage 已验证）。core/pricing/adapter 作为 workspace 依赖一并发布。
2. **GitHub Releases**：桌面安装包（Tauri，三平台）+ 可选单文件 CLI（`bun build --compile`，约 100MB，给无 Node/Bun 环境的用户）。

### 版本管理

- 语义化版本；0.x 阶段 minor 允许破坏性变更，1.0 在 M3 Dashboard 稳定后发布
- **changesets** 管理版本号与 CHANGELOG：每个 PR 带 changeset 文件声明影响面，release PR 由 CI 自动聚合
- 发布流水线：tag → CI 构建三平台产物 → npm publish + GitHub Release 草稿

### 社区文件

`LICENSE`（MIT）、`SECURITY.md`（含隐私立场）、`.github/`（issue 模板、PR 模板、CI）、`CONTRIBUTING.md`。

## 后果

- monorepo 的 private 包（apps/web、tui、desktop 壳）不发布 npm，仅 `@tokly/*` 库与 CLI 发布。
- CI 需要 npm token 与 GitHub Release 权限（仓库 secrets 配置）。
