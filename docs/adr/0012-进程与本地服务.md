# ADR-0012: 进程所有权、并发模型与本地服务安全

- 状态：accepted
- 日期：2026-08-03

## 背景

[架构总览](../架构总览.md)定了"写入单 owner + 端口文件发现 + 随机 token 鉴权"，但落到实现有五处未定义，每一处都能直接变成故障或漏洞：

1. `daemon.json` 里的 pid 在进程崩溃后陈旧，无接管协议；
2. 两个端同时启动都发现无 daemon，双 daemon 竞态——而写入单 owner 是收敛契约的前提；
3. 「文件权限仅用户可读」是 POSIX 语义，Windows 上不成立，而 Windows 是一等平台；
4. 浏览器如何拿到 token 从未定义（放 URL query 会进浏览器历史与服务端访问日志）；
5. TUI 降级为只读直连 SQLite 时绕过了版本协商——恰恰在版本不匹配时直接读库。

另有一处结构性决策从未做：Axum（async）与 rusqlite（阻塞）如何共存。

## 决策

### daemon 所有权：OS 咨询文件锁

`<data_dir>/tokly/daemon.lock` 上的**独占咨询锁**（POSIX `flock` / Windows `LockFileEx`）是所有权的唯一真相：

- 拿到锁 → 你是 daemon：绑定端口 → 生成 token → 原子写 `daemon.json`（临时文件 + rename）→ 开始服务；
- 拿不到锁 → 已有 daemon：读 `daemon.json` 连接之；若 `daemon.json` 缺失或端口不响应，退回重试抢锁；
- **进程崩溃时内核自动释放锁**——没有陈旧状态要清理，没有心跳，没有超时判据。

`daemon.json` 因此降级为纯发现缓存（`{port, pid, token, schema_version}`），不承担所有权语义。

### 本地服务鉴权

- token 长度 ≥ 256 bit，随 daemon 启动生成，只写入 `daemon.json`。
- 文件权限由跨平台 `secure_file` 抽象保证：POSIX `0600`；**Windows 用 DACL 仅授予当前用户 SID**，不依赖目录继承权限。
- **HTTP 层强制 `Origin` / `Host` 校验**，只接受 `127.0.0.1` / `localhost` 与预期端口——这才是对恶意网页（DNS rebinding）的实际防线，token 是第二道。
- **token 经 URL fragment 传递**：`tokly serve` 打开 `http://127.0.0.1:PORT/#t=<token>`。fragment 不发送到服务端、不进访问日志、不随 `Referer` 外泄；SPA 读取后存 `sessionStorage`，随即 `history.replaceState` 清出地址栏。

### schema 版本协商（含降级路径）

握手比对 `schema_migrations` 最新 version，不匹配拒开并提示迁移或升级。**只读直连降级路径走同一判据**：先读 `schema_migrations` 再决定是否读数据；库版本高于本体支持则拒绝并提示升级，不做"尽力解析"。

### 并发模型

- **写连接唯一且串行**：摄取、compact、dirty 队列重算共用同一个写连接，天然满足写入单 owner 与事务边界。
- **读走连接池**；所有 rusqlite 调用经 `spawn_blocking`，**Axum handler 不直接持有连接**。
- WAL 下读写不互斥，查询不被摄取阻塞。

（写连接是独立线程加 channel 还是互斥量守护，属实现选择，不在本决策范围。）

### 摄取节奏

文件源用 `notify` crate——架构总览原文写的 `fsnotify` 是 Go 生态的库名，属换栈残留。写爆发期 debounce 2s；不支持 watch 的走轮询兜底，节奏见各源 spec。

## 为什么现在做

写入单 owner 是[ADR-0002](0002-数据架构.md)收敛契约的**前提**：双 daemon 并发摄取会同时推进水位线并交叉写事件，收敛性 property test 在单进程下全绿也证明不了任何东西。所有权协议属于契约的一部分，不是运维细节。

并发模型同理：async handler 里直接调 rusqlite 会阻塞 executor，症状是"查询一多整个服务卡住"，而这类问题一旦在 M2 的 handler 里长满，改动面是全部端点。

## 代价与备选

- **备选一：数据库内的租约表 + 心跳 + CAS 抢占。** 弃选理由：需要自己定义超时判据、处理时钟漂移、写心跳，且崩溃后仍要等一个超时窗口。文件锁把这些全部交给内核，正确性更高、代码更少。
- **备选二：pid 文件 + 存活探测。** 弃选理由：pid 会被复用，探测本身就是竞态；这正是当前设计的问题所在。
- **备选三：token 走一次性交换码 + `/auth/exchange` 端点。** 弃选理由：在"本机同用户进程 + 恶意网页"这个威胁模型下，交换码防不住任何 fragment 防不住的东西（能读地址栏的浏览器扩展同样能读 sessionStorage），代价却是一个新端点、一份服务端状态与过期逻辑。**去掉它是必要性检验的结果。**
- **代价**：咨询锁在网络文件系统上不可靠。数据目录是本地用户目录，接受该限制；若检测到数据目录位于网络挂载点，启动时警告。
- **代价**：`Origin` 校验会让第三方本地工具接入本地 API 变麻烦。这是有意的——本地 API 不是公开集成面，需要时另开显式决策。

## 后果

- 架构总览「进程模型」节改为引用本 ADR，不再复述细节。
- `daemon.lock` 与 `secure_file` 抽象进 M1；`Origin` 校验与 fragment 传递进 M2 本地 HTTP 服务条目。
- 双 daemon 的排除进收敛性测试的前置条件说明：property test 的有效性依赖单 owner 成立。
